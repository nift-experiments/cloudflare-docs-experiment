

**Set up the monitor**


For a full list of monitor properties, refer to [Create Monitor](/api/resources/load_balancers/subresources/monitors/methods/create/). If you need help with API authentication, refer to [Cloudflare API documentation](/fundamentals/api/).



<pre class="nb-api-request"><code class="language-bash">curl --request POST \
--url https://api.cloudflare.com/client/v4/accounts/{account_id}/load_balancers/monitors \
--header &quot;Authorization: Bearer $CLOUDFLARE_API_TOKEN&quot; \
--data &#x27;{
&quot;type&quot;: &quot;https&quot;,
&quot;description&quot;: &quot;Login page monitor&quot;,
&quot;method&quot;: &quot;GET&quot;,
&quot;path&quot;: &quot;/health&quot;,

  &quot;Host&quot;: [
    &quot;example.com&quot;

  ]

&quot;timeout&quot;: 3,
&quot;retries&quot;: 0,
&quot;interval&quot;: 90,
&quot;expected_body&quot;: &quot;alive&quot;,
&quot;expected_codes&quot;: &quot;2xx&quot;,

**Prepare your servers**


Make sure that your firewall or web server does not block or rate limit your configured health monitors or requests associated with [Cloudflare IP addresses](https://www.cloudflare.com/ips).

Each health monitor has the HTTP user-agent of `"Mozilla/5.0 (compatible; Cloudflare-Traffic-Manager/1.0; +https://www.cloudflare.com/traffic-manager/; pool-id: $poolid)"`, where the `$poolid` is the first 16 characters of the [associated pool](/load-balancing/pools/).

<aside class="nb-aside caution">


<p>If you know that your endpoint is healthy but Load Balancing is reporting it as unhealthy, refer to our <a href="/load-balancing/troubleshooting/load-balancing-faq/#why-is-my-endpoint-or-pool-considered-unhealthy">Monitor troubleshooting guide</a>.</p>


</aside>


**Attach the monitor to a pool**

Once your monitor is created, save its `id` property. Include this value in the `monitor` parameter when [creating your pool](/load-balancing/pools/create-pool/#create-a-pool).
