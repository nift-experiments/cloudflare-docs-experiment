

1. Go to **Connectors** page.

<div class="nb-dash-button"></div>

2. From the **IPsec/GRE tunnels** tab, select **Create a tunnel**.
3. On the **Add tunnels** page, choose either a **GRE tunnel** or **IPsec tunnel**.
4. In **Name**, give your tunnel a descriptive name. This name must be unique, cannot contain spaces or special characters, and cannot be shared with other tunnels.
5. _(Optional)_ Give your tunnel a description in **Description**.
6. In **IPv4 Interface address**, enter the internal IP address for your tunnel along with the interface's prefix length (`/31` or `/30`). This is used to route traffic through the tunnel on the Cloudflare side. We recommend using a `/31` subnet, as it provides the most efficient use of IP address space.

Expand the section below for your tunnel type to complete the configuration:

<span id="add-gre-tunnel"></span>
<details class="nb-details"><summary>GRE tunnel</summary><div class="nb-details-body">

<ol start="7">
<li>In <strong>Customer GRE endpoint</strong>, enter your router's public IP address. You do not need this value if you use a physical or virtual connection like Cloudflare Network Interconnect because Cloudflare provides it.</li>
<li>In <strong>Cloudflare GRE endpoint</strong>, enter one of the anycast addresses assigned to your account. You can find them in <a href="https://dash.cloudflare.com/?to=/:account/ip-addresses/address-space">Leased IPs</a>.</li>
<li><em>(Optional)</em> Leave the default values for <strong>TTL</strong> and <strong>MTU</strong>, or customize them for your network.</li>
<li><em>(Optional)</em> Configure health check settings. Expand the following to learn more about each option:</li>
</ol>
<details class="nb-details"><summary>Health check options</summary><div class="nb-details-body">
<ul>
<li><strong>Tunnel health checks</strong>: Enabled by default. If you disable tunnel health checks, your tunnels appear 100% down in your <a href="/magic-transit/network-health/check-tunnel-health-dashboard/">tunnel health dashboard</a> even when working. Cloudflare keeps sending traffic through the tunnel without the means to detect if the tunnel goes down. You must set up your own system to detect down tunnels, as Cloudflare cannot warn you about down tunnels. Refer to <a href="/magic-transit/reference/tunnel-health-checks/">Tunnel health checks</a> for more information.</li>
<li><strong>Health check rate</strong>: If you keep tunnel health checks enabled, choose a <a href="/magic-transit/network-health/update-tunnel-health-checks-frequency/">health check rate</a> for your tunnel. Available options are <em>Low</em>, <em>Medium</em>, and <em>High</em>.</li>
<li><strong>Health check type</strong>: Defaults to <em>Reply</em> and to creating an ICMP (Internet Control Message Protocol) reply. If your firewall drops this type of packet because it assumes the packet is an attack, change this option to <em>Request</em> which creates an ICMP request. Refer to <a href="/magic-transit/reference/tunnel-health-checks/">Tunnel health checks</a> for more information.</li>
<li><strong>Health check direction</strong>: Defaults to <strong>unidirectional</strong> for Magic Transit. Refer to <a href="#bidirectional-vs-unidirectional-health-checks">Bidirectional vs unidirectional health checks</a> for more details.</li>
<li><strong>Health check target</strong>: The customer end of the tunnel. This field is only visible when <strong>Health check direction</strong> is set to <em>Unidirectional</em>.</li>
</ul>
</div></details>
<ol start="11">
<li><em>(Optional)</em> We recommend you test your tunnel before officially adding it. To test the tunnel, select <strong>Test tunnels</strong>.</li>
<li>To add multiple tunnels, select <strong>Add GRE tunnel</strong> for each new tunnel.</li>
<li>After adding your tunnel information, select <strong>Add tunnels</strong>.</li>
<li>(<em>Optional</em>) Select <strong>Allow BGP (Border Gateway Protocol) peering</strong> (beta) if you want to dynamically exchange routes between your network and Cloudflare. This feature requires <a href="/magic-transit/reference/traffic-steering/#unified-routing-mode-beta">Unified Routing (beta)</a>. <br /> BGP is recommended for environments with frequently changing routes or when you need automatic failover. Refer to <a href="/magic-transit/how-to/configure-routes/#configure-bgp-routes">Configure BGP routes</a> for more information.</li>
</ol>

</div></details>

</li>
