

1. Test your Worker locally:

<pre><code class="language-sh">npx wrangler dev
</code></pre>


<aside class="nb-aside note">
<h3 class="nb-aside-title" id="body-11419-local-development">Local development</h3>


<p>By default, <code>wrangler dev</code> uses a local R2 simulation. Objects you store during development exist only on your machine in the <code>.wrangler/state</code> folder and do not affect your production bucket.</p>
<p>To connect to your real R2 bucket during development, add <code>&quot;remote&quot;: true</code> to your R2 binding in your Wrangler configuration file. Refer to <a href="/workers/local-development/#remote-bindings">remote bindings</a> for more information.</p>


</aside>

2. Once the dev server is running, test storing and retrieving objects:

<pre><code class="language-sh">&#35; Store an object
curl -X PUT http://localhost:8787/my-file.txt -d &#x27;Hello, R2!&#x27;

&#35; Retrieve the object
curl http://localhost:8787/my-file.txt
</code></pre>


3. Deploy to production:

<pre><code class="language-sh">npx wrangler deploy
</code></pre>


4. After deploying, Wrangler outputs your Worker's URL (for example, `https://r2-worker.<YOUR_SUBDOMAIN>.workers.dev`). Test storing and retrieving objects:

<pre><code class="language-sh">&#35; Store an object
curl -X PUT https://r2-worker.&lt;YOUR_SUBDOMAIN&gt;.workers.dev/my-file.txt -d &#x27;Hello, R2!&#x27;

&#35; Retrieve the object
curl https://r2-worker.&lt;YOUR_SUBDOMAIN&gt;.workers.dev/my-file.txt
</code></pre>
