

Your backend generates an auth token by adding the user as a participant to a meeting with the [Add Participant](/api/resources/realtime_kit/subresources/meetings/methods/add_participant/) API endpoint. The API response includes a `token` field for that participant.

You can send this token to your frontend for the intended participant. The token is tied to that participant and meeting. It does not grant access to other meetings.

If you need a new token after the previous token expires, use the [Refresh Participant Token](/api/resources/realtime_kit/subresources/meetings/methods/refresh_participant_token/) endpoint. For more information, refer to [Participant tokens](/realtime/realtimekit/concepts/participant/#participant-tokens).
