<p>The following instructions are for release builds. Debug builds should work without additional steps.</p>
<p>Edit your <code>android/gradle.properties</code> and add the following lines:</p>
<pre><code class="language-txt">android.useFullClasspathForDexingTransform=true
</code></pre>
<p>Add a required <code>blob_provider_authority</code> string resource in the <code>strings.xml</code> file:</p>
<pre><code class="language-xml">&lt;resources&gt;
  ...
  &lt;string name=&quot;blob_provider_authority&quot;&gt;YOUR_APP_RESOURCE_NAME&lt;/string&gt;
  ...
&lt;/resources&gt;
</code></pre>
<p>Create or append to the file <code>android/app/proguard-rules.pro</code>:</p>
<pre><code class="language-txt">-keep class realtimekit.org.webrtc.** { *; }
-dontwarn org.chromium.build.BuildHooksAndroid
</code></pre>
<p>In your <code>android/app/build.gradle</code>, edit the release configuration and add the following line importing the ProGuard configuration:</p>
<pre><code class="language-java">buildTypes {
  release {
    ...
    proguardFiles getDefaultProguardFile('proguard-android.txt'), 'proguard-rules.pro'
  }
}
</code></pre>
<h4 id="body-11721-background-audio-and-video-android">Background audio and video (Android)</h4>
<p>The SDK includes an Android foreground service that keeps audio and video running when the app moves to the background. The service starts automatically when a participant joins a meeting and stops when they leave.</p>
<p>By default the service is enabled with generic notification text. To customize the notification or disable the service, pass <code>keepAliveService</code> to the <code>useRealtimeKitClient</code> hook before calling <code>initMeeting</code>:</p>
<pre><code class="language-tsx">const [meeting, initMeeting] = useRealtimeKitClient({
  keepAliveService: {
    enabled: true,                        // set to false to disable entirely
    title: &quot;Team call&quot;,                   // notification title
    text: &quot;Tap to return to your meeting&quot;, // notification body
  },
});
</code></pre>
<p>On Android 13 and above, the SDK automatically requests the <code>POST_NOTIFICATIONS</code> permission so the notification appears in the shade. No additional setup is required.</p>

<section class="nb-tab-panel" role="tabpanel" data-nb-tabs-content data-nb-tab-label="iOS">

<p><strong>Minimum supported iOS version: 15.1.</strong></p>
<p>Open your <code>Podfile</code> and set the platform to iOS 15.1:</p>
<pre><code class="language-txt">platform :ios, '15.1'
</code></pre>
<p>Add the following permission entries to your <code>Info.plist</code> file:</p>
<pre><code class="language-xml">&lt;key&gt;NSCameraUsageDescription&lt;/key&gt;
&lt;string&gt;Access camera to enable video during meetings.&lt;/string&gt;
&lt;key&gt;NSMicrophoneUsageDescription&lt;/key&gt;
&lt;string&gt;Access microphone to enable audio during meetings.&lt;/string&gt;
&lt;key&gt;NSPhotoLibraryUsageDescription&lt;/key&gt;
&lt;string&gt;Access photos to share images during meetings.&lt;/string&gt;
&lt;key&gt;UIViewControllerBasedStatusBarAppearance&lt;/key&gt;
&lt;false/&gt;
</code></pre>
<h4 id="body-11721-screen-sharing-ios">Screen sharing (iOS)</h4>
<p>iOS screen sharing requires a Broadcast Upload Extension and additional native setup. Refer to the <a href="/realtime/realtimekit/core/local-participant/#screen-share-setup-ios">Screen Share Setup (iOS)</a> guide for full instructions.</p>
<p>Once native setup is complete, pass <code>iOSScreenshareEnabled={true}</code> to <code>RtkMeeting</code> to enable the screen share button in the UI:</p>
<pre><code class="language-tsx">&lt;RtkMeeting meeting={meeting} iOSScreenshareEnabled={true} /&gt;
</code></pre>
