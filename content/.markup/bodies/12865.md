

**Context:**

You configured a Page Rule with **Disable Security** (deprecated) for all subdomains of `example.com` and the `example.com` domain itself:

- **URL**: `*example.com/*`
- **Setting**: _Disable Security_

This setting turned off a subset of Cloudflare security features: Email Obfuscation, Rate Limiting (previous version), Scrape Shield, URL (Zone) Lockdown, and WAF managed rules (previous version).

**How to replace**:

<div class="nb-steps">

<ol>
<li><a href="/rules/configuration-rules/create-dashboard/">Create a configuration rule</a> to turn off one or more security features:</li>
</ol>
<ul>
<li><a href="/waf/tools/scrape-shield/email-address-obfuscation/">Email Obfuscation</a></li>
<li><a href="/waf/tools/scrape-shield/hotlink-protection/">Hotlink Protection</a></li>
</ul>
<ol start="2">
<li>
<p>If required, <a href="/waf/managed-rules/waf-exceptions/define-dashboard/">create a WAF exception</a> to skip one or more rules of WAF managed rulesets for requests coming from IP addresses in an allowlist.</p>
</li>
<li>
<p>Turn off your existing Page Rule and validate the behavior of the rules you created.</p>
</li>
<li>
<p>If your tests succeed, delete the existing Page Rule.</p>
</li>
</ol>

</div>

<aside class="nb-aside caution">


<p>If you are still using <a href="/waf/reference/legacy/old-waf-managed-rules/">WAF managed rules (previous version)</a> or <a href="/waf/reference/legacy/old-rate-limiting/">Rate Limiting (previous version)</a>, consider upgrading to the new versions of these products. It is not possible to turn off these older products using modern Rules features.</p>


</aside>
