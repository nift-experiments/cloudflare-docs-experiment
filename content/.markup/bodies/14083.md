<section class="nb-tab-panel" role="tabpanel" data-nb-tabs-content data-nb-tab-label="Dashboard">

<p>To upload a custom SSL certificate in the dashboard:</p>
<ol>
<li>In the Cloudflare dashboard, go to the <strong>Edge Certificates</strong> page.</li>
</ol>
<div class="nb-dash-button"></div>
<ol start="2">
<li>
<p>In <strong>Edge Certificates</strong>, select <strong>Upload Custom SSL Certificate</strong>.</p>
</li>
<li>
<p>Copy and paste relevant values into <strong>SSL Certificate</strong> and <strong>Private key</strong> text areas (or select <strong>Paste from file</strong>).</p>
</li>
</ol>
<aside class="nb-aside note">
<p>If doing this manually, include the <code>---BEGIN CERTIFICATE---</code> and <code>---END CERTIFICATE---</code> like the placeholder text.</p>
</aside>
<ol start="4">
<li>
<p>Choose the appropriate <a href="/ssl/edge-certificates/custom-certificates/bundling-methodologies/"><strong>Bundle Method</strong></a>.</p>
</li>
<li>
<p>Select a value for <a href="/ssl/edge-certificates/custom-certificates/#geo-key-manager-private-key-restriction"><strong>Private Key Restriction</strong></a>.</p>
</li>
<li>
<p>Select a value for <strong>Legacy Client Support</strong>, which specifies <span class="nb-glossary-tooltip" title="Server Name Indication (SNI)">Server Name Indication (SNI)</span> support:</p>
</li>
</ol>
<ul>
<li><strong>Modern (recommended)</strong>: SNI only</li>
<li><strong>Legacy</strong>: Supports non-SNI</li>
</ul>
<aside class="nb-aside caution">
<p>Custom certificates of the type <code>legacy_custom</code> are not compatible with <a href="/byoip/">BYOIP</a>.</p>
</aside>
<ol start="7">
<li>
<p>Select <strong>Upload Custom Certificate</strong>. If you see an error for <code>The key you provided does not match the certificate</code>, contact your Certificate Authority to ensure the private key matches the certificate.</p>
</li>
<li>
<p>(optional) <a href="/ssl/edge-certificates/caa-records/">Add a CAA DNS record</a>.</p>
</li>
</ol>

</section>

<section class="nb-tab-panel" role="tabpanel" data-nb-tabs-content data-nb-tab-label="API">

<p>The following call will upload a certificate for use with <code>app.example.com</code>. Cloudflare will automatically bundle the certificate with a certificate chain optimized for maximum compatibility with browsers.</p>
<aside class="nb-aside caution">
<p>Note that if you are using an ECC key generated by OpenSSL, you will need to first remove the <code>-----BEGIN EC PARAMETERS-----...-----END EC PARAMETERS-----</code> section of the file.</p>
</aside>
<ol>
<li>Update the file and build the payload</li>
</ol>
<pre><code class="language-sh">cat app_example_com.pem
</code></pre>
<pre><code class="language-sh">-----BEGIN CERTIFICATE-----
MIIFJDCCBAygAwIBAgIQD0ifmj/Yi5NP/2gdUySbfzANBgkqhkiG9w0BAQsFADBN
MQswCQYDVQQGEwJVUzEVMBMGA1UEChMMRGlnaUNlcnQgSW5jMScwJQYDVQQDEx5E
...
SzSHfXp5lnu/3V08I72q1QNzOCgY1XeL4GKVcj4or6cT6tX6oJH7ePPmfrBfqI/O
OeH8gMJ+FuwtXYEPa4hBf38M5eU5xWG7
-----END CERTIFICATE-----
</code></pre>
<pre><code class="language-sh">MYCERT=&quot;$(cat app_example_com.pem|perl -pe 's/\r?\n/\\n/'|sed -e 's/..$//')&quot;
MYKEY=&quot;$(cat app_example_com.key|perl -pe 's/\r?\n/\\n/'|sed -e's/..$//')&quot;
</code></pre>
<p>With the certificate and key saved to environment variables (using escaped newlines), build the payload:</p>
<pre><code class="language-bash">request_body=$(&lt; &lt;(cat &lt;&lt;EOF
{
  &quot;certificate&quot;: &quot;$MYCERT&quot;,
  &quot;private_key&quot;: &quot;$MYKEY&quot;,
  &quot;bundle_method&quot;: &quot;ubiquitous&quot;
}
EOF
))
</code></pre>
<p>You can optionally add <a href="https://blog.cloudflare.com/introducing-cloudflare-geo-key-manager/">geographic restrictions</a> that specify where your private key can physically be decrypted:</p>
<pre><code class="language-bash">request_body=$(&lt; &lt;(cat &lt;&lt;EOF
{
  &quot;certificate&quot;: &quot;$MYCERT&quot;,
  &quot;private_key&quot;: &quot;$MYKEY&quot;,
  &quot;bundle_method&quot;: &quot;ubiquitous&quot;,
  &quot;geo_restrictions&quot;: {&quot;label&quot;: &quot;us&quot;}'
}
EOF
))
</code></pre>
<p>You can also enable support for legacy clients which do not include SNI in the TLS handshake.</p>
<pre><code class="language-bash">request_body=$(&lt; &lt;(cat &lt;&lt;EOF
{
  &quot;certificate&quot;: &quot;$MYCERT&quot;,
  &quot;private_key&quot;: &quot;$MYKEY&quot;,
  &quot;bundle_method&quot;: &quot;ubiquitous&quot;,
  &quot;geo_restrictions&quot;: {&quot;label&quot;: &quot;us&quot;}',
  &quot;type&quot;:&quot;sni_custom&quot;
}
EOF
))
</code></pre>
<p><code>sni_custom</code> is recommended by Cloudflare. Use <code>legacy_custom</code> when a specific client requires non-SNI support. The Cloudflare API treats all Custom SSL certificates as Legacy by default.</p>
<aside class="nb-aside caution">
<p>Custom certificates of the type <code>legacy_custom</code> are not compatible with <a href="/byoip/">BYOIP</a>.</p>
</aside>
<ol start="2">
<li>Upload your certificate and key</li>
</ol>
<p>Use the <a href="/api/resources/custom_certificates/methods/create/">POST</a> endpoint to upload your certificate and key.</p>
<pre><code class="language-bash">curl https://api.cloudflare.com/client/v4/zones/{zone_id}/custom_certificates \
--header &quot;X-Auth-Email: &lt;EMAIL&gt;&quot; \
--header &quot;X-Auth-Key: &lt;API_KEY&gt;&quot; \
--header &quot;Content-Type: application/json&quot; \
--data &quot;$request_body&quot;
</code></pre>
<ol start="3">
<li>(Optional) Add a CAA record.</li>
</ol>
<p>A Certificate Authority Authorization (CAA) DNS record specifies which certificate authorities (CAs) are allowed to issue certificates for a domain. This record reduces the chance of unauthorized certificate issuance and promotes standardization across your organization.</p>
<p>For more guidance, refer to <a href="/ssl/edge-certificates/caa-records/">Create a CAA record</a>.</p>
