Create a `tsconfig.worker.json` that extends your Node TypeScript configuration and adds the Workers types:

```jsonc title="tsconfig.worker.json"
{
	"extends": "./tsconfig.node.json",
	"compilerOptions": {
		"tsBuildInfoFile": "./node_modules/.tmp/tsconfig.worker.tsbuildinfo",
		"types": ["@cloudflare/workers-types/2023-07-01", "vite/client"],
	},
	"include": ["worker"],
}
```

Then add a reference to this new configuration in your root `tsconfig.json`:

```jsonc {6} title="tsconfig.json"
{
	"files": [],
	"references": [
		{ "path": "./tsconfig.app.json" },
		{ "path": "./tsconfig.node.json" },
		{ "path": "./tsconfig.worker.json" },
	],
}
```

3.  **Add your API Worker**


<h3 id="body-16932-add-your-api-worker">Add your API Worker</h3>

Create a `worker/index.ts` file with the following contents:

```ts title="worker/index.ts"
export default {
	fetch(request) {
		const url = new URL(request.url);

		if (url.pathname.startsWith("/api/")) {
			return Response.json({
				name: "Cloudflare",
			});
		}

		return new Response(null, { status: 404 });
	},
} satisfies ExportedHandler;
```

The Worker defined in the preceding code block will be invoked for any non-navigation request that does not match a static asset.
It returns a JSON response if the `pathname` starts with `/api/` and otherwise returns a `404` response.

<aside class="nb-aside note">


<p>For top-level navigation requests, browsers send a <code>Sec-Fetch-Mode: navigate</code> header.
If this is present and the URL does not match a static asset, the <code>not_found_handling</code> behavior will be invoked rather than the Worker.
This implicit routing is the default behavior.</p>
<p>If you would instead like to define the routes that invoke your Worker explicitly, you can provide an array of route patterns to <a href="/workers/static-assets/binding/#run_worker_first"><code>run_worker_first</code></a>.
This opts out of interpreting the <code>Sec-Fetch-Mode</code> header.</p>

<pre><code class="language-toml">name = &quot;cloudflare-vite-tutorial&quot;
compatibility_date = &quot;$today&quot;
main = &quot;./worker/index.ts&quot;

[assets]
not_found_handling = &quot;single-page-application&quot;
run_worker_first = [&quot;/api/*&quot;]
</code></pre>

4.  **Call the API from the client**

You can now call your API from your React components. For example, in `src/App.tsx`:

<pre><code class="language-tsx">import { useState } from &quot;react&quot;;

function App() {
	const [name, setName] = useState(&quot;unknown&quot;);

	return (
		&lt;div className=&quot;card&quot;&gt;
			&lt;button
				onClick={() =&gt; {
					fetch(&quot;/api/&quot;)
						.then((res) =&gt; res.json() as Promise&lt;{ name: string }&gt;)
						.then((data) =&gt; setName(data.name));
				}}
			&gt;
				Name from API is: {name}
			&lt;/button&gt;
		&lt;/div&gt;
	);
}

export default App;
</code></pre>
