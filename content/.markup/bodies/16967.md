<details class="nb-details"><summary>What's happening behind the scenes?</summary><div class="nb-details-body">

<p>This command installs the Cloudflare adapter and makes the appropriate changes to your <code>astro.config.mjs</code> file in one step. By default, this sets the build output configuration to <code>output: 'server'</code>, which server renders all your pages by default. If there are certain pages that <em>don't</em> need on demand rendering/SSR, for example static pages like a privacy policy, you should set <code>export const prerender = true</code> for that page or route to pre-render it. You can read more about the adapter configuration options <a href="https://docs.astro.build/en/guides/integrations-guide/cloudflare/#options">in the Astro docs</a>.</p>

</div></details>

2.  **Add a `.assetsignore` file**
Create a `.assetsignore` file in your `public/` folder, and add the following lines to it:

<pre><code class="language-txt">_worker.js
_routes.json
</code></pre>


3.  **Add a Wrangler configuration file**

    In your project root, create a Wrangler configuration file with the following content:

<div class="nb-wrangler-config">

<pre><code class="language-json">{
	&quot;name&quot;: &quot;my-astro-app&quot;,
	&quot;main&quot;: &quot;./dist/_worker.js/index.js&quot;,
	// Update to today&#x27;s date
	&quot;compatibility_date&quot;: &quot;$today&quot;,
	&quot;compatibility_flags&quot;: [&quot;nodejs_compat&quot;],
	&quot;assets&quot;: {
		&quot;binding&quot;: &quot;ASSETS&quot;,
		&quot;directory&quot;: &quot;./dist&quot;
	},
	&quot;observability&quot;: {
		&quot;enabled&quot;: true
	}
}
</code></pre>

</div>
<details class="nb-details"><summary>What's this configuration doing?</summary><div class="nb-details-body">

<p>The key parts of this config are:</p>
<ul>
<li><code>main</code> points to the entry point of your Worker script. This is generated by the Astro adapter, and is what powers your server-rendered pages.</li>
<li><code>assets.directory</code> tells Wrangler where to find your static assets. In this case, we're telling Wrangler to look in the <code>./dist</code> directory. If your assets are in a different directory, update the <code>directory</code> value accordingly.</li>
</ul>
<p>Read more about <a href="/workers/wrangler/configuration/">Wrangler configuration options</a> and <a href="/workers/wrangler/configuration/#assets">asset configuration options</a>.</p>

</div></details>

Use the following command to build and deploy. If you're using a CI service, be sure to update your "deploy command" accordingly.
