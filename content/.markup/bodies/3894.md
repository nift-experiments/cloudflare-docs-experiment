

API configuration object name: `"origin_range_requests"`.

The `mode` property accepts these values:

<table>
<thead>
<tr>
<th>Value</th>
<th>Behavior</th>
</tr>
</thead>
<tbody>
<tr>
<td><code>on</code></td>
<td>Allows Cloudflare to generate origin range requests for matching, eligible <code>GET</code> requests.</td>
</tr>
<tr>
<td><code>off</code></td>
<td>Does not generate Origin Range Requests. Cloudflare can still serve ranges from a complete cached file.</td>
</tr>
<tr>
<td><code>default</code></td>
<td>Applies no rule override. Cloudflare uses its platform default. No file extensions are currently turned on by default.</td>
</tr>
</tbody>
</table>

The `mode` property is required. The `on` and `off` modes override the default behavior for matching requests.

The `off` mode controls only range requests generated by Origin Range Requests. On a cacheable miss, Cloudflare may remove the client's `Range` header and fetch the complete file. If caching is bypassed or the request is not eligible for caching, Cloudflare may forward the client's original `Range` header.

```json title="API configuration example"
"action_parameters": {
  "cache": true,
  "origin_range_requests": {
    "mode": "on"
  }
}
```

To override Cloudflare's default behavior, use `off` in a rule that matches the affected traffic.

```json title="Turn off default Origin Range Requests"
"action_parameters": {
  "origin_range_requests": {
    "mode": "off"
  }
}
```

Refer to [Create a cache rule via API](/cache/how-to/cache-rules/create-api/#example-turn-off-default-origin-range-requests) for a complete opt-out example.
