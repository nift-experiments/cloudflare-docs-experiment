

1. In the Cloudflare dashboard, go to the **Security rules** page.

<div class="nb-dash-button"></div>

2. Select **Create** > **Content security rules**.

3. <a id="rule-form" />
Enter a descriptive name for the rule in **Description**.

4. Under **If incoming requests match**, define the scope of the content security rule (or policy). You can use the Expression Builder (specifying one or more values for **Field**, **Operator**, and **Value**) or manually enter an expression using the Expression Editor. For more information, refer to [Edit expressions in the dashboard](/ruleset-engine/rules-language/expressions/edit-expressions/).

5. Under **Allow these directives**, select the desired [CSP directives](/client-side-security/rules/csp-directives/) for the content security rule by enabling one or more checkboxes.
- To manually enter an allowed source, select **Add source**.
- To refresh the displayed sources based on detected resources, select **Refresh suggestions**.

<aside class="nb-aside note">


<p>Cloudflare provides suggestions for <strong>Default</strong>, <strong>Scripts</strong>, and <strong>Connections</strong> directives. For the <strong>Default</strong> directive, suggestions are based on monitored scripts and connections resources.</p>


</aside>

6. 
Under **Then take action**, select the desired action:

- _Allow_: Enforces the CSP directives configured in the rule, blocking any other resources from being loaded on your website, and logging any [rule violations](/client-side-security/rules/violations/).
- _Log_: Logs any content security rule violations without blocking any resources not covered by the rule.


7. To save and deploy your rule, select **Deploy**. If you are not ready to deploy your rule, select **Save as Draft**.
