<ol start="2">
<li>Select <strong>Add Custom Hostname</strong>.</li>
<li>Add your customer's hostname <code>app.customer.com</code> and set the relevant options, including:</li>

<ul>
<li>Select the <a href="/ssl/reference/protocols/">minimum TLS version</a>.</li>
<li>Select the <a href="/cloudflare-for-platforms/cloudflare-for-saas/security/certificate-management/issue-and-validate/validate-certificates/">validation method</a>.</li>
<li>Define a <a href="/cloudflare-for-platforms/cloudflare-for-saas/start/advanced-settings/custom-origin/">custom origin server</a>.</li>
<li>Enterprise customers can also select the <a href="/ssl/reference/certificate-authorities/">certificate authority (CA)</a>, <a href="/cloudflare-for-platforms/cloudflare-for-saas/security/certificate-management/custom-certificates/uploading-certificates/">upload a custom certificate</a>, or enable wildcard, which adds a <code>*.&lt;custom-hostname&gt;</code> SAN to the custom hostname certificate. For more details, refer to <a href="/ssl/reference/certificate-and-hostname-priority/#hostname-priority">Hostname priority</a> and <a href="/cloudflare-for-platforms/cloudflare-for-saas/plans/">Plans</a>.</li>
</ul>
<ol start="4">
<li>Select <strong>Add Custom Hostname</strong>.</li>
</ol>
<aside class="nb-aside note">
<h3 class="nb-aside-title" id="body-4110-default-behavior">Default behavior</h3>
<p>When you create a custom hostname:</p>
<ul>
<li>If you issue a custom hostname certificate with wildcards enabled, you cannot customize TLS settings for these wildcard hostnames.</li>
<li>If you do not specify the <strong>Minimum TLS Version</strong>, it defaults to the zone's Minimum TLS Version. You can still <a href="/cloudflare-for-platforms/cloudflare-for-saas/security/certificate-management/enforce-mtls/#minimum-tls-version">edit this setting</a> after creation.</li>
</ul>
</aside>

</section> <section class="nb-tab-panel" role="tabpanel" data-nb-tabs-content data-nb-tab-label="API">

<ol>
<li>To create a custom hostname using the API, use the <a href="/api/resources/custom_hostnames/methods/create/">Create Custom Hostname</a> endpoint.</li>
</ol>
<ul>
<li>Only Enterprise customers can use the <code>certificate_authority</code> parameter to specify a CA, the <code>custom_certificate</code>/<code>custom_cert_bundle</code> to upload a custom certificate, or <code>wildcard</code> to create a wildcard certificate. Refer to <a href="/cloudflare-for-platforms/cloudflare-for-saas/plans/">Plans</a>.</li>
<li>You can leave the <code>certificate_authority</code> parameter empty to set it to &quot;default CA&quot;. With this option, Cloudflare checks the CAA records before requesting the certificates, which helps ensure the certificates can be issued from the CA.</li>
</ul>
<ol start="2">
<li>For the newly created custom hostname, the <code>POST</code> response may not return the DCV validation token <code>validation_records</code>.  It is recommended to make a second <a href="/api/resources/custom_hostnames/methods/list/"><code>GET</code> command</a> (with a delay) to retrieve these details.</li>
</ol>
<p>The response contains the complete definition of the new custom hostname.</p>
<aside class="nb-aside note">
<h3 class="nb-aside-title" id="body-4110-default-behavior-1">Default behavior</h3>
<p>When you create a custom hostname:</p>
<ul>
<li>If you issue a custom hostname certificate with wildcards enabled, you cannot customize TLS settings for these wildcard hostnames.</li>
<li>If you do not specify the <strong>Minimum TLS Version</strong>, it defaults to the zone's Minimum TLS Version. You can still <a href="/cloudflare-for-platforms/cloudflare-for-saas/security/certificate-management/enforce-mtls/#minimum-tls-version">edit this setting</a> after creation.</li>
</ul>
</aside>
