

1.  Ensure that `ping_group_range` includes the Group ID (GID) of the user running `cloudflared`:

a. Find the user that owns the `cloudflared` process:

<pre><code class="language-sh">ps -aux | grep cloudflared
</code></pre>


<pre><code class="language-sh">johndoe         407  0.8  1.7 1259904 35296 ?       Ssl  21:02   0:00 /usr/bin/cloudflared --no-autoupdate tunnel run --token eyJhI...
</code></pre>


b. Get the Group ID of the `cloudflared` user:

<pre><code class="language-sh">id -g johndoe
</code></pre>


<pre><code class="language-sh">10001
</code></pre>


c. Determine the Group IDs that are allowed to use ICMP:

<pre><code class="language-sh">sudo sysctl net.ipv4.ping_group_range
</code></pre>


<pre><code class="language-sh">net.ipv4.ping_group_range= 0 10000
</code></pre>


d. Either add the user to a group within that range, or update the range to encompass a group the user is already in. To update `ping_group_range`:

<pre><code class="language-sh">echo 0 10001 | sudo tee /proc/sys/net/ipv4/ping_group_range
</code></pre>


e. If you need to make the change apply to an already running process, you need to restart `cloudflared`. To make the change persist on reboot, update your `systcl` parameters:

<pre><code class="language-sh">echo &quot;net.ipv4.ping_group_range = 0 10001&quot; | sudo tee -a /etc/sysctl.d/99-cloudflared.conf
</code></pre>


2.  If you are running multiple network interfaces (for example, `eth0` and `eth1`), configure `cloudflared` to use the external Internet-facing interface:

<pre><code class="language-sh">cloudflared tunnel run --icmpv4-src &lt;IP of primary interface&gt;
</code></pre>
