<li>Ensure that <code>ping_group_range</code> includes the Group ID (GID) of the user running <code>cloudflared</code>:</li>

<p>a. Find the user that owns the <code>cloudflared</code> process:</p>
<pre><code class="language-sh">ps -aux | grep cloudflared
</code></pre>
<pre><code class="language-sh">johndoe         407  0.8  1.7 1259904 35296 ?       Ssl  21:02   0:00 /usr/bin/cloudflared --no-autoupdate tunnel run --token eyJhI...
</code></pre>
<p>b. Get the Group ID of the <code>cloudflared</code> user:</p>
<pre><code class="language-sh">id -g johndoe
</code></pre>
<pre><code class="language-sh">10001
</code></pre>
<p>c. Determine the Group IDs that are allowed to use ICMP:</p>
<pre><code class="language-sh">sudo sysctl net.ipv4.ping_group_range
</code></pre>
<pre><code class="language-sh">net.ipv4.ping_group_range= 0 10000
</code></pre>
<p>d. Either add the user to a group within that range, or update the range to encompass a group the user is already in. To update <code>ping_group_range</code>:</p>
<pre><code class="language-sh">echo 0 10001 | sudo tee /proc/sys/net/ipv4/ping_group_range
</code></pre>
<p>e. If you need to make the change apply to an already running process, you need to restart <code>cloudflared</code>. To make the change persist on reboot, update your <code>systcl</code> parameters:</p>
<pre><code class="language-sh">echo &quot;net.ipv4.ping_group_range = 0 10001&quot; | sudo tee -a /etc/sysctl.d/99-cloudflared.conf
</code></pre>

<li>If you are running multiple network interfaces (for example, <code>eth0</code> and <code>eth1</code>), configure <code>cloudflared</code> to use the external Internet-facing interface:</li>
</ol>
<pre><code class="language-sh">cloudflared tunnel run --icmpv4-src &lt;IP of primary interface&gt;
</code></pre>

<p>In your environment, modify the <code>ping_group_range</code> parameter to include the Group ID (GID) of the user running <code>cloudflared</code>.</p>
<p>By default the <a href="https://github.com/cloudflare/cloudflared/blob/master/Dockerfile#L29C6-L29C13"><code>cloudflared</code> Docker container</a> executes as a user called <code>nonroot</code> inside of the container. <code>nonroot</code> is a specific user that exists in the <a href="https://github.com/GoogleContainerTools/distroless/blob/859eeea1f9b3b7d59bdcd7e24a977f721e4a406c/base/base.bzl#L8">base image</a> we use, and its Group ID is hardcoded to 65532.</p>
