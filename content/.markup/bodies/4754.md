<ol>
<li>In the <a href="https://dash.cloudflare.com/">Cloudflare dashboard</a>, go to <strong>Zero Trust</strong> &gt; <strong>Access controls</strong> &gt; <strong>Access settings</strong>.</li>
<li>Under <strong>Allow multi-factor authentication (MFA)</strong>, select the <a href="#supported-mfa-methods">MFA methods</a> you want to allow in your organization.</li>
<li>Set an <strong>Authentication duration</strong>. This determines how long a user can log in to Access without being prompted for MFA again. If the user does not have an active MFA session for the required authenticator method, they must complete MFA in addition to IdP authentication.</li>
<li>(Optional) To avoid double prompting a user for MFA, you can enable <a href="#use-identity-provider-mfa"><strong>Use identity provider MFA</strong></a>. This will check the AMR value passed from the identity provider at the time of authentication, if that AMR value passes an allowed MFA method, the user will not be prompted for MFA for the duration configured.</li>
<li>(Optional) To apply your MFA methods and authentication duration to all Access applications, select <strong>Apply global MFA settings by default</strong>. You can <a href="/cloudflare-one/access-controls/policies/mfa-requirements/#configure-independent-mfa-for-an-application">override the global MFA settings</a> for individual applications and policies.</li>
</ol>
<aside class="nb-aside note">
<p>The <a href="/cloudflare-one/access-controls/access-settings/app-launcher/">App Launcher</a> is exempt from the global MFA requirement. Users must be able to access the App Launcher without MFA to enroll their authenticators.</p>
</aside>

<section class="nb-tab-panel" role="tabpanel" data-nb-tabs-content data-nb-tab-label="API">

<ol>
<li>Get your existing Zero Trust organization configuration:</li>
</ol>
<pre class="nb-api-request"><code class="language-bash">curl --request GET \
--url https://api.cloudflare.com/client/v4/accounts/{account_id}/access/organizations \
--header &quot;Authorization: Bearer $CLOUDFLARE_API_TOKEN&quot;</code></pre>
<ol start="2">
<li>Send a <code>PUT</code> request to update your organization's MFA settings. To avoid overwriting your existing configuration, the <code>PUT</code> request body should contain all fields returned by the previous <code>GET</code> request.</li>
</ol>
<pre class="nb-api-request"><code class="language-bash">curl --request PUT \
--url https://api.cloudflare.com/client/v4/accounts/{account_id}/access/organizations \
--header &quot;Authorization: Bearer $CLOUDFLARE_API_TOKEN&quot; \
--data &#x27;{
&quot;auth_domain&quot;: &quot;your-team-name.cloudflareaccess.com&quot;,
&quot;name&quot;: &quot;Your Team Name&quot;,
&quot;mfa_config&quot;: {
  &quot;allowed_authenticators&quot;: [
    &quot;totp&quot;,
    &quot;biometrics&quot;,
    &quot;security_key&quot;
  ],
  &quot;session_duration&quot;: &quot;24h&quot;
},
&quot;mfa_required_for_all_apps&quot;: false
}&#x27;</code></pre>
<p>Set <code>allowed_authenticators</code> to an array containing one or more of:</p>
<ul>
<li><code>totp</code> — Authenticator application (time-based one-time passwords).</li>
<li><code>biometrics</code> — Biometrics (Touch ID, Face ID, Windows Hello).</li>
<li><code>security_key</code> — Security keys (hardware keys that support WebAuthn).</li>
<li><code>piv_key</code> — PIV keys (YubiKeys).</li>
<li><code>ssh_fido2_key</code> — FIDO2 keys for SSH connections to infrastructure applications.</li>
</ul>
<p><code>piv_key</code> and <code>ssh_fido2_key</code> apply only to SSH connections to infrastructure applications. If allowed at the organization level, these MFA methods will only apply to infrastructure applications. They will not be available for other application types.</p>
<p>Set <code>session_duration</code> to a duration string (for example, <code>30m</code>, <code>1h</code>, <code>24h</code>). To require MFA on every access, use <code>0m</code>.</p>
