<li>In the <a href="https://dash.cloudflare.com/">Cloudflare dashboard</a>, go to <strong>Zero Trust</strong> &gt; <strong>Access controls</strong> &gt; <strong>Targets</strong>.</li>
<li>Select <strong>Add a target</strong>.</li>
<li>In <strong>Target hostname</strong>, enter a user-friendly name for the <div class="nb-interactive-component" data-cf-component="GlossaryTooltip"></li>
</ol>
<p>target</p>
</div>. We recommend using the server hostname, for example `production-server`. The target hostname does not need to be unique and can be reused for multiple targets. Hostnames are used to define the targets secured by an Access application; they are not used for DNS address resolution.
<details class="nb-details"><summary>Hostname format restrictions</summary><div class="nb-details-body">
<ul>
<li>Case insensitive</li>
<li>Contain no more than 253 characters</li>
<li>Contain only alphanumeric characters, <code>-</code>, or <code>.</code> (no spaces allowed)</li>
<li>Start and end with an alphanumeric character</li>
</ul>
</div></details>
4. In **IP addresses**, enter the IPv4 and/or IPv6 address of the target resource. The dropdown menu will not populate until you type in the full IP address.
<aside class="nb-aside note">
<p>If the target IP does not appear in the dropdown, go to <strong>Networking</strong> &gt; <strong>Routes</strong> and confirm that the IP routes through Cloudflare Tunnel.</p>
</aside>
5. In the dropdown menu, select the IP address and [virtual network](/cloudflare-one/networks/connectors/cloudflare-tunnel/private-net/cloudflared/tunnel-virtual-networks/) where the resource is located. This IP address and virtual network pairing is now assigned to this target and cannot be reused in another target by design.
6. (Optional) In **Tags**, add key-value tags to organize your target. For example, use `environment`, `team`, or `region` to group targets and match them later in [target criteria](/cloudflare-one/access-controls/applications/non-http/infrastructure-apps/#target-criteria). Each tag key can only appear once on a target. For example, a single target can have `environment:production` or `environment:staging`, but not both.
7. Select **Add target**.

<p>Make a <code>POST</code> request to the <a href="/api/resources/zero_trust/subresources/access/subresources/infrastructure/subresources/targets/methods/create/">Infrastructure Access Targets</a> endpoint:</p>
<pre class="nb-api-request"><code class="language-bash">curl --request POST \
--url https://api.cloudflare.com/client/v4/accounts/{account_id}/infrastructure/targets \
--header &quot;Authorization: Bearer $CLOUDFLARE_API_TOKEN&quot; \
--data &#x27;{
&quot;hostname&quot;: &quot;infra-access-target&quot;,
&quot;ip&quot;: {
  &quot;ipv4&quot;: {
    &quot;ip_addr&quot;: &quot;187.26.29.249&quot;,
    &quot;virtual_network_id&quot;: &quot;c77b744e-acc8-428f-9257-6878c046ed55&quot;
  },
  &quot;ipv6&quot;: {
    &quot;ip_addr&quot;: &quot;64c0:64e8:f0b4:8dbf:7104:72b0:ec8f:f5e0&quot;,
    &quot;virtual_network_id&quot;: &quot;c77b744e-acc8-428f-9257-6878c046ed55&quot;
  }
},
&quot;tags&quot;: {
  &quot;environment&quot;: &quot;production&quot;,
  &quot;team&quot;: &quot;platform&quot;
}
}&#x27;</code></pre>
<p>The <code>tags</code> field is optional. Use <a href="/resource-tagging/">Resource Tagging</a> to manage tags. Each key can only appear once per target.</p>
