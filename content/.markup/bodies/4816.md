
<section class="nb-tab-panel" role="tabpanel" data-nb-tabs-content data-nb-tab-label="Dashboard">

<ol>
<li>In the <a href="https://dash.cloudflare.com/">Cloudflare dashboard</a>, go to <strong>Zero Trust</strong> &gt; <strong>Access controls</strong> &gt; <strong>Applications</strong>.</li>
<li>Select <strong>Create new application</strong>.</li>
<li>Select <strong>Infrastructure</strong>.</li>
<li>Enter any name for the application.</li>
<li>In <strong>Target criteria</strong>, choose which targets this application covers. Match targets by <span class="nb-glossary-tooltip" title="target hostname">hostname</span>, tag, or both. Use <code>include</code> to match any value. Use <code>require</code> to match all values. Use <code>exclude</code> to reject matching targets.</li>
<li>Enter the <strong>Protocol</strong> and <strong>Port</strong> that will be used to connect to the server.</li>
<li>(Optional) If a protocol runs on more than one port, select <strong>Add new target criteria</strong> and reconfigure the same target criteria and protocol with a different port number.</li>
</ol>
<aside class="nb-aside note">
<p>Access for Infrastructure only supports assigning one protocol per port. You can reuse a port/protocol pairing across infrastructure applications, but the port cannot be reassigned to another protocol.</p>
</aside>
8. Select **Next**.
9. To secure your targets, configure a policy that defines who can connect and how they can connect:
1. Enter any name for your policy.
2. Create a rule that matches the users who are allowed to reach the targets. For more information, refer to [Access policies](/cloudflare-one/access-controls/policies/) and review the list of [infrastructure policy selectors](/cloudflare-one/access-controls/applications/non-http/infrastructure-apps/#infrastructure-policy-selectors).
3. In **Connection context**, configure the following settings:
   - **SSH user**: Enter the UNIX usernames that users can log in as (for example, `root` or `ec2-user`).
   - **Allow users to log in as their email alias**: (Optional) When selected, users who match your policy definition will be able to access the target using their lowercased email address prefix. For example, `Jdoe@company.com` could log in as `jdoe`.
<aside class="nb-aside note">
<p>Cloudflare will not create new users on the target. UNIX users must already be present on the server.</p>
</aside>
<ol start="10">
<li>Select <strong>Add application</strong>.</li>
</ol>

<section class="nb-tab-panel" role="tabpanel" data-nb-tabs-content data-nb-tab-label="API">

<p>Make a <code>POST</code> request to the <a href="/api/resources/zero_trust/subresources/access/subresources/applications/methods/create/">Access applications</a> endpoint:</p>
<p>The following example uses the operator-based target criteria format with <code>include</code>, <code>require</code>, and <code>exclude</code>:</p>
<pre class="nb-api-request"><code class="language-bash">curl --request POST \
--url https://api.cloudflare.com/client/v4/accounts/{account_id}/access/apps \
--header &quot;Authorization: Bearer $CLOUDFLARE_API_TOKEN&quot; \
--data &#x27;{
&quot;name&quot;: &quot;Example infrastructure app&quot;,
&quot;type&quot;: &quot;infrastructure&quot;,
&quot;target_criteria&quot;: [
  {
    &quot;port&quot;: 22,
    &quot;protocol&quot;: &quot;SSH&quot;,
    &quot;include&quot;: {
      &quot;target_attributes&quot;: {
        &quot;hostname&quot;: [
          &quot;infra-access-target&quot;
        ]
      },
      &quot;tags&quot;: {
        &quot;environment&quot;: [
          &quot;production&quot;,
          &quot;staging&quot;
        ]
      }
    },
    &quot;require&quot;: {
      &quot;tags&quot;: {
        &quot;team&quot;: [
          &quot;platform&quot;
        ]
      }
    },
    &quot;exclude&quot;: {
      &quot;tags&quot;: {
        &quot;lifecycle&quot;: [
          &quot;decommissioned&quot;
        ]
      }
    }
  }
],
&quot;policies&quot;: [
  {
    &quot;name&quot;: &quot;Allow a specific email&quot;,
    &quot;decision&quot;: &quot;allow&quot;,
    &quot;include&quot;: [
      {
        &quot;email&quot;: {
          &quot;email&quot;: &quot;jdoe@company.com&quot;
        }
      }
    ],
    &quot;connection_rules&quot;: {
      &quot;ssh&quot;: {
        &quot;usernames&quot;: [
          &quot;root&quot;,
          &quot;ec2-user&quot;
        ]
      }
    }
  }
]
}&#x27;</code></pre>
<p>For more information about target criteria formats, refer to <a href="/cloudflare-one/access-controls/applications/non-http/infrastructure-apps/#target-criteria">Target criteria</a>.</p>

<aside class="nb-aside note">
<h3 class="nb-aside-title" id="body-4816-provider-versions">Provider versions</h3>
<p>The following example requires Cloudflare provider version <code>&gt;=4.45.0</code>.</p>
</aside>
<ol>
<li>Add the following permission to your <a href="https://registry.terraform.io/providers/cloudflare/cloudflare/4.45.0/docs/resources/api_token"><code>cloudflare_api_token</code></a>:</li>
</ol>
<ul>
<li><code>Access: Apps and Policies Write</code></li>
</ul>
<ol start="2">
<li>Use the <a href="https://registry.terraform.io/providers/cloudflare/cloudflare/4.45.0/docs/resources/zero_trust_access_application"><code>cloudflare_zero_trust_access_application</code></a> resource to create an infrastructure application:</li>
</ol>
<pre><code class="language-tf">resource &quot;cloudflare_zero_trust_access_application&quot; &quot;infra-app&quot; {
	account_id = var.cloudflare_account_id
	name       = &quot;Example infrastructure app&quot;
	type       = &quot;infrastructure&quot;

	target_criteria {
		port     = 22
		protocol = &quot;SSH&quot;
		target_attributes {
			name = &quot;hostname&quot;
			values = [&quot;infra-access-target&quot;]
		}
	}
}
</code></pre>
<p>To match targets by tag, define <code>include</code>, <code>require</code>, or <code>exclude</code> blocks with <code>tags</code> selectors.</p>
<ol start="3">
<li>Use the <a href="https://registry.terraform.io/providers/cloudflare/cloudflare/4.45.0/docs/resources/zero_trust_access_policy"><code>cloudflare_zero_trust_access_policy</code></a> resource to add an infrastructure policy to the application:</li>
</ol>
<pre><code class="language-tf">resource &quot;cloudflare_zero_trust_access_policy&quot; &quot;infra-app-policy&quot; {
	application_id = cloudflare_zero_trust_access_application.infra-app.id
	account_id = var.cloudflare_account_id
	name       = &quot;Allow a specific email&quot;
	decision   = &quot;allow&quot;
	precedence = 1

	include {
		email = [&quot;jdoe@company.com&quot;]
	}

	connection_rules {
		ssh {
			usernames = [&quot;root&quot;, &quot;ec2-user&quot;]
		}
	}
}
</code></pre>
