
<section class="nb-tab-panel" role="tabpanel" data-nb-tabs-content data-nb-tab-label="Dashboard">

<p>Configure these settings in the <strong>Advanced settings</strong> tab of your <a href="#enable-managed-oauth-on-a-self-hosted-application">self-hosted app</a>, <a href="#enable-managed-oauth-on-an-mcp-server-application">MCP server application</a>, or <a href="#enable-managed-oauth-on-an-mcp-server-portal">MCP server portal</a>.</p>
<ul>
<li><strong>Allow localhost clients</strong>: Allow any client with redirect URIs on <code>localhost</code>.</li>
<li><strong>Allow loopback clients</strong>: Allow any client with redirect URIs on <code>127.0.0.1</code>.</li>
<li><strong>Allowed redirect URIs</strong>: Redirect URIs allowed for dynamically registered clients (for example, <code>https://playground.ai.cloudflare.com/*</code>). The URL must use <code>https</code>. Paths may end in <code>/*</code> to match all sub-paths.</li>
<li><strong>Grant session duration</strong>: How long the OAuth refresh token remains valid.</li>
<li><strong>Access token lifetime</strong>: How long an OIDC Access token can be used to authenticate with your application. Cloudflare recommends configuring a short <strong>Access token lifetime</strong> (default 15 minutes) in conjunction with a longer <strong>Grant session duration</strong>. When the access token expires, Cloudflare uses the refresh token to issue a new one after re-evaluating the user against your Access policies. When the refresh token expires, the user must re-authenticate with the identity provider.</li>
</ul>
<aside class="nb-aside note">
<h3 class="nb-aside-title" id="body-4837-recommended-configuration-for-cli-and-agent-use-cases">Recommended configuration for CLI and agent use cases</h3>
<p>For CLI tools, AI agents, and other non-browser clients, set a short access token lifetime (5–15 minutes) with a longer grant session duration (1–2 weeks). With this configuration:</p>
<ul>
<li>The client refreshes tokens silently in the background using the refresh token — no user interaction required.</li>
<li>Access policies are re-evaluated on each token refresh, maintaining continuous identity verification.</li>
<li>The user only sees the authorization prompt when the grant session (refresh token) expires.</li>
</ul>
<p>For example, with a 15-minute access token and a 2-week grant session, a user authenticates once via the browser and then works uninterrupted for up to two weeks before needing to re-authenticate.</p>
</aside>
