

The following use cases show how you could configure allow policies for accept sender.

<h3 id="body-4942-use-case-1">Use case 1</h3>

<div class="nb-example"><h3 class="nb-component-title" id="body-4942-company-receives-emails-from-third-party-providers-not-used-internally-these-emails-are-sent-from-the-service-provider-and-email-security-gives-these-emails-an-incorrect-disposition">Company receives emails from third-party providers not used internally. These emails are sent from the service provider, and Email security gives these emails an incorrect disposition.</h3>

<p>This use case can affect companies such as Shopify, PayPal, and Docusign.</p>
<p>To solve this:</p>
<ol>
<li>Create a <a href="/cloudflare-one/email-security/submissions/team-submissions/">team submission</a>.</li>
<li>Inform your Cloudflare contact about the escalation.</li>
<li>Do not set up allow policies or blocked senders. In this use case, configuring allow policies will create a security gap. Setting up blocked senders will block legitimate emails from providers such as Shopify, PayPal, and Docusign.</li>
</ol>

</div>

<h3 id="body-4942-use-case-2">Use case 2</h3>

<div class="nb-example"><h3 class="nb-component-title" id="body-4942-company-receives-emails-via-third-party-providers-that-are-used-internally-these-emails-are-sent-from-the-company-s-custom-domain-but-email-security-marks-these-emails-as-bulk-spam-or-spoof">Company receives emails via third-party providers that are used internally. These emails are sent from the company&#x27;s custom domain, but Email security marks these emails as bulk, spam, or spoof.</h3>

<p>This use case can cause the emails you want to receive to follow the auto-moves rules you set up. This use case affects emails from internal tools (such as Salesforce, Atlassian, and Figma) that are given an incorrect disposition.</p>
<p>To solve this, when you add an allow policy in the Cloudflare One dashboard:</p>
<ol>
<li>Choose <strong>Accept sender</strong>.</li>
<li>Verify that <strong>Sender verification (recommended)</strong> is turned on.</li>
</ol>

</div>

<h3 id="body-4942-use-case-3">Use case 3</h3>

<div class="nb-example"><h3 class="nb-component-title" id="body-4942-company-receives-emails-via-third-party-providers-that-are-used-internally-these-emails-are-sent-from-the-company-s-custom-domain-but-email-security-marks-these-emails-as-bulk-spam-or-spoof-the-custom-email-domain-does-not-support-dmarc-spf-or-dkim-and-would-fail-sender-verification">Company receives emails via third-party providers that are used internally. These emails are sent from the company&#x27;s custom domain, but Email security marks these emails as bulk, spam, or spoof. The custom email domain does not support DMARC, SPF, or DKIM, and would fail Sender Verification.</h3>

<p>This use case impacts the emails from internal tools (such as Salesforce, Atlassian, and Figma) that are given an incorrect disposition.</p>
<p>To solve this, when you add an allow policy in the Cloudflare One dashboard:</p>
<ol>
<li>Choose <strong>Accept sender</strong> based on the static IP you own.</li>
<li>Ensure that <strong>Sender verification (recommended)</strong> is turned off.</li>
</ol>
<aside class="nb-aside caution">
<p>Do not use email addresses or email domains for this policy as they can be easily spoofed without <strong>Sender Verification (Recommended)</strong> enabled.</p>
</aside>

</div>
