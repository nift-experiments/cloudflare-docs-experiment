<section class="nb-tab-panel" role="tabpanel" data-nb-tabs-content data-nb-tab-label="API / Terraform">

<p>The dashboard wizard is not required. After account bootstrap, APIs and Terraform can automate the supported Mesh resources. You will need your <a href="/fundamentals/account/find-account-and-zone-ids/">account ID</a>, Zero Trust team name, <code>jq</code>, and an <a href="/fundamentals/api/get-started/create-token/">API token</a> with permissions for the resources you configure.</p>
<aside class="nb-aside note">
<h3 class="nb-aside-title" id="body-5200-initial-api-token">Initial API token</h3>
<p>You must create the initial API token in the dashboard. An authorized token can <a href="/fundamentals/api/how-to/create-via-api/">create subsequent user-owned or account-owned tokens through the API</a>.</p>
</aside>
<p>Before continuing, configure every item in <a href="#required-account-settings">Required account settings</a>. The examples in this section configure the Mesh node device profile, node, and connector token. You must configure device enrollment and global settings separately. <strong>Allow all Cloudflare One traffic to reach enrolled devices</strong> and the ICMP Gateway proxy require dashboard configuration.</p>
<p>Before connecting a node, create a safe Include-mode profile. This request requires the <code>Zero Trust Write</code> permission. It matches Mesh nodes, uses MASQUE in Traffic and DNS mode, and routes only the Mesh IP range through Cloudflare:</p>
<pre><code class="language-bash">set -euo pipefail

PROFILE_RESPONSE=$(
	curl --fail-with-body --silent --show-error \
		&quot;https://api.cloudflare.com/client/v4/accounts/$ACCOUNT_ID/devices/policy&quot; \
		--request POST \
		--header &quot;Authorization: Bearer $CLOUDFLARE_API_TOKEN&quot; \
		--header &quot;Content-Type: application/json&quot; \
		--data &quot;$(jq -n \
			--arg match &quot;identity.email == \&quot;warp_connector@$TEAM_NAME.cloudflareaccess.com\&quot;&quot; \
			'{
				name: &quot;Cloudflare Mesh nodes&quot;,
				description: &quot;Route Mesh IP traffic through Cloudflare&quot;,
				enabled: true,
				precedence: 100,
				match: $match,
				service_mode_v2: {mode: &quot;warp&quot;},
				tunnel_protocol: &quot;masque&quot;,
				include: [{address: &quot;100.96.0.0/12&quot;, description: &quot;Cloudflare Mesh IPs&quot;}]
			}')&quot;
)

jq -e '.success == true and (.result.id | type == &quot;string&quot;)' \
	&lt;&lt;&lt; &quot;$PROFILE_RESPONSE&quot; &gt; /dev/null
PROFILE_ID=$(jq -r '.result.id' &lt;&lt;&lt; &quot;$PROFILE_RESPONSE&quot;)
</code></pre>
<p>Set <code>ACCOUNT_ID</code>, <code>TEAM_NAME</code>, and <code>CLOUDFLARE_API_TOKEN</code> in the shell before running the command. Use an unused <code>precedence</code> value that places this profile before broader profiles. Do not add an <code>exclude</code> field. A device profile cannot contain both <code>include</code> and <code>exclude</code>.</p>
<p>The API response uses the standard <code>success</code>, <code>errors</code>, <code>messages</code>, and <code>result</code> fields. A non-2xx response causes <code>curl</code> to fail. A response with <code>success: false</code> or without <code>result.id</code> causes <code>jq</code> to fail. Do not continue until the command returns zero and <code>PROFILE_ID</code> is set.</p>
<p>The following requests require an API token with either <code>Cloudflare One Connectors Write</code> or <code>Cloudflare One Connector: WARP Write</code> permission. To create a Mesh node and retrieve its connector token:</p>
<pre><code class="language-bash">set -euo pipefail

NODE_RESPONSE=$(
	curl --fail-with-body --silent --show-error \
		&quot;https://api.cloudflare.com/client/v4/accounts/$ACCOUNT_ID/warp_connector&quot; \
		--request POST \
		--header &quot;Authorization: Bearer $CLOUDFLARE_API_TOKEN&quot; \
		--header &quot;Content-Type: application/json&quot; \
		--data '{&quot;name&quot;:&quot;web-server&quot;}'
)

jq -e '.success == true and (.result.id | type == &quot;string&quot;)' \
	&lt;&lt;&lt; &quot;$NODE_RESPONSE&quot; &gt; /dev/null
NODE_ID=$(jq -r '.result.id' &lt;&lt;&lt; &quot;$NODE_RESPONSE&quot;)

TOKEN_RESPONSE=$(
	curl --fail-with-body --silent --show-error \
		&quot;https://api.cloudflare.com/client/v4/accounts/$ACCOUNT_ID/warp_connector/$NODE_ID/token&quot; \
		--header &quot;Authorization: Bearer $CLOUDFLARE_API_TOKEN&quot;
)

MESH_NODE_TOKEN=$(jq -er \
	'select(.success == true) | .result | select(type == &quot;string&quot; and length &gt; 0)' \
	&lt;&lt;&lt; &quot;$TOKEN_RESPONSE&quot;)
</code></pre>
<p>The commands stop on an HTTP or API error. Do not continue until they return zero and set <code>NODE_ID</code> and <code>MESH_NODE_TOKEN</code>. If token retrieval fails after node creation, retry only the token request with the existing <code>NODE_ID</code>. Do not rerun the node creation request.</p>
<p>Install the node and replace <code>&lt;TOKEN&gt;</code> with the value of <code>MESH_NODE_TOKEN</code>:</p>
<p>IP forwarding is not required to reach the node by its Mesh IP. If the node will advertise <a href="/mesh/features/routes/">CIDR routes</a>, enable persistent forwarding before connecting it:</p>
<pre><code class="language-sh">printf 'net.ipv4.ip_forward = 1\nnet.ipv6.conf.all.forwarding = 1\nnet.ipv6.conf.all.accept_ra = 2\n' | sudo tee /etc/sysctl.d/99-zzz-cloudflare-warp-connector.conf &amp;&amp;
sudo sysctl --system
</code></pre>
