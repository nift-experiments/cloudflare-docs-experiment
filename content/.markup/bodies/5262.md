<p>If you are using <strong>Exclude</strong> mode:</p>
<p>a. <a href="/cloudflare-one/team-and-resources/devices/cloudflare-one-client/configure/route-traffic/split-tunnels/#remove-a-route">Delete the route</a> containing your <p>private network</p>
's IP/CIDR range. For example, if your network uses the default AWS range of <code>172.31.0.0/16</code>, delete <code>172.16.0.0/12</code>.</p>
<p>b. <a href="/cloudflare-one/team-and-resources/devices/cloudflare-one-client/configure/route-traffic/split-tunnels/#add-a-route">Re-add IP/CIDR ranges</a> that are not explicitly used by your <p>private network</p>
. For the AWS example above, you would add new entries for <code>172.16.0.0/13</code>, <code>172.24.0.0/14</code>, <code>172.28.0.0/15</code>, and <code>172.30.0.0/16</code>. This ensures that only traffic to <code>172.31.0.0/16</code> routes through the Cloudflare One Client.</p>
<p>You can use the following calculator to determine which IP addresses to re-add:</p>
<div class="nb-interactive-component" data-cf-component="SubtractIPCalculator"></div>
<details class="nb-details" open><summary>Calculator instructions</summary><div class="nb-details-body">
<ol>
<li>In <strong>Base CIDR</strong>, enter the RFC 1918 range that you deleted from Split Tunnels.</li>
<li>In <strong>Subtracted CIDRs</strong>, enter the IP/CIDR range used by your <p>private network</p>
.</li>
<li>Re-add the calculator results to your Split Tunnel Exclude mode list.</li>
</ol>
</div></details>
<p>By tightening the private IP range included in the Cloudflare One Client, you reduce the risk of breaking a user's <a href="/cloudflare-one/team-and-resources/devices/cloudflare-one-client/configure/settings/#allow-users-to-enable-local-network-exclusion">access to local resources</a>.</p>
