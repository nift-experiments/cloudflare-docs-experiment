
To route overlapping IPs over virtual networks for [locally-managed tunnels](/cloudflare-one/networks/connectors/cloudflare-tunnel/do-more-with-tunnels/local-management/):

1. Create a Cloudflare Tunnel for each private network with overlapping IPs (one tunnel per isolated environment, for example staging and production):

   1. Within your staging environment, authenticate `cloudflared`:

<pre><code class="language-sh">cloudflared login
</code></pre>


   2. Create a tunnel to connect your staging network to Cloudflare.

<pre><code class="language-sh">cloudflared tunnel create staging-tunnel
</code></pre>


   3. Within your production environment, authenticate `cloudflared`:

<pre><code class="language-sh">cloudflared login
</code></pre>


   4. Create a tunnel to connect your production network to Cloudflare.

<pre><code class="language-sh">cloudflared tunnel create production-tunnel
</code></pre>


The following steps may be executed from any `cloudflared` instance.

2. Create two unique virtual networks.

<pre><code class="language-sh">cloudflared tunnel vnet add staging-vnet
cloudflared tunnel vnet add production-vnet
</code></pre>


3. Before moving on, run the following command to verify that your newly created virtual networks are listed correctly:

<pre><code class="language-sh">cloudflared tunnel vnet list
</code></pre>


<aside class="nb-aside note">
<h3 class="nb-aside-title" id="body-5395-default-virtual-network">Default virtual network</h3>


<p>All accounts come pre-configured with a virtual network named <code>default</code>. You can choose a new default by typing <code>cloudflared tunnel vnet update --default &lt;virtual-network-name&gt;</code>.</p>


</aside>

4.  Configure your tunnels with the IP/CIDR range of your private networks, and assign the tunnels to their respective virtual networks.

<pre><code class="language-sh">cloudflared tunnel route ip add --vnet staging-vnet 10.128.0.3/32 staging-tunnel
cloudflared tunnel route ip add --vnet production-vnet 10.128.0.3/32 production-tunnel
</code></pre>




5.  Verify that the IP routes are listed correctly:

<pre><code class="language-sh">cloudflared tunnel route ip list
</code></pre>


    We now have two overlapping IP addresses routed over `staging-vnet` and `production-vnet` respectively.

    6. Within your staging environment, create a [configuration file](/cloudflare-one/networks/connectors/cloudflare-tunnel/do-more-with-tunnels/local-management/configuration-file/) for `staging-tunnel`. The configuration file will be structured as follows:

<pre><code class="language-txt">tunnel: &lt;Tunnel-UUID&gt;
credentials-file: /root/.cloudflared/credentials-file.json
warp-routing:
   enabled: true
</code></pre>


    7. Run your tunnel.

<pre><code class="language-sh">cloudflared tunnel run staging-tunnel
</code></pre>


    8. Within your production environment, repeat Steps 6 and 7 for `production-tunnel`.

    You can use now the Cloudflare One Client to [switch between virtual networks](#connect-to-a-virtual-network).
