
<section class="nb-tab-panel" role="tabpanel" data-nb-tabs-content data-nb-tab-label="Dashboard">

<p>To route overlapping IPs over virtual networks:</p>
<ol>
<li>Create two unique virtual networks:</li>
<li>In the Cloudflare dashboard, go to <strong>Networking</strong> &gt; <strong>Routes</strong> &gt; <strong>Virtual networks</strong>.</li>
</ol>
<div class="nb-dash-button"></div>
<ol start="2">
<li>Select <strong>Create virtual network</strong>.</li>
<li>Name your virtual network <code>staging-vnet</code> and select <strong>Save</strong>.</li>
<li>Repeat Steps 1a-1d to create another virtual network called <code>production-vnet</code>.</li>
<li>Create a Cloudflare Tunnel for each private network with overlapping IPs (one tunnel per isolated environment, for example staging and production):</li>
<li>Go to <strong>Networking</strong> &gt; <strong>Tunnels</strong>.</li>
<li>Select <strong>Create a tunnel</strong>.</li>
<li>Name your tunnel <code>Staging tunnel</code> and select <strong>Create</strong>.</li>
<li>Install the connector within your staging environment.</li>
<li>Go to <strong>Networking</strong> &gt; <strong>Routes</strong>.</li>
</ol>
<div class="nb-dash-button"></div>
<ol start="6">
<li>Select <strong>Create route</strong> &gt; <strong>Tunnel CIDR</strong>.</li>
<li>Select <code>Staging tunnel</code>, enter <code>10.128.0.1/32</code> as the network, and select <em>staging-vnet</em> as the virtual network. Select <strong>Create route</strong>.</li>
<li>Repeat Steps 2a-2d to create another tunnel called <code>Production tunnel</code>. Be sure to install the connector within your production environment.</li>
<li>Repeat Steps 2e-2g to create a route for <code>Production tunnel</code> with <code>10.128.0.1/32</code> assigned to <em>production-vnet</em>.</li>
</ol>
<p>We now have two overlapping IP addresses routed over <code>staging-vnet</code> and <code>production-vnet</code> respectively. You can use the Cloudflare One Client to <a href="#connect-to-a-virtual-network">switch between virtual networks</a>.</p>

<section class="nb-tab-panel" role="tabpanel" data-nb-tabs-content data-nb-tab-label="Terraform (v5)">

<p>To route overlapping IPs over virtual networks:
1. Add the following permission to your <a href="https://registry.terraform.io/providers/cloudflare/cloudflare/latest/docs/resources/api_token"><code>cloudflare_api_token</code></a>:
- <code>Cloudflare Tunnel Write</code></p>
<pre><code>2. Create two unique virtual networks:
</code></pre>
<pre><code class="language-tf">resource &quot;cloudflare_zero_trust_tunnel_cloudflared_virtual_network&quot; &quot;staging_vnet&quot; {
	account_id = var.cloudflare_account_id
	name       = &quot;staging-vnet&quot;
	comment    = &quot;Staging virtual network&quot;
	is_default = false
}

resource &quot;cloudflare_zero_trust_tunnel_cloudflared_virtual_network&quot; &quot;production_vnet&quot; {
	account_id = var.cloudflare_account_id
	name       = &quot;production-vnet&quot;
	comment    = &quot;Production virtual network&quot;
	is_default = false
}
</code></pre>
<pre><code>3. Create a Cloudflare Tunnel for each private network with overlapping IPs (one tunnel per isolated environment, for example staging and production):
</code></pre>
<pre><code class="language-tf">resource &quot;cloudflare_zero_trust_tunnel_cloudflared&quot; &quot;staging_tunnel&quot; {
	account_id = var.cloudflare_account_id
	name       = &quot;Staging tunnel&quot;
	config_src = &quot;cloudflare&quot;
}

resource &quot;cloudflare_zero_trust_tunnel_cloudflared&quot; &quot;production_tunnel&quot; {
	account_id = var.cloudflare_account_id
	name       = &quot;Production tunnel&quot;
	config_src = &quot;cloudflare&quot;
}
</code></pre>
<pre><code>4. Route `10.128.0.1/32` through `Staging tunnel` and assign it to `staging-vnet`. Route `10.128.0.1/32` through `Production tunnel` and assign it to `production-vnet`.
</code></pre>
<pre><code class="language-tf">resource &quot;cloudflare_zero_trust_tunnel_cloudflared_route&quot; &quot;staging_tunnel_route&quot; {
	account_id         = var.cloudflare_account_id
	tunnel_id          = cloudflare_zero_trust_tunnel_cloudflared.staging_tunnel.id
	network            = &quot;10.128.0.1/32&quot;
	comment            = &quot;Staging tunnel route&quot;
	virtual_network_id = cloudflare_zero_trust_tunnel_cloudflared_virtual_network.staging_vnet.id
}

resource &quot;cloudflare_zero_trust_tunnel_cloudflared_route&quot; &quot;production_tunnel_route&quot; {
	account_id         = var.cloudflare_account_id
	tunnel_id          = cloudflare_zero_trust_tunnel_cloudflared.production_tunnel.id
	network            = &quot;10.128.0.1/32&quot;
	comment            = &quot;Production tunnel route&quot;
	virtual_network_id = cloudflare_zero_trust_tunnel_cloudflared_virtual_network.production_vnet.id
}
</code></pre>
<pre><code>5. [Get the token](/cloudflare-one/networks/connectors/cloudflare-tunnel/configure-tunnels/remote-tunnel-permissions/#get-the-tunnel-token) for each tunnel.

6. Using the tunnel tokens, run `Staging tunnel` in your staging environment and run `Production tunnel` in your production environment. Refer to [Install and run the tunnel](/cloudflare-one/networks/connectors/cloudflare-tunnel/get-started/create-remote-tunnel-api/#4-install-and-run-the-tunnel).
</code></pre>

</section>

<section class="nb-tab-panel" role="tabpanel" data-nb-tabs-content data-nb-tab-label="Locally-managed tunnels">

<p>To route overlapping IPs over virtual networks for <a href="/cloudflare-one/networks/connectors/cloudflare-tunnel/do-more-with-tunnels/local-management/">locally-managed tunnels</a>:</p>
<ol>
<li>
<p>Create a Cloudflare Tunnel for each private network with overlapping IPs (one tunnel per isolated environment, for example staging and production):</p>
<ol>
<li>Within your staging environment, authenticate <code>cloudflared</code>:</li>
</ol>
</li>
</ol>
<pre><code class="language-sh">cloudflared login
</code></pre>
<ol start="2">
<li>Create a tunnel to connect your staging network to Cloudflare.</li>
</ol>
<pre><code class="language-sh">cloudflared tunnel create staging-tunnel
</code></pre>
<ol start="3">
<li>Within your production environment, authenticate <code>cloudflared</code>:</li>
</ol>
<pre><code class="language-sh">cloudflared login
</code></pre>
<ol start="4">
<li>Create a tunnel to connect your production network to Cloudflare.</li>
</ol>
<pre><code class="language-sh">cloudflared tunnel create production-tunnel
</code></pre>
<p>The following steps may be executed from any <code>cloudflared</code> instance.</p>
<ol start="2">
<li>Create two unique virtual networks.</li>
</ol>
<pre><code class="language-sh">cloudflared tunnel vnet add staging-vnet
cloudflared tunnel vnet add production-vnet
</code></pre>
<ol start="3">
<li>Before moving on, run the following command to verify that your newly created virtual networks are listed correctly:</li>
</ol>
<pre><code class="language-sh">cloudflared tunnel vnet list
</code></pre>
<aside class="nb-aside note">
<h3 class="nb-aside-title" id="body-5396-default-virtual-network">Default virtual network</h3>
<p>All accounts come pre-configured with a virtual network named <code>default</code>. You can choose a new default by typing <code>cloudflared tunnel vnet update --default &lt;virtual-network-name&gt;</code>.</p>
</aside>
<ol start="4">
<li>Configure your tunnels with the IP/CIDR range of your private networks, and assign the tunnels to their respective virtual networks.</li>
</ol>
<pre><code class="language-sh">cloudflared tunnel route ip add --vnet staging-vnet 10.128.0.3/32 staging-tunnel
cloudflared tunnel route ip add --vnet production-vnet 10.128.0.3/32 production-tunnel
</code></pre>
<ol start="5">
<li>Verify that the IP routes are listed correctly:</li>
</ol>
<pre><code class="language-sh">cloudflared tunnel route ip list
</code></pre>
<pre><code>We now have two overlapping IP addresses routed over `staging-vnet` and `production-vnet` respectively.

6. Within your staging environment, create a [configuration file](/cloudflare-one/networks/connectors/cloudflare-tunnel/do-more-with-tunnels/local-management/configuration-file/) for `staging-tunnel`. The configuration file will be structured as follows:
</code></pre>
<pre><code class="language-txt">tunnel: &lt;Tunnel-UUID&gt;
credentials-file: /root/.cloudflared/credentials-file.json
warp-routing:
   enabled: true
</code></pre>
<pre><code>7. Run your tunnel.
</code></pre>
<pre><code class="language-sh">cloudflared tunnel run staging-tunnel
</code></pre>
<pre><code>8. Within your production environment, repeat Steps 6 and 7 for `production-tunnel`.

You can use now the Cloudflare One Client to [switch between virtual networks](#connect-to-a-virtual-network).
</code></pre>
