This example keeps `Tunnel1` and `Tunnel2` in the global routing table so the existing IPsec underlay configuration, IKE control plane, and management commands remain unchanged.

The VRF in this configuration is used only as a local forwarding target for PBR. It does not participate in any dynamic routing protocol, so no Route Distinguisher or address-family configuration is required.

The global default route remains in place and continues to forward IPsec underlay traffic and any non-LAN traffic out the router's normal Internet path. Return traffic from Cloudflare arrives on `Tunnel1` and `Tunnel2` in the global table and is forwarded to the LAN via the connected route for `192.168.125.0/24`, so no return-path configuration is required.
