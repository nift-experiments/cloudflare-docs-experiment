<p><strong>1. Obtain the VMware image</strong></p>
<p>Download the Virtual Appliance OVA image from <a href="https://assets.magic-wan-connector.cloudflare.com/stable/mconn.ova">https://assets.magic-wan-connector.cloudflare.com/stable/mconn.ova</a>. You can also download it from the dashboard when you register a virtual appliance, in the <strong>Add an appliance</strong> &gt; <strong>Virtual appliance</strong> step. The OVA image includes the files required to install and configure the virtual machine (VM) for Virtual Appliance with the appropriate settings. For details, refer to <a href="https://docs.vmware.com/en/VMware-vSphere/7.0/com.vmware.vsphere.vm_admin.doc/GUID-AE61948B-C2EE-436E-BAFB-3C7209088552.html">VMware VMs documentation</a>.</p>
<p>This image can be deployed multiple times to create several instances of a Virtual Appliance, in different locations or on the same ESXi host.</p>
<p>You consume one license key for each instance created. Generate a license key for each instance from the <a href="/cloudflare-wan/configuration/appliance/configure-virtual-appliance/#register-a-virtual-appliance-and-generate-a-license-key">Connectors page</a>. For example, to deploy 10 Virtual Appliances, generate 10 license keys.</p>
<p><strong>2. Deploy the Virtual Appliance on VMware</strong></p>
<p>The following instructions assume you already have VMware ESXi hypervisor installed with sufficient resources. For details, refer to <a href="#prerequisites">Prerequisites</a>.</p>
<ol>
<li>When setting up your VMware ESXi, you need to create port groups for Virtual Appliance. Go to <strong>Networking</strong> &gt; <strong>Port groups</strong>, and prepare your vSwitch port groups and/or VLANs for your desired network topology. For example, a simple deployment typically has:</li>
</ol>
<ul>
<li>A WAN port group where the Virtual Appliance will get an IP address (static or DHCP) that has access to the Internet.</li>
<li>A LAN port group, where the Virtual Appliance will act as default router, and possibly DHCP server.</li>
<li>A null, or unused, port group for allocating unused virtual interfaces in the Virtual Appliance. You can, for example, create a null port group with the name of <code>Null port group</code>, and a <strong>VLAN ID</strong> of <code>999</code>.</li>
</ul>
<aside class="nb-aside note">
<h3 class="nb-aside-title" id="body-5731-vlan-tagging">VLAN tagging</h3>
<p>Virtual Appliance supports creating subinterfaces through the use of <a href="https://en.wikipedia.org/wiki/IEEE_802.1Q">802.1Q VLAN tagging</a>.</p>
<p>Use VLAN ID <code>0</code> when:</p>
<ul>
<li>Connected to a Port Group or Distributed Port Group that is associated with a specific VLAN.</li>
<li>Connected to a Port Group or Distributed Port Group that is configured as a trunk that requires untagged packets.</li>
</ul>
<p>You can also configure subinterfaces on the Virtual Appliance by associating the network interface with a Port Group or Distributed Port Group trunk and specifying a VLAN ID in addition to the port associated with the network interface (VLAN ID <code>1</code>-<code>4094</code>).</p>
<p>Refer to <a href="https://kb.vmware.com/s/article/1003825">VMware's documentation</a> for more information.</p>
</aside>
<ol start="2">
<li>Extract the files in the OVA image you downloaded. For example:</li>
</ol>
<pre><code class="language-sh">tar -xvf mconn.ova</code></pre>
<p>Take note of the folder where you are extracting the files to, as you will need to refer to that folder when creating the VM.</p>
<ol start="3">
<li>
<p>Go to <strong>Virtual Machines</strong> &gt; <strong>Create/Register VM</strong> wizard to start deploying the Virtual Appliance.</p>
</li>
<li>
<p>Select <strong>Deploy a virtual machine from an OVF or OVA file</strong> &gt; <strong>Next</strong>.</p>
</li>
<li>
<p>Choose a descriptive name for your virtual machine.</p>
</li>
<li>
<p>Upload the files you have extracted from the OVA image. These include <code>mconn.ovf</code>, <code>mconn.nvram</code>, and <code>mconn.vmdk</code>.</p>
</li>
<li>
<p>Select where you want to save the files extracted from the OVA image &gt; <strong>Next</strong>.</p>
</li>
<li>
<p>In <strong>Networking mappings</strong>, select assignments for your desired topology according to the port groups you set up previously:</p>
</li>
<li>
<p>For example, map <code>eno1</code> port to <code>VM Network</code> to create your WAN, and <code>eno2</code> to <code>LAN0</code> to act as your LAN port.</p>
</li>
<li>
<p>Allocate any unused ports to the <code>null</code> port group.</p>
</li>
<li>
<p>Take note of your configuration. You will need this information to configure your network in the Cloudflare dashboard.</p>
</li>
<li>
<p>In <strong>Disk provisioning</strong>, select <strong>Thin</strong>.</p>
</li>
<li>
<p>Before completing the deployment wizard, disable <strong>Power on automatically</strong>. This is important so that you can configure the license key prior to boot.</p>
</li>
<li>
<p>Configure the virtual machine with the license key you generated:</p>
</li>
<li>
<p>Select the Virtual Appliance's VM &gt; <strong>Settings</strong>.</p>
</li>
<li>
<p>Go to <strong>VM Options</strong> &gt; <strong>Advanced</strong> &gt; <strong>Edit Configuration</strong>.</p>
</li>
<li>
<p>Select <strong>Add parameter</strong> to add your license key. Scroll down to the last entry (this is where VMware adds the new parameter), and add the following two new entries:</p>
<ul>
<li><strong>Key</strong>: <code>guestinfo.cloudflare.identity</code></li>
<li><strong>Value</strong> <code>&lt;YOUR_LICENSE_KEY&gt;</code></li>
</ul>
</li>
</ol>
<aside class="nb-aside note">
<p>You cannot use the same license key twice, or reuse a key once the virtual machine has been registered with Cloudflare. Generate a new key for every new Virtual Appliance from the <a href="/cloudflare-wan/configuration/appliance/configure-virtual-appliance/#register-a-virtual-appliance-and-generate-a-license-key">Connectors page</a>.</p>
</aside>
<ol start="12">
<li>Select <strong>Save</strong> to finish configuring your Virtual Appliance.</li>
<li>Continue setup in your <a href="#set-up-cloudflare-dashboard">Cloudflare dashboard.</a></li>
</ol>

<p><strong>1. Obtain the Virtual Appliance script</strong></p>
<p>Download the Virtual Appliance helper script for libvirt/KVM to your host. The script deploys the virtual machine with the appropriate settings for Virtual Appliance. For details on system requirements, refer to <a href="#prerequisites">Prerequisites</a>.</p>
<p>The deployment assumes the use of libvirt. The virtual machine manager graphical interface is not required. The VM uses the <code>OVMF_CODE.fd</code> file from the <code>ovmf</code> package on Debian or Ubuntu.</p>
<p>The script can be deployed multiple times to create several instances of a Virtual Appliance, in different locations or on the same host. You consume one license key for each instance created. Generate a license key for each instance from the <a href="/cloudflare-wan/configuration/appliance/configure-virtual-appliance/#register-a-virtual-appliance-and-generate-a-license-key">Connectors page</a>. For example, to deploy 10 Virtual Appliances, generate 10 license keys.</p>
<pre><code class="language-sh">curl -OL https://assets.magic-wan-connector.cloudflare.com/stable/libvirt_mconn_vm.sh</code></pre>
<p><strong>2. Deploy the Virtual Appliance on libvirt/KVM</strong></p>
<p>The following instructions assume you already have libvirt installed with sufficient resources. For details, refer to <a href="#prerequisites">Prerequisites</a>.</p>
<ol>
<li>In the terminal prompt of your host, run the script with elevated privileges. The script takes one optional argument, the name of the VM. If you do not provide a name, the VM defaults to <code>vmconn</code>:</li>
</ol>
<pre><code class="language-sh">sudo bash ./libvirt_mconn_vm.sh</code></pre>
<ol start="2">
<li>When prompted, enter a name for the VM. This name is used for the VM definition, the disk name, and the nvram file name. If the name already exists, the script exits with an error and you must use a different name.</li>
<li>Select the storage pool for the VM disk.</li>
<li>Choose whether to enable the graphics console in addition to the serial console.</li>
<li>Enter your license key.</li>
</ol>
<aside class="nb-aside note">
<p>You cannot use the same license key twice, or reuse a key once the virtual machine has been registered with Cloudflare. Generate a new key for every new Virtual Appliance from the <a href="/cloudflare-wan/configuration/appliance/configure-virtual-appliance/#register-a-virtual-appliance-and-generate-a-license-key">Connectors page</a>.</p>
</aside>
<p>The script deploys the virtual machine with the appropriate settings. NICs are named based on the defined PCI path of each NIC. Changing the PCI path of a NIC breaks functionality. NICs are configured in an inactive state with the <code>default</code> network source.</p>
<ol start="6">
<li>Configure the NICs for your environment. Configure the WAN-associated NICs as macvtap devices to avoid potential connectivity issues.</li>
<li>Continue setup in your <a href="#set-up-cloudflare-dashboard">Cloudflare dashboard</a>.</li>
</ol>
