

<section class="nb-tab-panel" role="tabpanel" data-nb-tabs-content data-nb-tab-label="Dashboard">

<ol>
<li>In the <a href="https://dash.cloudflare.com/">Cloudflare dashboard</a>, go to <strong>Zero Trust</strong> &gt; <strong>Traffic policies</strong> &gt; <strong>Traffic settings</strong> &gt; <strong>Certificates</strong>.</li>
<li>Select <strong>Upload certificate</strong>.</li>
<li>Enter the private key and SSL certificate you generated or select <strong>Paste certificate from file</strong> to upload them from a file. If uploading a certificate chain, paste all certificates (root and intermediates) in PEM format with the root certificate first.</li>
<li>Select <strong>Upload custom certificate</strong>.</li>
</ol>
<p>You can now <a href="#use-a-custom-root-certificate">use the generated custom root certificate</a> for inspection.</p>

</section>

<section class="nb-tab-panel" role="tabpanel" data-nb-tabs-content data-nb-tab-label="API">

<ol>
<li></li>
</ol>
<p>Use the <a href="/api/resources/mtls_certificates/methods/create/">Upload mTLS certificate endpoint</a> to upload the certificate and private key to Cloudflare. The certificate must be a root CA or certificate chain, formatted as a single string with <code>\n</code> replacing the line breaks.</p>
<pre class="nb-api-request"><code class="language-bash">curl --request POST \
--url https://api.cloudflare.com/client/v4/accounts/{account_id}/mtls_certificates \
--header &quot;Authorization: Bearer $CLOUDFLARE_API_TOKEN&quot; \
--data &#x27;{
&quot;name&quot;: &quot;example_ca_cert&quot;,
&quot;certificates&quot;: &quot;-----BEGIN CERTIFICATE-----\nXXXXX\n-----END CERTIFICATE-----&quot;,
&quot;private_key&quot;: &quot;-----BEGIN PRIVATE KEY-----\nXXXXX\n-----END PRIVATE KEY-----&quot;,
&quot;ca&quot;: true
}&#x27;</code></pre>
<p>The response will return a UUID for the certificate. For example:</p>
<pre><code class="language-json">{
  &quot;success&quot;: true,
  &quot;errors&quot;: [],
  &quot;messages&quot;: [],
  &quot;result&quot;: {
    &quot;id&quot;: &quot;2458ce5a-0c35-4c7f-82c7-8e9487d3ff60&quot;,
    &quot;name&quot;: &quot;example_ca_cert&quot;,
    &quot;issuer&quot;: &quot;O=Example Inc.,L=California,ST=San Francisco,C=US&quot;,
    &quot;signature&quot;: &quot;SHA256WithRSA&quot;,
    ...
  }
}
</code></pre>
<p>When uploading a certificate chain, the <code>certificates</code> field should contain all certificates in PEM format. To format this field, order the root certificate first, then concatenate any intermediate certificates.</p>
<ol start="2">
<li>Set the certificate as available for use in inspection with the <a href="/api/resources/zero_trust/subresources/gateway/subresources/certificates/methods/activate/">Activate a Zero Trust certificate endpoint</a>. This will deploy the certificate across the Cloudflare global network.</li>
</ol>
<pre class="nb-api-request"><code class="language-bash">curl --request POST \
--url https://api.cloudflare.com/client/v4/accounts/{account_id}/gateway/certificates/{certificate_id}/activate \
--header &quot;Authorization: Bearer $CLOUDFLARE_API_TOKEN&quot;</code></pre>
<p>The response will return the certificate and a <code>pending_deployment</code> binding status. For example:</p>
<pre><code class="language-json">{
	&quot;errors&quot;: [],
	&quot;messages&quot;: [],
	&quot;success&quot;: true,
	&quot;result&quot;: {

		&quot;id&quot;: &quot;f174e90a-fafe-4643-bbbc-4a0ed4fc8415&quot;,
		&quot;certificate&quot;: &quot;-----BEGIN CERTIFICATE-----\\n ... \\n-----END CERTIFICATE-----\\n&quot;,
		&quot;issuer_org&quot;: &quot;Example Inc.&quot;,
		&quot;issuer_raw&quot;: &quot;O=Example Inc.,L=California,ST=San Francisco,C=US&quot;,
		&quot;fingerprint&quot;: &quot;E9:19:49:AA:DD:D8:1E:C1:20:2A:D8:22:BF:A5:F8:FC:1A:F7:10:9F:C7:5B:69:AB:0:31:91:8B:61:B4:BF:1C&quot;,
		&quot;binding_status&quot;: &quot;pending_deployment&quot;,
		&quot;type&quot;: &quot;custom&quot;,
		&quot;updated_at&quot;: &quot;2014-01-01T05:20:00.12345Z&quot;,
		&quot;uploaded_on&quot;: &quot;2014-01-01T05:20:00.12345Z&quot;,
		&quot;created_at&quot;: &quot;2014-01-01T05:20:00.12345Z&quot;,
		&quot;expires_on&quot;: &quot;2014-01-01T05:20:00.12345Z&quot;
	}
}
</code></pre>

</ol>
<pre class="nb-api-request"><code class="language-bash">curl --request GET \
--url https://api.cloudflare.com/client/v4/accounts/{account_id}/gateway/certificates/{certificate_id} \

<ol start="4">
<li>
<p>(Optional) Verify the certificate is installed on your user's devices either <a href="/cloudflare-one/team-and-resources/devices/user-side-certificates/automated-deployment/">with the Cloudflare One Client</a> or <a href="/cloudflare-one/team-and-resources/devices/user-side-certificates/manual-deployment/">manually</a>.</p>
</li>
<li>
<p>Use the <a href="/api/resources/zero_trust/subresources/gateway/subresources/configurations/methods/edit/">Patch Zero Trust account configuration endpoint</a> to turn on the certificate for use in inspection. For example:</p>
</li>
</ol>
<pre class="nb-api-request"><code class="language-bash">curl --request PATCH \
--url https://api.cloudflare.com/client/v4/accounts/{account_id}/gateway/configuration \
--header &quot;Authorization: Bearer $CLOUDFLARE_API_TOKEN&quot; \
--data &#x27;{
&quot;settings&quot;: {
  &quot;certificate&quot;: {
    &quot;id&quot;: &quot;{certificate_id}&quot;,
    &quot;in_use&quot;: true
  }
}
}&#x27;</code></pre>
<p>Once <code>in-use</code> is set to <code>true</code>, Gateway will sign your traffic using the custom root certificate and private key. If you turn off or deactivate the custom certificate, Gateway will revert to the next available Cloudflare certificate generated for your Zero Trust account.</p>
