

1. [Download](https://pkg.cloudflareclient.com/) and install the Cloudflare One Client package.

2. Open a terminal window. Ensure that you are logged into the terminal as the current user and not as root.

3. (Optional) Validate your organization's <span class="nb-glossary-tooltip" title="team name">team name</span>:

<div class="nb-tabs" data-nb-tabs data-nb-sync-key="os"><div role="tablist" aria-label="Options" data-nb-tabs-list></div><div data-nb-tabs-panels>

<section class="nb-tab-panel" role="tabpanel" data-nb-tabs-content data-nb-tab-label="macOS / Linux">
<pre><code class="language-sh">curl --fail --silent --show-error \
  &quot;https://&lt;YOUR_TEAM_NAME&gt;.cloudflareaccess.com/cdn-cgi/access/certs&quot; \
  &gt; /dev/null
</code></pre>
</section>
<section class="nb-tab-panel" role="tabpanel" data-nb-tabs-content data-nb-tab-label="Windows (PowerShell)">
<pre><code class="language-powershell">Invoke-WebRequest -UseBasicParsing &quot;https://&lt;YOUR_TEAM_NAME&gt;.cloudflareaccess.com/cdn-cgi/access/certs&quot; | Out-Null
</code></pre>
</section>

</div></div>

A successful request confirms that the team domain exists and is reachable. It does not confirm enrollment eligibility. Compare the value with the team name in your Zero Trust settings.

4. Enroll into Cloudflare Zero Trust using your team name:

<pre><code class="language-sh">warp-cli registration new &lt;your-team-name&gt;
</code></pre>


5. In the browser window that opens, complete the authentication steps required by your organization.

Once authenticated, you will see a success page and a dialog prompting you to open a link.

6. Select **Open Link**.

7. Verify the registration in the terminal:

<pre><code class="language-sh">warp-cli registration show
</code></pre>


<details class="nb-details"><summary>Troubleshoot missing registration</summary><div class="nb-details-body">

<p>The <code>warp-cli registration new</code> success message does not prove that organization enrollment completed. If the browser reports an invalid enrollment request while the CLI reports success, treat the enrollment as failed. Inspect the enrollment endpoint HTTP response in browser developer tools. You can also collect <a href="/cloudflare-one/team-and-resources/devices/cloudflare-one-client/troubleshooting/diagnostic-logs/">diagnostic logs</a> with <code>warp-diag</code>.</p>
<p>Do not open the bare <code>https://&lt;YOUR_TEAM_NAME&gt;.cloudflareaccess.com/warp</code> URL as a fallback. It does not contain the active enrollment session. If the registration continues to be missing, manually copy the authentication token from the browser to the Cloudflare One Client:</p>
<ol>
<li>On the success page, right-click and select <strong>View Page Source</strong>.</li>
<li>Find the HTML metadata tag that contains the token. For example, <code>&lt;meta http-equiv=&quot;refresh&quot; content&quot;=0;url=com.cloudflare.warp://&lt;your-team-name&gt;.cloudflareaccess.com/auth?token=yeooilknmasdlfnlnsadfojDSFJndf_kjnasdf...&quot; /&gt;</code></li>
<li>Copy the URL field: <code>com.cloudflare.warp://&lt;your-team-name&gt;.cloudflareaccess.com/auth?token=&lt;your-token&gt;</code></li>
<li>In the terminal, run the following command using the URL obtained in the previous step.</li>
</ol>
<pre><code class="language-sh">warp-cli registration token &quot;com.cloudflare.warp://&lt;your-team-name&gt;.cloudflareaccess.com/auth?token=&lt;your-token&gt;&quot;
</code></pre>
<p>If you get a <code>401</code> error, then the token has expired. Generate a new one by refreshing the web page and quickly grab the new token from the page source.</p>

</div></details>

8. If you did not configure the client to [auto-connect](/cloudflare-one/team-and-resources/devices/cloudflare-one-client/configure/settings/#auto-connect), manually connect:

<pre><code class="language-sh">warp-cli connect
</code></pre>


9. If the device profile routes `www.cloudflare.com` through WARP, verify the data path:

<div class="nb-tabs" data-nb-tabs data-nb-sync-key="os"><div role="tablist" aria-label="Options" data-nb-tabs-list></div><div data-nb-tabs-panels>

<section class="nb-tab-panel" role="tabpanel" data-nb-tabs-content data-nb-tab-label="macOS / Linux">
<pre><code class="language-sh">curl --silent https://www.cloudflare.com/cdn-cgi/trace | grep &#x27;^warp=on$&#x27;
</code></pre>
</section>
<section class="nb-tab-panel" role="tabpanel" data-nb-tabs-content data-nb-tab-label="Windows (PowerShell)">
<pre><code class="language-powershell">if (-not (curl.exe --silent https://www.cloudflare.com/cdn-cgi/trace | Select-String &#x27;^warp=on$&#x27;)) { exit 1 }
</code></pre>
</section>

</div></div>

In Include mode, expect `warp=off` for destinations that are not in the include list. Test an included destination instead. In DNS-only mode, use the registration output from step 7 to verify enrollment. DNS-only mode cannot carry network traffic.
