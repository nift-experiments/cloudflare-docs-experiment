

1.  In the [Cloudflare dashboard](https://dash.cloudflare.com/), go to **Zero Trust** > **Team & Resources** > **Devices** > **Device profiles** > **General profiles**.
2.  Locate the [device profile](/cloudflare-one/team-and-resources/devices/cloudflare-one-client/configure/device-profiles/) you would like to modify and select **Configure**.
3.  Under **Split Tunnels**, check whether your [Split Tunnels mode](/cloudflare-one/team-and-resources/devices/cloudflare-one-client/configure/route-traffic/split-tunnels/#change-split-tunnels-mode) is set to **Exclude** or **Include**.
4.  Select **Manage**.
5.  You can exclude or include routes based on either their IP address or domain. When possible we recommend adding an IP address instead of a domain. To learn about the consequences of adding a domain, refer to [Domain-based Split Tunnels](/cloudflare-one/team-and-resources/devices/cloudflare-one-client/configure/route-traffic/split-tunnels/#domain-based-split-tunnels).

<section class="nb-tab-panel" role="tabpanel" data-nb-tabs-content data-nb-tab-label="Add an IP">
<p>To add an IP address to Split Tunnels:</p>
<ol>
<li>Select <em>IP Address</em>.</li>
<li>Enter the IP address or <span class="nb-glossary-tooltip" title="CIDR">CIDR</span> you want to exclude or include.</li>
<li>Select <strong>Save destination</strong>.</li>
</ol>
<p>Traffic to this IP address is now excluded or included from the WARP tunnel.</p>

</section> <section class="nb-tab-panel" role="tabpanel" data-nb-tabs-content data-nb-tab-label="Add a domain">
<p>To add a domain to Split Tunnels:</p>
<ol>
<li>Select <em>Domain</em>.</li>
<li>Enter a <a href="/cloudflare-one/team-and-resources/devices/cloudflare-one-client/configure/route-traffic/split-tunnels/#valid-domains">valid domain</a> to exclude or include.</li>
<li>Select <strong>Save destination</strong>.</li>
<li>(Optional) If your domain does not have a public DNS record, create a <a href="/cloudflare-one/team-and-resources/devices/cloudflare-one-client/configure/route-traffic/local-domains/">Local Domain Fallback</a> entry to allow a private DNS server to handle domain resolution.</li>
</ol>
<p>When a user goes to the domain, the domain gets resolved according to your Local Domain Fallback configuration (either by Gateway or by your private DNS server). Split Tunnels will then dynamically include or exclude the IP address returned in the DNS lookup.</p>
