<ol>
<li>
<p>In the <a href="https://dash.cloudflare.com/">Cloudflare dashboard</a>, go to <strong>Zero Trust</strong> &gt; <strong>Team &amp; Resources</strong> &gt; <strong>Devices</strong> &gt; <strong>Device profiles</strong> &gt; <strong>General profiles</strong>.</p>
</li>
<li>
<p>Locate the <a href="/cloudflare-one/team-and-resources/devices/cloudflare-one-client/configure/device-profiles/">device profile</a> you would like to view or modify and select <strong>Configure</strong>.</p>
</li>
<li>
<p>Scroll down to <strong>Local Domain Fallback</strong> and select <strong>Manage</strong>.</p>
</li>
<li>
<p>In <strong>Domain</strong>, enter the apex domain (<code>example.com</code>) that you want to resolve using your private DNS server. All prefixes under the apex domain are subject to Local Domain Fallback (in other words, <code>example.com</code> is interpreted as <code>*.example.com</code>).</p>
</li>
<li>
<p>In <strong>DNS Servers</strong>, enter the IP address of the DNS servers that should resolve that domain name. Cloudflare recommends keeping the list to a maximum of eight servers to avoid performance issues.</p>
</li>
<li>
<p>Enter an optional description and select <strong>Save domain</strong>.</p>
</li>
</ol>

<p>A Local Domain Fallback list is scoped to a specific <a href="/cloudflare-one/team-and-resources/devices/cloudflare-one-client/configure/device-profiles/">device profile</a>. If a device profile does not have a corresponding Local Domain Fallback resource, those devices will use the default local domains shown in Step 2.</p>
<ol>
<li>Add the following permission to your <a href="https://registry.terraform.io/providers/cloudflare/cloudflare/latest/docs/resources/api_token"><code>cloudflare_api_token</code></a>:</li>
</ol>
<ul>
<li><code>Zero Trust Write</code></li>
</ul>
<ol start="2">
<li>(Optional) Create a list of domains that you can reuse across multiple device profiles. For example, you can declare a local value in the same module as your device profiles:</li>
</ol>

<ol start="3">
<li>To configure Local Domain Fallback for the default device profile, use the <a href="https://registry.terraform.io/providers/cloudflare/cloudflare/latest/docs/resources/zero_trust_device_default_profile_local_domain_fallback"><code>cloudflare_zero_trust_device_default_profile_local_domain_fallback</code></a> resource. To configure Local Domain Fallback for a custom device profile, use<a href="https://registry.terraform.io/providers/cloudflare/cloudflare/latest/docs/resources/zero_trust_device_custom_profile_local_domain_fallback"><code>cloudflare_zero_trust_device_custom_profile_local_domain_fallback</code></a>. For example:</li>
</ol>
<pre><code class="language-tf">resource &quot;cloudflare_zero_trust_device_custom_profile_local_domain_fallback&quot; &quot;example&quot; {
	account_id = var.cloudflare_account_id
	policy_id  = cloudflare_zero_trust_device_custom_profile.example.id
	domains = concat(
		&#35; Global entries
		local.default_local_domains,

		&#35; Profile-specific entries
		[
			{
			suffix = &quot;example.com&quot;
			description = &quot;Domain for local development&quot;
			dns_server = [&quot;1.1.1.1&quot;, &quot;192.168.0.1&quot;]
			}
		]
	)
}
</code></pre>
<p>For <code>suffix</code>, specify the apex domain (<code>example.com</code>) that you want to resolve using your private DNS server. All prefixes under the apex domain are subject to Local Domain Fallback (in other words, <code>example.com</code> is interpreted as <code>*.example.com</code>). For <code>dns_server</code>, enter the IP address of the DNS servers that should resolve that domain name. Cloudflare recommends keeping the list to a maximum of eight servers to avoid performance issues.</p>
