

1. Use the [Create Zone](/api/resources/zones/methods/create/) endpoint to create an [internal zone](/dns/internal-dns/internal-zones/). Specify your account ID and set the `type` to `internal`.

<details class="nb-details"><summary>Internal zone configuration conditions</summary><div class="nb-details-body">

<ul>
<li>Internal zones can contain the same <a href="/dns/manage-dns-records/reference/dns-record-types/">DNS record types</a> that Cloudflare supports for public zones.</li>
<li>An internal zone can have the same name as a public zone in the same account.</li>
<li>Each internal zone can be linked to multiple <a href="/dns/internal-dns/dns-views/">views</a>.<sup>1</sup></li>
<li>There can be several internal zones with the same name in one account. However, two internal zones with the same name cannot be linked to the same view.</li>
<li>Internal zones are not subject to any top-level domain (TLD) restrictions. This means that an internal zone can be created if its TLD is not registered publicly (for example, <code>xyz.local</code>), if it is created on the TLD itself (<code>local</code>), or even if on the root (<code>.</code>).</li>
</ul>
<p><sup>1</sup> Logical groupings of internal DNS zones that are referenced by Gateway resolver policies to define how a specific query should be resolved.</p>

</div></details>

<details class="nb-details"><summary>Example</summary><div class="nb-details-body">

<pre class="nb-api-request"><code class="language-bash">curl --request POST \
--url https://api.cloudflare.com/client/v4/zones \
--header &quot;Authorization: Bearer $CLOUDFLARE_API_TOKEN&quot; \
--data &#x27;{
&quot;account&quot;: {
  &quot;id&quot;: &quot;&lt;ACCOUNT_ID&gt;&quot;
},
&quot;name&quot;: &quot;&lt;ZONE_NAME&gt;&quot;,
&quot;type&quot;: &quot;internal&quot;
}&#x27;</code></pre>

</div></details>

2. Add DNS records to your internal zone using your preferred option:

- [Import](/api/resources/dns/subresources/records/methods/import/) a formatted BIND file. Refer to the [DNS records how-to](/dns/manage-dns-records/how-to/import-and-export/) for guidance.
- Use other API endpoints, such as [`/batch`](/api/resources/dns/subresources/records/methods/batch/), to manage DNS records. Refer to [Batch record changes](/dns/manage-dns-records/how-to/batch-record-changes/#use-the-api) for details.

3. Repeat this process for each internal zone you wish to add.
