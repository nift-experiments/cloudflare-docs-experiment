<ol>
<li>In <a href="https://one.dash.cloudflare.com/">Cloudflare One</a>, go to <strong>Traffic policies</strong> &gt; <strong>Firewall policies</strong> &gt; <strong>Resolver policies</strong>.</li>
<li>Select <strong>Add a policy</strong> and enter a name and description.</li>
<li>Create an expression for the traffic you wish to route. For guidance about selectors, operators, and values, refer to <a href="/cloudflare-one/traffic-policies/resolver-policies/#selectors">Gateway resolver policies</a>.</li>
<li>Select <strong>Use Internal DNS</strong>. Choose the view that queries matching the expression should be sent to.</li>
<li>(Optional) Adjust the option to <strong>Fallback through public DNS</strong> according to your use case.</li>
</ol>
<ul>
<li>Off: Gateway DNS resolver returns the response as-is to the client.</li>
<li>On: In case the response from the internal zone is REFUSED, NXDOMAIN, or a response with a CNAME type, Gateway DNS resolver sends the query to Cloudflare 1.1.1.1 public resolver and tries to resolve the query via public DNS.</li>
</ul>
<ol start="6">
<li>Select <strong>Create policy</strong> to confirm.</li>
</ol>

<p>Use the API endpoints under <a href="/api/resources/zero_trust/subresources/gateway/subresources/rules/">Zero Trust &gt; Gateway &gt; Rules</a> to set up resolver policies. For guidance about selectors, operators, and values, refer to <a href="/cloudflare-one/traffic-policies/resolver-policies/#selectors">Gateway</a>.</p>
<p>Use the rule settings object to define <code>resolve_dns_internally</code>, specifying <code>view_id</code> and <code>fallback</code> option. The fallback options behave as follows:</p>
<ul>
<li><code>none</code>: Gateway DNS resolver returns the response as-is to the client.</li>
<li><code>public_dns</code>: In case the response from the internal zone is REFUSED, NXDOMAIN, or a response with a CNAME type, Gateway DNS resolver sends the query to Cloudflare 1.1.1.1 public resolver and tries to resolve the query via public DNS.</li>
</ul>
