<p>The simplest way to route emails is forwarding them to existing email addresses.</p>
<h3 id="body-8610-add-a-destination-address">Add a destination address</h3>
<p>Before you can create a routing rule, add and verify the destination address that will receive the forwarded emails. Destination addresses are managed at the account level and can be reused across domains.</p>
<ol>
<li>In the Cloudflare dashboard, go to <strong>Compute</strong> &gt; <strong>Email Service</strong> &gt; <strong>Email Routing</strong> &gt; <strong>Destination Addresses</strong>.</li>
</ol>
<div class="nb-dash-button"></div>
<ol start="2">
<li>Under <strong>Destination addresses</strong>, enter the email address you want to use as a destination in the inline form and submit it.</li>
<li>Open the verification email Cloudflare sends to that address and select <strong>Verify email address</strong>.</li>
</ol>
<p>For full details, refer to <a href="/email-service/configuration/email-routing-addresses/#add-a-destination-address">Add a destination address</a>.</p>
<h3 id="body-8610-create-a-routing-rule">Create a routing rule</h3>
<ol>
<li>In the Cloudflare dashboard, go to <strong>Compute</strong> &gt; <strong>Email Service</strong> &gt; <strong>Email Routing</strong>.</li>
</ol>
<div class="nb-dash-button"></div>
<ol start="2">
<li>
<p>Select the domain you want to create an email address for.</p>
</li>
<li>
<p>Select the <strong>Routing Rules</strong> tab.</p>
</li>
<li>
<p>Select <strong>Create routing rule</strong>.</p>
</li>
<li>
<p>Configure your first rule (for instance, forwarding emails to <code>support@yourdomain.com</code> to your personal email address):</p>
</li>
</ol>
<ul>
<li><strong>Email pattern</strong>: Enter the local part of the email (for example, <code>support</code> for <code>support@yourdomain.com</code>), and select your domain</li>
<li><strong>Action</strong>: Send to an email</li>
<li><strong>Destination</strong>: Your personal email address (for example, <code>your-email@gmail.com</code>)</li>
</ul>
<ol start="6">
<li>Select <strong>Save</strong>.</li>
</ol>
<h3 id="body-8610-test-your-routing-rule">Test your routing rule</h3>
<p>Verify that your routing rule is working:</p>
<ol>
<li>
<p>Send an email from another email account to your newly created address (for example, <code>support@yourdomain.com</code>). Send from an account that is different from the destination address. Some providers discard messages that appear to come from the same account they are being delivered to.</p>
</li>
<li>
<p>Check the destination inbox for the forwarded email.</p>
</li>
<li>
<p>If you do not see the email right away, check your spam folder.</p>
</li>
</ol>

<section class="nb-tab-panel" role="tabpanel" data-nb-tabs-content data-nb-tab-label="Route to Workers">

<p>Use Workers to process emails with custom logic before forwarding or responding.</p>
<h3 id="body-8610-create-an-email-processing-worker">Create an email processing Worker</h3>
<ol>
<li>Create a new Worker project:</li>
</ol>
<pre><code class="language-sh">npm create cloudflare@latest email-processor
</code></pre>
<p>When prompted, select <strong>&quot;Hello World&quot; Worker</strong> as the template. Then navigate to the project directory:</p>
<pre><code class="language-sh">cd email-processor
</code></pre>
<ol start="2">
<li>Install the required package for creating email replies:</li>
</ol>
<pre><code class="language-sh">npm install mimetext
</code></pre>
<ol start="3">
<li>Add the <code>nodejs_compat</code> compatibility flag to your Wrangler configuration file. This is required for the <code>mimetext</code> package:</li>
</ol>
<div class="nb-wrangler-config">
<pre><code class="language-jsonc">{
	&quot;compatibility_flags&quot;: [&quot;nodejs_compat&quot;],
}
</code></pre>
</div>
<ol start="4">
<li>Create your email handler in <code>src/index.ts</code>:</li>
</ol>
<pre><code class="language-ts">import { EmailMessage } from &quot;cloudflare:email&quot;;
import { createMimeMessage } from &quot;mimetext&quot;;

// ============================================
// Configuration - Update these values
// ============================================
const YOUR_DOMAIN = &quot;yourdomain.com&quot;; // Replace with your verified domain
const FORWARD_TO_EMAIL = &quot;your-team@example.com&quot;; // Replace with where you want emails forwarded

export default {
	async email(message, env, ctx): Promise&lt;void&gt; {
		const sender = message.from;
		const recipient = message.to;
		const subject = message.headers.get(&quot;subject&quot;) || &quot;&quot;;

		console.log(
			`Processing email from ${sender} to ${recipient} with subject ${subject}`,
		);

		// Route based on recipient
		if (recipient.includes(&quot;support@&quot;)) {
			// Send auto-reply
			const msg = createMimeMessage();
			const messageId = message.headers.get(&quot;Message-ID&quot;);
			if (messageId) {
				msg.setHeader(&quot;In-Reply-To&quot;, messageId);
				msg.setHeader(&quot;References&quot;, messageId);
			}
			msg.setSender({
				name: &quot;Support Team&quot;,
				addr: `support@${YOUR_DOMAIN}`,
			});
			msg.setRecipient(message.from);
			msg.setSubject(`Re: ${subject}`);

			// Add plain text version
			msg.addMessage({
				contentType: &quot;text/plain&quot;,
				data: &quot;Thank you for contacting support. Your ticket number is 123.\n\nA member of our support team will get back to you shortly.&quot;,
			});

			// Add HTML version
			msg.addMessage({
				contentType: &quot;text/html&quot;,
				data: &quot;&lt;p&gt;Thank you for contacting support. Your ticket number is &lt;strong&gt;123&lt;/strong&gt;.&lt;/p&gt;&lt;p&gt;A member of our support team will get back to you shortly.&lt;/p&gt;&quot;,
			});

			const replyMessage = new EmailMessage(
				`support@${YOUR_DOMAIN}`,
				message.from,
				msg.asRaw(),
			);

			await message.reply(replyMessage);

			// Forward to support team
			await message.forward(FORWARD_TO_EMAIL);
		} else {
			// Default: forward to admin
			await message.forward(FORWARD_TO_EMAIL);
		}
	},
} satisfies ExportedHandler&lt;Env&gt;;
</code></pre>
<aside class="nb-aside caution">
<h3 class="nb-aside-title" id="body-8610-update-configuration">Update configuration</h3>
<p>Before deploying, update the constants at the top of the file:</p>
<ul>
<li><code>YOUR_DOMAIN</code>: Your verified domain from the Cloudflare dashboard</li>
<li><code>FORWARD_TO_EMAIL</code>: The email address where you want to receive forwarded emails</li>
</ul>
</aside>
<ol start="5">
<li>Deploy your Worker:</li>
</ol>
<pre><code class="language-sh">npm run deploy
</code></pre>
<h3 id="body-8610-configure-routing-to-worker">Configure routing to Worker</h3>
<ol>
<li>In the Cloudflare dashboard, go to <strong>Compute</strong> &gt; <strong>Email Service</strong> &gt; <strong>Email Routing</strong>.</li>
</ol>
<div class="nb-dash-button"></div>
<ol start="2">
<li>
<p>Select the domain you want to configure routing for.</p>
</li>
<li>
<p>Select the <strong>Routing Rules</strong> tab.</p>
</li>
<li>
<p>Select <strong>Create routing rule</strong>.</p>
</li>
<li>
<p>Configure Worker routing:</p>
</li>
</ol>
<ul>
<li><strong>Email pattern</strong>: Enter the local part of the email (for example, <code>support</code> for <code>support@yourdomain.com</code>), and select your domain</li>
<li><strong>Action</strong>: Send to a Worker</li>
<li><strong>Worker</strong>: Select your <code>email-processor</code> Worker</li>
</ul>
<ol start="6">
<li>Select <strong>Save</strong>.</li>
</ol>
<h3 id="body-8610-test-your-email-routing">Test your email routing</h3>
<p>After configuring the routing rule, test that it works:</p>
<ol>
<li>
<p>Send an email from your personal email account to the address you configured (for example, <code>support@yourdomain.com</code>).</p>
</li>
<li>
<p>Check your <code>FORWARD_TO_EMAIL</code> inbox for the forwarded email.</p>
</li>
<li>
<p>If the recipient email was <code>support@</code>, you should also receive an auto-reply at your personal email address.</p>
</li>
</ol>
