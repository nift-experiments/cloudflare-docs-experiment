
<h3 id="body-9067-2-1-manual-create-a-service-token">2.1. (Manual) Create a service token</h3>

The service token will be used to restrict requests to the tunnel, and is needed for the next step.

<div class="nb-steps">

<ol>
<li>
<p>In the <a href="https://dash.cloudflare.com/">Cloudflare dashboard</a>, go to <strong>Zero Trust</strong> &gt; <strong>Access controls</strong> &gt; <strong>Service credentials</strong> &gt; <strong>Service Tokens</strong>.</p>
</li>
<li>
<p>Select <strong>Create Service Token</strong>.</p>
</li>
<li>
<p>Name the service token. The name allows you to easily identify events related to the token in the logs and to revoke the token individually.</p>
</li>
<li>
<p>Set a <strong>Service Token Duration</strong> of <code>Non-expiring</code>. This prevents the service token from expiring, ensuring it can be used throughout the life of the Hyperdrive configuration.</p>
</li>
<li>
<p>Select <strong>Generate token</strong>. You will see the generated Client ID and Client Secret for the service token, as well as their respective request headers.</p>
</li>
<li>
<p>Copy the Access Client ID and Access Client Secret. These will be used when creating the Hyperdrive configuration.</p>
</li>
</ol>
<aside class="nb-aside caution">
<p>This is the only time Cloudflare Access will display the Client Secret. If you lose the Client Secret, you must regenerate the service token.</p>
</aside>

</div>

<h3 id="body-9067-2-2-manual-create-an-access-application-to-secure-the-tunnel">2.2. (Manual) Create an Access application to secure the tunnel</h3>

[Cloudflare Access](/cloudflare-one/access-controls/policies/) will be used to verify that requests to the tunnel originate from Hyperdrive using the service token created above.

<div class="nb-steps">

<ol>
<li>
<p>In the <a href="https://dash.cloudflare.com/">Cloudflare dashboard</a>, go to <strong>Zero Trust</strong> &gt; <strong>Access controls</strong> &gt; <strong>Applications</strong>.</p>
</li>
<li>
<p>Select <strong>Create new application</strong>.</p>
</li>
<li>
<p>Select <strong>Self-hosted and private</strong>.</p>
</li>
<li>
<p>Select <strong>Add public hostname</strong> and enter the subdomain and domain that was previously set for the tunnel application.</p>
</li>
<li>
<p>Select <strong>Create new policy</strong>.</p>
</li>
<li>
<p>Enter a <strong>Policy name</strong> and set the <strong>Action</strong> to <em>Service Auth</em>.</p>
</li>
<li>
<p>Create an <strong>Include</strong> rule. Specify a <strong>Selector</strong> of <em>Service Token</em> and the <strong>Value</strong> of the service token you created in step <a href="#21-manual-create-a-service-token">2. Create a service token</a>.</p>
</li>
<li>
<p>Save the policy.</p>
</li>
<li>
<p>In <strong>Identity providers</strong>, turn off <em>Accept all available identity providers</em> and clear all identity providers.</p>
</li>
<li>
<p>In <strong>Session Duration</strong>, select <code>No duration, expires immediately</code>.</p>
</li>
<li>
<p>(Optional) Go to <strong>Additional settings</strong>. Turn off <strong>Show application in App Launcher</strong>.</p>
</li>
<li>
<p>Select <strong>Create</strong>.</p>
</li>
</ol>

</div>

<h3 id="body-9067-2-3-manual-create-a-hyperdrive-configuration">2.3. (Manual) Create a Hyperdrive configuration</h3>

This will create a Hyperdrive configuration using the usual database information (database name, database host, database user, and database password).

In addition, it will also set the Access Client ID and the Access Client Secret of the Service Token. When Hyperdrive makes requests to the tunnel, requests will be intercepted by Access and validated using the credentials of the Service Token.

<aside class="nb-aside note">


<p>When creating the Hyperdrive configuration for the private database, you must enter the <code>access-client-id</code> and the <code>access-client-secret</code>, and omit the <code>port</code>. Hyperdrive will route database messages to the public hostname of the tunnel, and the tunnel will rely on its service configuration (as configured in <a href="#12-connect-your-database-using-a-public-hostname">1.2. Connect your database using a public hostname</a>) to route requests to the database within your private network.</p>


</aside>
