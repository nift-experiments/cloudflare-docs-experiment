<pre><code class="language-ts">export interface Env {
  USERS_NOTIFICATION_CONFIG: KVNamespace;
}

export default {
  async fetch(request, env, ctx): Promise&lt;Response&gt; {
    try {
      await env.USERS_NOTIFICATION_CONFIG.put(&quot;user_2&quot;, &quot;disabled&quot;);
      const value = await env.USERS_NOTIFICATION_CONFIG.get(&quot;user_2&quot;);
      if (value === null) {
        return new Response(&quot;Value not found&quot;, { status: 404 });
      }
      return new Response(value);
    } catch (err) {
      console.error(`KV returned error:`, err);
      const errorMessage =
        err instanceof Error
          ? err.message
          : &quot;An unknown error occurred when accessing KV storage&quot;;
      return new Response(errorMessage, {
        status: 500,
        headers: { &quot;Content-Type&quot;: &quot;text/plain&quot; },
      });
    }
  },
} satisfies ExportedHandler&lt;Env&gt;;
</code></pre>
</div>
<p>The code above:</p>
<ol>
<li>Writes a key to <code>BINDING_NAME</code> using KV's <code>put()</code> method.</li>
<li>Reads the same key using KV's <code>get()</code> method, and returns an error if the key is null (or in case the key is not set, or does not exist).</li>
<li>Uses JavaScript's <a href="https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Statements/try...catch"><code>try...catch</code></a> exception handling to catch potential errors. When writing or reading from any service, such as Workers KV or external APIs using <code>fetch()</code>, you should expect to handle exceptions explicitly.</li>
</ol>
<p>The browser should simply return the <code>VALUE</code> corresponding to the <code>KEY</code> you have specified with the <code>get()</code> method.
