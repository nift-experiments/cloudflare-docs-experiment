<aside class="nb-aside note">
<p>When using <a href="/workers/wrangler/commands/general/#dev"><code>wrangler dev</code></a> to develop locally, Wrangler defaults to using a local version of KV to avoid interfering with any of your live production data in KV. This means that reading keys that you have not written locally returns null.</p>
<p>To have <code>wrangler dev</code> connect to your Workers KV namespace running on Cloudflare's global network, you can set <code>&quot;remote&quot; : true</code> in the KV binding configuration. Refer to the <a href="/workers/local-development/#remote-bindings">remote bindings documentation</a> for more information.</p>
<p>Also refer to <a href="/kv/concepts/kv-bindings/#use-kv-bindings-when-developing-locally">KV binding docs</a>.</p>
</aside>
<div class="nb-steps">
<ol>
<li>In your Worker script, add your KV binding in the <code>Env</code> interface. If you have bootstrapped your project with JavaScript, this step is not required.</li>
</ol>
<pre><code class="language-ts">interface Env {
	USERS_NOTIFICATION_CONFIG: KVNamespace;
	// ... other binding types
}
</code></pre>
<ol start="2">
<li>Use the <code>put()</code> method on <code>USERS_NOTIFICATION_CONFIG</code> to create a new key-value pair. You will add a new key <code>user_2</code> with value <code>disabled</code> to your KV namespace.</li>
</ol>
<pre><code class="language-ts">let value = await env.USERS_NOTIFICATION_CONFIG.put(&quot;user_2&quot;, &quot;disabled&quot;);
</code></pre>
<ol start="3">
<li>Use the KV <code>get()</code> method to fetch the data you stored in your KV namespace. You will fetch the value of the key <code>user_2</code> from your KV namespace.</li>
</ol>
<pre><code class="language-ts">let value = await env.USERS_NOTIFICATION_CONFIG.get(&quot;user_2&quot;);
</code></pre>
</div>
<p>Your Worker code should look like this:</p>
<div class="nb-type-script-example">
<pre><code class="language-ts">export interface Env {
  USERS_NOTIFICATION_CONFIG: KVNamespace;
}

export default {
  async fetch(request, env, ctx): Promise&lt;Response&gt; {
    try {
      await env.USERS_NOTIFICATION_CONFIG.put(&quot;user_2&quot;, &quot;disabled&quot;);
      const value = await env.USERS_NOTIFICATION_CONFIG.get(&quot;user_2&quot;);
      if (value === null) {
        return new Response(&quot;Value not found&quot;, { status: 404 });
      }
      return new Response(value);
    } catch (err) {
      console.error(`KV returned error:`, err);
      const errorMessage =
        err instanceof Error
          ? err.message
          : &quot;An unknown error occurred when accessing KV storage&quot;;
      return new Response(errorMessage, {
        status: 500,
        headers: { &quot;Content-Type&quot;: &quot;text/plain&quot; },
      });
    }
  },
} satisfies ExportedHandler&lt;Env&gt;;
</code></pre>
</div>
<p>The code above:</p>
<ol>
<li>Writes a key to your KV namespace using KV's <code>put()</code> method.</li>
<li>Reads the same key using KV's <code>get()</code> method.</li>
<li>Checks if the key is null, and returns a <code>404</code> response if it is.</li>
<li>If the key is not null, it returns the value of the key.</li>
<li>Uses JavaScript's <a href="https://developer.mozilla.org/docs/Web/JavaScript/Reference/Statements/try...catch"><code>try...catch</code></a> exception handling to catch potential errors. When writing or reading from any service, such as Workers KV or external APIs using <code>fetch()</code>, you should expect to handle exceptions explicitly.</li>
</ol>
