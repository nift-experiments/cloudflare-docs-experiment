<p><strong>Set up the monitor</strong></p>
<p>You can create a monitor within the <a href="/load-balancing/load-balancers/create-load-balancer/">load balancer workflow</a> or in the <strong>Monitors</strong> tab:</p>
<ol>
<li>
<p>Go to <strong>Load Balancing</strong>.</p>
</li>
<li>
<p>Select the <strong>Monitors</strong> tab.</p>
</li>
<li>
<p>Select <strong>Create monitor</strong>.</p>
</li>
<li>
<p>Add the following information:</p>
</li>
</ol>
<ul>
<li><strong>Type</strong>: The protocol to use for health monitors</li>
<li><em>Non-enterprise customers</em>: Choose <strong>HTTP</strong>, <strong>HTTPS</strong>, or <strong>TCP</strong>.</li>
<li><em>Enterprise customers</em>: Choose <strong>HTTP</strong>, <strong>HTTPS</strong>, <strong>TCP</strong>, <strong>UDP ICMP</strong>, <strong>ICMP Ping</strong>, or <strong>SMTP</strong>.</li>
<li><strong>Path</strong>: The endpoint path to run health monitor requests against</li>
<li><strong>Port</strong>: The destination port for health monitors</li>
</ul>
<ol start="5">
<li>For additional settings, select <strong>Advanced health monitor settings</strong>:</li>
</ol>
<ul>
<li><strong>Interval</strong>:</li>
<li>By increasing the default, you can improve failover time, but you may also increase load on your endpoints.</li>
<li>Minimum time in seconds is 60 (Pro), 15 (Business), and 10 (Enterprise).</li>
<li><strong>Timeout</strong> and <strong>Retries</strong>:</li>
<li>The health monitor request will return unhealthy if it exceeds the duration specified in <strong>Timeout</strong> (and exceeds this duration more times than the specified number of <strong>Retries</strong>).</li>
<li><strong>Expected Code(s)</strong>: The expected HTTP response codes listed individually (<code>200</code>, <code>302</code>) or as a range (for example, entering <code>2xx</code> would cover all response codes in the <code>200</code> range).</li>
<li><strong>Response Body</strong>:</li>
<li>Looks for a case-insensitive substring in the response body.</li>
<li>Make sure that the value is relatively static and within the first 10 KB of the HTML page.</li>
<li><strong>Simulate Zone</strong>:</li>
<li>It is recommended to use the same zone in which the Load Balancer exists.</li>
<li>Changes the egress zone settings of a health monitor request to ensure compatibility with features like <a href="/ssl/origin-configuration/authenticated-origin-pull/">Authenticated Origin Pulls (mTLS)</a>, <a href="/argo-smart-routing/">Argo Smart Routing</a>, <a href="/ssl/client-certificates/byo-ca/">Bring your own CA (mTLS)</a>, <a href="/smart-shield/configuration/dedicated-egress-ips/">Dedicated CDN Egress IPs</a>, and <a href="/speed/optimization/protocol/http2-to-origin/">HTTP/2 to Origin</a>.</li>
<li><strong>Follow Redirects</strong>:</li>
<li>Instead of reporting a <code>301</code> or <code>302</code> code as unhealthy, the health monitor request follows redirects to the final endpoint.</li>
<li><strong>Configure Request Header(s)</strong>:</li>
<li>Useful if your endpoints are expecting specific incoming headers.</li>
<li><strong>Header</strong>:</li>
<li>The HTTP request headers to send in the health monitor. It is recommended that you set a Host header by default. The User-Agent header cannot be overridden. This parameter is only valid for HTTP and HTTPS monitors.</li>
</ul>
<ol start="6">
<li>Select <strong>Save</strong>.</li>
</ol>
<aside class="nb-aside note">
<h3 class="nb-aside-title" id="body-9809-note">Note</h3>
<p>To increase confidence in pool status, you can also increase the <code>consecutive_up</code> and <code>consecutive_down</code> fields when <a href="/api/resources/load_balancers/subresources/monitors/methods/create/">creating a monitor with the API</a>.</p>
<p>To become healthy or unhealthy, monitored endpoints must pass this health monitor request the consecutive number of times specified in these parameters.</p>
</aside>
<p><strong>Prepare your servers</strong></p>
<p>Make sure that your firewall or web server does not block or rate limit your configured health monitors or requests associated with <a href="https://www.cloudflare.com/ips">Cloudflare IP addresses</a>.</p>
<p>Each health monitor has the HTTP user-agent of <code>&quot;Mozilla/5.0 (compatible; Cloudflare-Traffic-Manager/1.0; +https://www.cloudflare.com/traffic-manager/; pool-id: $poolid)&quot;</code>, where the <code>$poolid</code> is the first 16 characters of the <a href="/load-balancing/pools/">associated pool</a>.</p>
<aside class="nb-aside caution">
<p>If you know that your endpoint is healthy but Load Balancing is reporting it as unhealthy, refer to our <a href="/load-balancing/troubleshooting/load-balancing-faq/#why-is-my-endpoint-or-pool-considered-unhealthy">Monitor troubleshooting guide</a>.</p>
</aside>
