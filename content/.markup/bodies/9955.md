<ol>
<li>In the <a href="https://dash.cloudflare.com/">Cloudflare dashboard</a>, go to <strong>Zero Trust</strong> &gt; <strong>Team &amp; Resources</strong> &gt; <strong>Devices</strong> &gt; <strong>Device profiles</strong> &gt; <strong>Management</strong>.</li>
<li>In <strong>Device enrollment</strong> &gt; <strong>Device enrollment permissions</strong>, select <strong>Manage</strong>.</li>
<li>In the <strong>Policies</strong> tab, configure one or more <a href="/cloudflare-one/access-controls/policies/">Access policies</a> to define who can join their device. For example, you could allow all users with a company email address:</li>
</ol>

<th>Selector</th>
<th>Value</th>

</tr>

<aside class="nb-aside note">
<p>Device posture checks are not supported in device enrollment policies. The Cloudflare One Client (formerly WARP) can only perform posture checks after the device is enrolled.</p>
</aside>
<ol start="4">
<li>In the <strong>Login methods</strong> tab:</li>
</ol>
<p>a. Select the <a href="/cloudflare-one/integrations/identity-providers/">identity providers</a> users can authenticate with. If you have not integrated an identity provider, you can use the <a href="/cloudflare-one/integrations/identity-providers/one-time-pin/">one-time PIN</a>.</p>
<p>b. (Optional) If you plan to only allow access via a single IdP, turn on <strong>Apply instant authentication</strong>. End users will not be shown the Cloudflare Access login page. Instead, Cloudflare will redirect users directly to your SSO login event.</p>
<ol start="5">
<li>Select <strong>Save</strong>.</li>
</ol>

<ol>
<li>Add the following permission to your <a href="https://registry.terraform.io/providers/cloudflare/cloudflare/latest/docs/resources/api_token"><code>cloudflare_api_token</code></a>:</li>
</ol>
<ul>
<li><code>Access: Apps and Policies Write</code></li>
</ul>
<ol start="2">
<li>Create a reusable Access policy using the <a href="https://registry.terraform.io/providers/cloudflare/cloudflare/latest/docs/resources/zero_trust_access_policy"><code>cloudflare_zero_trust_access_policy</code></a> resource:</li>
</ol>
<pre><code class="language-tf">resource &quot;cloudflare_zero_trust_access_policy&quot; &quot;allow_company_emails&quot; {
	account_id   = var.cloudflare_account_id
	name         = &quot;Allow company emails&quot;
	decision     = &quot;allow&quot;
	include      = [
		{
			email_domain = {
				domain = &quot;@example.com&quot;
			}
		}
	]
}
</code></pre>
<ol start="3">
<li>Use the <a href="https://registry.terraform.io/providers/cloudflare/cloudflare/latest/docs/resources/zero_trust_access_application"><code>cloudflare_zero_trust_access_application</code></a> resource to create an application with type <code>warp</code>.</li>
</ol>
<pre><code class="language-tf">resource &quot;cloudflare_zero_trust_access_application&quot; &quot;device_enrollment&quot; {
	account_id       = var.cloudflare_account_id
	type             = &quot;warp&quot;
	name             = &quot;Warp device enrollment&quot;
	allowed_idps              = [cloudflare_zero_trust_access_identity_provider.microsoft_entra_id.id]
	auto_redirect_to_identity = true
	app_launcher_visible      = false
	policies = [
		{
			id = cloudflare_zero_trust_access_policy.allow_company_emails.id
			precedence = 1
		}
	]
}
</code></pre>
