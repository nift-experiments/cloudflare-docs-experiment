<h2 id="what-is-1-1-1-1">What is 1.1.1.1?</h2>
<p>1.1.1.1 is Cloudflare's fast and secure DNS resolver. When you visit a website like <code>cloudflare.com</code>, your computer needs to find the IP address of the server that hosts it. Your computer cannot perform this translation on its own, so it sends the request to a DNS resolver.</p>
<p>A DNS resolver looks up the IP address for a given domain name (for example, <code>2400:cb00:2048:1::c629:d7a2</code> for <code>cloudflare.com</code>) and returns it to the requesting device.</p>
<p>Your device is usually configured to use a DNS resolver chosen by your ISP (such as Comcast or AT&amp;T) for home or wireless Internet, or by your network administrator for office networks. You can change which DNS resolver your device uses at any time. Refer to <a href="/1.1.1.1/setup/">Set up 1.1.1.1</a> for instructions.</p>

<p>Visit <a href="https://one.one.one.one/help">1.1.1.1/help</a> to make sure your system is connected to 1.1.1.1 and that it is working.</p>
<h2 id="what-do-dns-resolvers-do">What do DNS resolvers do?</h2>
<p>DNS resolvers are like address books for the Internet. They translate domain names into IP addresses so that your browser knows which server to contact. A resolver does this by working backwards from the top of the domain name hierarchy.</p>
<p>Every resolver knows how to find the invisible <code>.</code> at the end of domain names (for example, <code>cloudflare.com.</code>). There are <a href="http://www.root-servers.org/">hundreds of root servers</a> all over the world that host the <code>.</code> file. Resolvers come preconfigured with the <a href="http://www.internic.net/domain/named.root">IP addresses of those root servers</a>. Cloudflare itself hosts <a href="http://www.internic.net/domain/root.zone">that file</a> on all of its servers around the world through a <a href="https://blog.cloudflare.com/f-root/">partnership with ISC</a>.</p>
<p>The resolver asks one of the root servers where to find the next link in the chain — the top-level domain (TLD), which is the domain ending like <code>.com</code> or <code>.org</code>. The root servers return the address of the TLD server responsible for that ending.</p>
<p>The resolver then asks the TLD server where to find the specific domain. For example, a resolver might ask <code>.com</code> where to find <code>cloudflare.com</code>. The TLD server responds with the address of the authoritative nameserver that holds the records for that domain.</p>
<p>Once the resolver has the final IP address, it returns the answer to the device that asked.</p>
<p>This whole system is called the <a href="https://www.cloudflare.com/learning/dns/what-is-dns/">Domain Name System (DNS)</a>. It includes the servers that host domain records (called <a href="https://www.cloudflare.com/learning/dns/dns-server-types/">authoritative DNS servers</a>) and the servers that look up those records on behalf of users (DNS resolvers).</p>
<h2 id="does-1-1-1-1-support-any">Does 1.1.1.1 support ANY?</h2>
<p>No. Cloudflare <a href="https://blog.cloudflare.com/deprecating-dns-any-meta-query-type/">stopped supporting the ANY query type</a> in 2015. The <code>ANY</code> query asks a DNS server to return all record types for a domain at once. In practice, <code>ANY</code> is more often used to amplify denial-of-service attacks than for legitimate purposes. When 1.1.1.1 receives an <code>ANY</code> query, it responds with <code>NOTIMPL</code> (not implemented).</p>
<h2 id="how-does-1-1-1-1-work-with-dnssec">How does 1.1.1.1 work with DNSSEC?</h2>
<p>DNSSEC (Domain Name System Security Extensions) lets domain owners cryptographically sign their DNS records. A DNSSEC-validating resolver checks these signatures to confirm that a DNS response is authentic and has not been modified.</p>
<p>1.1.1.1 is a DNSSEC-validating resolver. On every query, it sends the <code>DO</code> (DNSSEC OK) flag to signal that it can accept signed responses. If the authoritative server provides signed records, 1.1.1.1 validates the signatures before returning the answer. 1.1.1.1 supports the signature algorithms listed in <a href="/1.1.1.1/encryption/dnskey/">Supported DNSKEY signature algorithms</a>.</p>

<h2 id="what-is-purge-cache">What is Purge Cache?</h2>
<p>1.1.1.1's Purge Cache tool allows you to refresh 1.1.1.1's DNS cache for domain names. To refresh the cache for a domain name, visit the <a href="https://one.one.one.one/purge-cache/">Purge Cache page</a>.</p>
<h2 id="can-ips-used-by-1-1-1-1-be-allowlisted">Can IPs used by 1.1.1.1 be allowlisted?</h2>
<p>Authoritative DNS providers may want to allowlist the IP addresses that 1.1.1.1 uses when querying upstream nameservers. The full list of Cloudflare IP addresses is available at <a href="https://www.cloudflare.com/ips/">https://www.cloudflare.com/ips/</a>.</p>
