<p>Use <code>getScheduledTasks()</code> when code should create recurring Think turns or deterministic scheduled handlers. Think reconciles the declarations on startup, stores a durable one-shot schedule for the next occurrence, and re-arms the next occurrence after each run.</p>

<p>The DSL supports <code>every &lt;n&gt; minutes</code>, <code>every &lt;n&gt; hours</code>, <code>every day at HH:mm</code>, <code>every weekday at HH:mm</code>, and <code>every week on monday,wednesday at HH:mm</code>. Wall-clock schedules require either an inline timezone, a task <code>timezone</code>, or <code>getDefaultTimezone()</code>. If an alarm is late, Think runs the intended occurrence once and schedules the next future occurrence; it does not backfill missed runs.</p>
<p>Each task must define exactly one of <code>prompt</code> or <code>handler</code>. Prompt tasks create a durable submission with <a href="/agents/harnesses/think/programmatic-submissions/"><code>submitMessages()</code></a>. Handler tasks receive <code>{ taskId, scheduledFor, scheduledForDate, occurrenceKey, idempotencyKey, schedule, scheduleKind, timezone, metadata }</code> and are intended for app-owned work such as creating a Workflow run or writing a run ledger. Delivery is at-least-once; use <code>idempotencyKey</code> or <code>occurrenceKey</code> for your own durable idempotency.</p>
<p>Static declarations reconcile on startup. If <code>getScheduledTasks()</code> reads product-owned data that can change while the Durable Object is live, call <code>internal_reconcileScheduledTasks()</code> after updating that data. During reconciliation Think records the task row before creating the underlying Agent schedule, so a missing <code>schedule_id</code> is only a pending reconcile state and is repaired on the next reconcile. The task <code>retry</code> option retries the prompt or handler action before the failure is logged. The next occurrence is still scheduled after the action succeeds or exhausts its retries, so failed occurrences do not block future runs.</p>
<h2 id="when-to-use-a-workflow-instead">When to use a workflow instead</h2>
<p>For a recurring job whose steps matter — multiple deterministic steps, long waits, or human approval — use a handler task to create a <a href="/agents/harnesses/think/workflows/">Think Workflow</a> run. Keep simple recurring prompts as prompt tasks, and keep one-off background turns on <a href="/agents/harnesses/think/programmatic-submissions/"><code>submitMessages()</code></a>.</p>
