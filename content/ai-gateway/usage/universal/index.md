<p>The Universal Endpoint allows you to contact every provider through a single endpoint.</p>
<pre><code class="language-txt">https://gateway.ai.cloudflare.com/v1/{account_id}/{gateway_id}&#10;</code></pre>
<p>The payload expects an array of messages. Each message is an object with the following parameters:</p>
<ul>
<li><code>provider</code>: the name of the provider you would like to direct this message to. Can be OpenAI, workers-ai, or any of our supported providers.</li>
<li><code>endpoint</code>: the pathname of the provider API you are trying to reach. For example, on OpenAI it can be <code>chat/completions</code>, and for Workers AI this might be <a href="/workers-ai/models/llama-3.1-8b-instruct/"><code>@cf/meta/llama-3.1-8b-instruct</code></a>. Refer to the sections that are specific to <a href="/ai-gateway/usage/providers/">each provider</a>.</li>
<li><code>authorization</code>: the content of the Authorization HTTP Header that should be used when contacting this provider. This usually starts with <code>Token</code> or <code>Bearer</code>.</li>
<li><code>query</code>: the payload as the provider expects it in their official API.</li>
</ul>
<h2 id="curl-example">cURL example</h2>
<pre><code class="language-bash">curl https://gateway.ai.cloudflare.com/v1/{account_id}/{gateway_id} \&#10;  &#45;-header &#x27;Content-Type: application/json&#x27; \&#10;  &#45;-data &#x27;[&#10;  {&#10;    &quot;provider&quot;: &quot;workers-ai&quot;,&#10;    &quot;endpoint&quot;: &quot;@cf/meta/llama-3.1-8b-instruct&quot;,&#10;    &quot;headers&quot;: {&#10;      &quot;Authorization&quot;: &quot;Bearer {cloudflare_token}&quot;,&#10;      &quot;Content-Type&quot;: &quot;application/json&quot;&#10;    },&#10;    &quot;query&quot;: {&#10;      &quot;messages&quot;: [&#10;        {&#10;          &quot;role&quot;: &quot;system&quot;,&#10;          &quot;content&quot;: &quot;You are a friendly assistant&quot;&#10;        },&#10;        {&#10;          &quot;role&quot;: &quot;user&quot;,&#10;          &quot;content&quot;: &quot;What is Cloudflare?&quot;&#10;        }&#10;      ]&#10;    }&#10;  },&#10;  {&#10;    &quot;provider&quot;: &quot;openai&quot;,&#10;    &quot;endpoint&quot;: &quot;chat/completions&quot;,&#10;    &quot;headers&quot;: {&#10;      &quot;Authorization&quot;: &quot;Bearer {open_ai_token}&quot;,&#10;      &quot;Content-Type&quot;: &quot;application/json&quot;&#10;    },&#10;    &quot;query&quot;: {&#10;      &quot;model&quot;: &quot;gpt-4o-mini&quot;,&#10;      &quot;stream&quot;: true,&#10;      &quot;messages&quot;: [&#10;        {&#10;          &quot;role&quot;: &quot;user&quot;,&#10;          &quot;content&quot;: &quot;What is Cloudflare?&quot;&#10;        }&#10;      ]&#10;    }&#10;  }&#10;]&#x27;&#10;</code></pre>
<p>The above will send a request to Workers AI Inference API. If it fails, it will proceed to OpenAI. You can add as many fallbacks as you need by adding another object in the array.</p>
<h2 id="fallbacks">Fallbacks</h2>
<p>You can specify model or provider fallbacks to handle request failures and ensure reliability. The payload array defines the fallback sequence — if the first provider fails, the request falls to the next entry in the array. For more details, refer to <a href="/ai-gateway/configuration/fallbacks/">Fallbacks</a>.</p>
<p>By default, Cloudflare triggers your fallback if a model request returns an error. You can also configure <a href="#request-timeouts">request timeouts</a> to trigger fallbacks when a provider takes too long to respond.</p>
<h3 id="response-header-cf-aig-step">Response header (<code>cf-aig-step</code>)</h3>
<p>When using fallbacks, the response header <code>cf-aig-step</code> indicates which model successfully processed the request by returning the step number:</p>
<ul>
<li><code>cf-aig-step:0</code> — The first (primary) model was used successfully.</li>
<li><code>cf-aig-step:1</code> — The request fell back to the second model.</li>
<li><code>cf-aig-step:2</code> — The request fell back to the third model.</li>
<li>Subsequent steps — Each fallback increments the step number by 1.</li>
</ul>
<h2 id="request-timeouts">Request timeouts</h2>
<p>A request timeout triggers a fallback if a provider takes too long to respond.</p>
<p>Configure the timeout by setting a <code>requestTimeout</code> property (in milliseconds) within the provider-specific <code>config</code> object. Each provider can have a different <code>requestTimeout</code> value.</p>
<p>The timeout is based on when the first part of the response comes back. As long as the first part of the response returns within the specified timeframe — such as when streaming a response — your gateway will wait for the response.</p>

<h2 id="request-retries">Request retries</h2>
<p>The Universal Endpoint supports automatic retries for failed requests, with a maximum of five retry attempts. Retries are attempted before triggering any configured fallbacks.</p>
<p>Configure the retry settings with the following properties in the provider-specific <code>config</code>:</p>
<pre><code class="language-ts">config:{&#10;	maxAttempts?: number;&#10;	retryDelay?: number;&#10;	backoff?: &quot;constant&quot; | &quot;linear&quot; | &quot;exponential&quot;;&#10;}&#10;</code></pre>
<ul>
<li><code>maxAttempts</code>: Maximum number of retry attempts (up to 5).</li>
<li><code>retryDelay</code>: Delay before retrying, in milliseconds (maximum of 60 seconds).</li>
<li><code>backoff</code>: Backoff method — <code>constant</code>, <code>linear</code>, or <code>exponential</code>.</li>
</ul>
<p>On the final retry attempt, your gateway will wait until the request completes, regardless of how long it takes. Each provider can have different retry settings.</p>

<h2 id="header-configuration-hierarchy">Header configuration hierarchy</h2>
<p>The Universal Endpoint allows you to set fallback models or providers and customize headers for each provider or request. You can configure headers at three levels:</p>
<ol>
<li><strong>Provider level</strong>: Headers specific to a particular provider.</li>
<li><strong>Request level</strong>: Headers included in individual requests.</li>
<li><strong>Gateway settings</strong>: Default headers configured in your gateway dashboard.</li>
</ol>
<p>Since the same settings can be configured in multiple locations, AI Gateway applies a hierarchy to determine which configuration takes precedence:</p>
<ul>
<li><strong>Provider-level headers</strong> override all other configurations.</li>
<li><strong>Request-level headers</strong> are used if no provider-level headers are set.</li>
<li><strong>Gateway-level settings</strong> are used only if no headers are configured at the provider or request levels.</li>
</ul>
<p>This hierarchy ensures consistent behavior, prioritizing the most specific configurations. Use provider-level and request-level headers for fine-tuned control, and gateway settings for general defaults.</p>
<h3 id="hierarchy-example">Hierarchy example</h3>
<p>This example demonstrates how headers set at different levels impact caching behavior:</p>
<ul>
<li><strong>Request-level header</strong>: The <code>cf-aig-cache-ttl</code> is set to <code>3600</code> seconds, applying this caching duration to the request by default.</li>
<li><strong>Provider-level header</strong>: For the fallback provider (OpenAI), <code>cf-aig-cache-ttl</code> is explicitly set to <code>0</code> seconds, overriding the request-level header and disabling caching for responses when OpenAI is used as the provider.</li>
</ul>
<p>This shows how provider-level headers take precedence over request-level headers, allowing for granular control of caching behavior.</p>
<pre><code class="language-bash">curl https://gateway.ai.cloudflare.com/v1/{account_id}/{gateway_id} \&#10;  &#45;-header &#x27;Content-Type: application/json&#x27; \&#10;  &#45;-header &#x27;cf-aig-cache-ttl: 3600&#x27; \&#10;  &#45;-data &#x27;[&#10;    {&#10;      &quot;provider&quot;: &quot;workers-ai&quot;,&#10;      &quot;endpoint&quot;: &quot;@cf/meta/llama-3.1-8b-instruct&quot;,&#10;      &quot;headers&quot;: {&#10;        &quot;Authorization&quot;: &quot;Bearer {cloudflare_token}&quot;,&#10;        &quot;Content-Type&quot;: &quot;application/json&quot;&#10;      },&#10;      &quot;query&quot;: {&#10;        &quot;messages&quot;: [&#10;          {&#10;            &quot;role&quot;: &quot;system&quot;,&#10;            &quot;content&quot;: &quot;You are a friendly assistant&quot;&#10;          },&#10;          {&#10;            &quot;role&quot;: &quot;user&quot;,&#10;            &quot;content&quot;: &quot;What is Cloudflare?&quot;&#10;          }&#10;        ]&#10;      }&#10;    },&#10;    {&#10;      &quot;provider&quot;: &quot;openai&quot;,&#10;      &quot;endpoint&quot;: &quot;chat/completions&quot;,&#10;      &quot;headers&quot;: {&#10;        &quot;Authorization&quot;: &quot;Bearer {open_ai_token}&quot;,&#10;        &quot;Content-Type&quot;: &quot;application/json&quot;,&#10;        &quot;cf-aig-cache-ttl&quot;: &quot;0&quot;&#10;      },&#10;      &quot;query&quot;: {&#10;        &quot;model&quot;: &quot;gpt-4o-mini&quot;,&#10;        &quot;stream&quot;: true,&#10;        &quot;messages&quot;: [&#10;          {&#10;            &quot;role&quot;: &quot;user&quot;,&#10;            &quot;content&quot;: &quot;What is Cloudflare?&quot;&#10;          }&#10;        ]&#10;      }&#10;    }&#10;  ]&#x27;&#10;</code></pre>
