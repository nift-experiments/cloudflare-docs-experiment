<p>Many Cloudflare customers run software-as-a-service products with multiple customers. A big concern for such companies is understanding the cost of each customer, and understanding customer behaviour more widely.</p>
<p>Keeping data on every web request used by a customer can be expensive, as can attributing page views to customers. At Cloudflare we have solved this problem with the same in-house technologies now available to you through Analytics Engine.</p>
<h2 id="recording-data-on-usage">Recording data on usage</h2>
<p>Analytics Engine is designed for use with Cloudflare Workers. If you already use Cloudflare Workers to serve requests, you can start sending data into Analytics Engine in just a few lines of code:</p>
<pre><code class="language-javascript">  [...]&#10;&#10;  // This examples assumes you give a unique ID to each of your SaaS customers, and the Worker has&#10;  // assigned it to the variable named `customer_id`&#10;  const { pathname } = new URL(request.url);&#10;  env.USAGE_INDEXED_BY_CUSTOMER_ID.writeDataPoint({&#10;    &quot;indexes&quot;: [customer_id],&#10;    &quot;blobs&quot;: [pathname]&#10;  });&#10;</code></pre>
<p>SaaS customer activity often follows an exponential pattern: one customer may do 100 million requests per second, while another does 100 requests a day. If all data is sampled together, the usage of bigger customers can cause smaller customers data to be sampled to zero. Analytics Engine allows you to prevent that: in the example code above we supply the customer's unique ID as the index, causing Analytics Engine to sample your customers' individual activity.</p>
<h2 id="viewing-usage">Viewing usage</h2>
<p>You can start viewing customer data either using Grafana (for visualisations) or as JSON (for your own tools). Other areas of the Analytics Engine documentation explain this in-depth.</p>
<p>Look at customer usage over all endpoints:</p>
<pre><code class="language-sql">SELECT&#10;  index1 AS customer_id,&#10;  sum(_sample_interval) AS count&#10;FROM&#10;  usage_indexed_by_customer_id&#10;GROUP BY customer_id&#10;</code></pre>
<p>If run in Grafana, this query returns a graph summarising the usage of each customer. The <code>sum(_sample_interval)</code> accounts for the sampling - refer to other Analytics Engine documentation. This query gives you an answer to &quot;which customers are most active?&quot;</p>
<p>The example <code>writeDataPoint</code> call above writes an endpoint name. If you do that, you can break down customer activity by endpoint:</p>
<pre><code class="language-sql">SELECT&#10;  index1 AS customer_id,&#10;  blob1 AS request_endpoint,&#10;  sum(_sample_interval) AS count&#10;FROM&#10;  usage_indexed_by_customer_id&#10;GROUP BY customer_id, request_endpoint&#10;</code></pre>
<p>This can give you insights into what endpoints different customers are using. This can be useful for business purposes (for example, understanding customer needs) as well as for your engineers to see activity and behaviour (observability).</p>
<h2 id="billing-customers">Billing customers</h2>
<p>Analytics Engine can be used to bill customers based on a reliable approximation of usage. In order to get the best approximation, when generating bills we suggest executing one query per customer. This can result in less sampling than querying multiple customers at once.</p>
<pre><code class="language-sql">SELECT&#10;  index1 AS customer_id,&#10;  blob1 AS request_endpoint,&#10;  sum(_sample_interval) AS usage_count&#10;FROM&#10;  usage_indexed_by_customer_id&#10;WHERE&#10;  customer_id = &#x27;substitute_customer_id_here&#x27;&#10;  AND timestamp &gt;= toDateTime(&#x27;2023-03-01 00:00:00&#x27;)&#10;  AND timestamp &lt; toDateTime(&#x27;2023-04-01 00:00:00&#x27;)&#10;GROUP BY customer_id, request_endpoint&#10;</code></pre>
<p>Running this query once for each customer at the end of each month could give you the data to produce a bill. This is just an example: most likely you'll want to adjust this example to how you want to bill.</p>
<p>When producing a bill, most likely you will also want to provide the daily costs. The following query breaks down usage by day:</p>
<pre><code class="language-sql">SELECT&#10;  index1 AS customer_id,&#10;  toStartOfInterval(timestamp, INTERVAL &#x27;1&#x27; DAY) AS date,&#10;  blob1 AS request_endpoint,&#10;  sum(_sample_interval) AS request_count&#10;FROM&#10;  usage_indexed_by_customer_id&#10;WHERE&#10;  customer_id = &#x27;x&#x27;&#10;  AND timestamp &gt;= toDateTime(&#x27;2023-03-01 00:00:00&#x27;)&#10;  AND timestamp &lt; toDateTime(&#x27;2023-04-01 00:00:00&#x27;)&#10;GROUP BY customer_id, date, request_endpoint&#10;</code></pre>
<p>You will want to take the usage queries above, adapt them for how you charge customers, and make a backend system run those queries and calculate the customer charges based on the data returned.</p>
