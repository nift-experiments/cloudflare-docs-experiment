<p>In this example, we are going to use the GraphQL Analytics API to retrieve logs for an Access login event. These logs are particularly useful for determining why a user received a <code>403</code> Forbidden error, since they surface additional data beyond what is shown in the dashboard Access logs.</p>
<p>The following API call will request logs for a single Access login event and output the requested fields. The authentication request is identified by its <strong>Ray ID</strong>, which you can obtain from the <code>403</code> Forbidden page shown to the user.</p>
<p>You will need to insert your <code>&lt;CLOUDFLARE_ACCOUNT_TAG&gt;</code>, your API credentials in <code>&lt;API_TOKEN&gt;</code><sup><a href="#footnote-1">1</a></sup>, and substitute your own values for the following variables:</p>
<ul>
<li><code>rayID</code>: A unique identifier assigned to the authentication request.</li>
<li><code>datetimeStart</code>: The earliest event time to query (no earlier than September 16, 2022).</li>
<li><code>datetimeEnd</code>: The latest event time to query. Be sure to specify a time range that includes the login event you are querying.</li>
</ul>
<h2 id="api-call">API Call</h2>
<pre tabindex="0"><code class="language-bash">echo &#x27;{ &quot;query&quot;:&#10;  &quot;query accessLoginRequestsAdaptiveGroups($accountTag: string, $rayId: string, $datetimeStart: string, $datetimeEnd: string) {&#10;    viewer {&#10;      accounts(filter: {accountTag: $accountTag}) {&#10;        accessLoginRequestsAdaptiveGroups(limit: 100, filter: {datetime_geq: $datetimeStart, datetime_leq: $datetimeEnd, cfRayId: $rayId}, orderBy: [datetime_ASC]) {&#10;          dimensions {&#10;            datetime&#10;            isSuccessfulLogin&#10;            hasWarpEnabled&#10;            hasGatewayEnabled&#10;            hasExistingJWT&#10;            approvingPolicyId&#10;            cfRayId&#10;            ipAddress&#10;            userUuid&#10;            identityProvider&#10;            country&#10;            deviceId&#10;            mtlsStatus&#10;            mtlsCertSerialId&#10;            mtlsCommonName&#10;            serviceTokenId&#10;          }&#10;        }&#10;      }&#10;    }&#10;  }&quot;,&#10;  &quot;variables&quot;: {&#10;    &quot;accountTag&quot;: &quot;&lt;CLOUDFLARE_ACCOUNT_TAG&gt;&quot;,&#10;    &quot;rayId&quot;: &quot;74e4ac510dfdc44f&quot;,&#10;    &quot;datetimeStart&quot;: &quot;2022-09-20T14:36:38Z&quot;,&#10;    &quot;datetimeEnd&quot;: &quot;2022-09-22T14:36:38Z&quot;&#10;}&#10;}&#x27; | tr -d &#x27;\n&#x27; | curl --silent \&#10;https://api.cloudflare.com/client/v4/graphql \&#10;&#45;-header &quot;Authorization: Bearer &lt;API_TOKEN&gt;&quot; \&#10;&#45;-header &quot;Accept: application/json&quot; \&#10;&#45;-header &quot;Content-Type: application/json&quot; \&#10;&#45;-data @- | jq .&#10;</code></pre>

<p>You can compare the query results to your Access policies to understand why a user was blocked. For example, if your application requires a valid mTLS certificate, Access blocked the request shown above because <code>mtlsStatus</code>, <code>mtlsCommonName</code>, and <code>mtlsCertSerialId</code> are empty.</p>
