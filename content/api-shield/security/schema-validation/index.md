<div class="nb-glossary-definition"><p>The API schema defines which API requests are valid based on several request properties like target endpoint, path or query variable format, and HTTP method.</p></div>
<p>Schema Validation compares incoming requests with an uploaded OpenAPI schema. The uploaded schema supplies expected request structure for a Schema Profile.</p>
<p>After the uploaded profile becomes available, Cloudflare generates an <strong>always-on detection</strong>. Use <code>cf.schema_validation.uploaded.violated</code> to analyze and mitigate violations.</p>
<p>The detection does not mitigate traffic by itself. Review results in <a href="/waf/detections/application-profiles/analyze-profile-detections/">Profile Analysis</a> before <a href="/waf/detections/application-profiles/enforce-profiles-with-custom-rules/">enforcing the profile with Custom Rules</a>.</p>
<p>Schema Validation 2.0 is the current version. For previous-version reference, refer to <a href="/api-shield/reference/classic-schema-validation/">Configure Classic Schema Validation</a>.</p>

<h2 id="specifications">Specifications</h2>
<p>Cloudflare currently only accepts <a href="https://spec.openapis.org/oas/v3.0.3.html">OpenAPI v3 schemas</a>. The accepted file formats are YAML (<code>.yml</code> or <code>.yaml</code> file extension) and JSON (<code>.json</code> file extension).</p>
<p>OpenAPI schemas generated by different tooling may not be specific enough to import to Schema validation. Use a third-party tool such as <a href="https://swagger.io/tools/swagger-editor/">Swagger Editor</a> to ensure that schemas are compliant to the OpenAPI specification.</p>
<hr />
<h2 id="limitations">Limitations</h2>
<p>Cloudflare API Shield's Schema validation (importing) and <a href="/api-shield/management-and-monitoring/endpoint-management/schema-learning/">Schema learning</a> (exporting) capabilities rely on the <a href="https://spec.openapis.org/oas/v3.0.3">OpenAPI Specification (OAS) v3.0</a>.</p>
<p>This support includes all patch versions, such as OAS v3.0.x. OAS v3.1 is not supported, and there are no plans to expand support for OpenAPI 2.0.</p>

<h2 id="body-inspection">Body inspection</h2>
<p>API Shield has the ability to identify body specifications contained in uploaded schemas and validate that the data of incoming API requests adheres to them.</p>
<p>Schema validation currently supports validating requests with content-type <code>application/json</code>.</p>
<p>Within the OpenAPI specification, request body schemas are associated to media-ranges (such as <code>application/*</code>, <code>application/xml</code> or <code>application/json</code>).</p>
<p>When Cloudflare validates incoming requests, Cloudflare checks that the request's <code>content-type</code> matches the OpenAPI-specified media-range.</p>
<p>For example, when the OpenAPI file specifies <code>application/*</code> as part of the request body content map, Cloudflare will accept requests with the content-types <code>application/xml</code> and <code>application/json</code>. However, only <code>application/json</code> bodies will be validated with the supplied schema.</p>
<p>Cloudflare recommends keeping the media-ranges as tight as possible by setting them to an individual media-type. If you need to support multiple content-types on an API endpoint, you can utilize wildcard media-ranges.</p>
<p>Care should also be taken if the origin is configured to perform <a href="https://mimesniff.spec.whatwg.org/">MIME sniffing</a>. For example, when a request carrying a JSON body is deliberately carrying an <code>application/malicious</code> content-type and Cloudflare was configured to allow <code>application/*</code> media-ranges, the request would be passed along to the origin without validating the JSON body contents. However, an origin that ignores the content-type and either trial deserializes or sniffs the MIME type may deserialize the JSON body with a wrong assumption of having passed schema body validation.</p>
<p>As such, if you need to support <code>application/json</code> and <code>application/xml</code> on the same endpoint, you can use <code>application/*</code>. Cloudflare will validate the provided schema for request bodies where the content-type is set to <code>application/json</code>. Requests with content-type <code>application/xml</code> (and others matching <code>application/*</code>) will be let through. It is still strongly advised to disable content-type sniffing on your origin.</p>
<p>Cloudflare allows specifying the following media-ranges in the OpenAPI request body content map:</p>
<ul>
<li><code>*/*</code></li>
<li><code>application/*</code></li>
<li><code>application/json</code>.</li>
</ul>
<p>Media-ranges can also be configured to enforce a <code>charset</code> parameter. For this, Cloudflare only accepts the <code>charset</code> parameter with a static value of <code>utf-8</code> as part of the media-range specification and when configured, we will similarly require the request's content-type to carry this charset.</p>

<h2 id="troubleshooting">Troubleshooting</h2>
<p>This section addresses common issues you may encounter when using schema validation.</p>
<h3 id="resolve-a-oneof-constraint-violation">Resolve a <code>OneOf</code> constraint violation</h3>
<p>A <code>OneOf</code> constraint error means a request violated its uploaded profile. Its body did not match exactly one <a href="https://swagger.io/docs/specification/v3_0/data-models/oneof-anyof-allof-not/"><code>oneOf</code></a> option.</p>
<p>The request was invalid for one of two reasons:</p>
<ul>
<li><strong>Matches Zero</strong>: The payload did not correctly match any of the available subschemas. This is common when a discriminator field is set, but the payload is missing other required fields for that type.</li>
<li><strong>Matches Multiple</strong>: The payload was ambiguous and matched more than one subschema. This happens with generic schemas (for example, if a payload includes both an <code>email</code> and a <code>phone</code> field, it might match both an <code>email</code> and a <code>phone</code> schema definition, violating the &quot;exactly one&quot; rule).</li>
</ul>
<p>To fix this, compare the sampled request with its schema definition. The request may omit required fields or match conflicting types.</p>
