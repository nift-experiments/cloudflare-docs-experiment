<p>Our lightweight and open-source connector, <a href="https://github.com/cloudflare/cloudflared"><code>cloudflared</code></a>, was built to be highly available without any additional configuration requirements. When you run a tunnel, <code>cloudflared</code> establishes four outbound-only connections between the origin server and the Cloudflare network. These four connections are made to four different servers spread across at least two distinct data centers. This model ensures high availability and mitigates the risk of individual connection failures. This means in event a single connection, server, or data center goes offline, your resources will remain available.</p>
<h2 id="cloudflared-replicas"><code>cloudflared</code> replicas</h2>
<p>You can deploy additional instances of <code>cloudflared</code> for availability and failover. These instances are called replicas. Each replica establishes four new connections to Cloudflare, providing additional points of ingress to your origin. All replicas point to the same tunnel, so if a single host running <code>cloudflared</code> goes down, the remaining replicas continue to serve traffic.</p>

<p>Replicas do not support traffic steering (such as round-robin or hash-based routing). When a request arrives at Cloudflare, it is forwarded to the geographically closest replica. If that connection fails, Cloudflare retries with other replicas, but there is no guarantee about which one is chosen. If you need intelligent traffic distribution, use <a href="#cloudflare-load-balancers">Cloudflare Load Balancers</a> instead.</p>
<h3 id="when-to-use-cloudflared-replicas">When to use <code>cloudflared</code> replicas</h3>
<ul>
<li>To provide additional points of availability for a single tunnel.</li>
<li>To allocate failover nodes within your network.</li>
<li>To update the configuration of a tunnel <a href="/cloudflare-one/networks/connectors/cloudflare-tunnel/downloads/update-cloudflared/#update-with-multiple-cloudflared-instances">without downtime</a>.</li>
</ul>
<p>For setup instructions, refer to <a href="/cloudflare-one/networks/connectors/cloudflare-tunnel/configure-tunnels/tunnel-availability/deploy-replicas/">Deploy cloudflared replicas</a>.</p>
<h2 id="cloudflare-load-balancers">Cloudflare Load Balancers</h2>
<p><a href="/load-balancing/">Cloudflare Load Balancing</a> proactively steers traffic away from unhealthy origins and intelligently distributes the traffic load based on your choice of <a href="/load-balancing/understand-basics/traffic-steering/">steering algorithms</a>. Unlike <a href="#cloudflared-replicas"><code>cloudflared</code> replicas</a> which all use the same tunnel, a typical load balancer setup requires creating multiple tunnels. Most customers will create one tunnel per data center and one load balancer pool per tunnel.</p>

<h3 id="when-to-use-load-balancers">When to use load balancers</h3>
<ul>
<li>To intelligently steer traffic based on latency, geolocation, or other signals.</li>
<li>To implement failover logic if a tunnel reaches an inactive state.</li>
<li>To get a <a href="/notifications/notification-available/#load-balancing">health alert</a> when a tunnel reaches an inactive state.</li>
<li>To distribute traffic more evenly across your Cloudflare Tunnel-accessible origins or endpoints.</li>
</ul>
<p>For setup instructions, refer to <a href="/cloudflare-one/networks/connectors/cloudflare-tunnel/routing-to-tunnel/public-load-balancers/">Public load balancers</a> or <a href="/load-balancing/private-network/">Private Network Load Balancing</a> depending on your <a href="#types-of-load-balancers">use case</a>.</p>
<h3 id="types-of-load-balancers">Types of load balancers</h3>
<p>There are two types of load balancers that you can use with Cloudflare Tunnel endpoints:</p>
<ul>
<li><a href="/cloudflare-one/networks/connectors/cloudflare-tunnel/routing-to-tunnel/public-load-balancers/">Public load balancers</a> steer traffic from the Internet to applications published on a Cloudflare domain. Use this method if your service is served by Cloudflare Tunnel via a <a href="/cloudflare-one/networks/connectors/cloudflare-tunnel/get-started/create-remote-tunnel/#2a-publish-an-application">published application route</a>.</li>
<li><a href="/load-balancing/private-network/">Private load balancers</a> steer traffic from Cloudflare One Clients, Cloudflare WAN, and other <span class="nb-glossary-tooltip" title="on-ramp">on-ramps</span> to an internal IP on your private network. Use this method if your service is connected to Cloudflare Tunnel via a <a href="/cloudflare-one/networks/connectors/cloudflare-tunnel/private-net/cloudflared/connect-cidr/">CIDR route</a>.</li>
</ul>
