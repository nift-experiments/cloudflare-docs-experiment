<p>Review terminology for Cloudflare Tunnels.</p>
<h2 id="tunnel">Tunnel</h2>
<p>A tunnel is a secure, outbound-only pathway you can establish between your origin and Cloudflare's global network. Each tunnel you create will be assigned a <a href="#tunnel-name">name</a> and a <a href="#tunnel-uuid">UUID</a>.</p>
<h2 id="tunnel-uuid">Tunnel UUID</h2>
<p>A tunnel UUID is an alphanumeric, unique ID assigned to a tunnel. The tunnel UUID can be used whenever you need to reference a specific tunnel.</p>
<h2 id="tunnel-name">Tunnel name</h2>
<p>A tunnel name is a unique, user-friendly identifier that you choose for a tunnel. Since a tunnel can proxy traffic to multiple services, tunnel names do not need to be hostnames. For example, you can assign your tunnel a name that represents your application/network, a particular server, or the cloud environment where it runs.</p>
<h2 id="connector">Connector</h2>
<p>The connector, referred to as <code>cloudflared</code>, establishes connectivity from your origin server to the Cloudflare global network. Each <code>cloudflared</code> instance creates four long-lived connections to at least two distinct data centers within Cloudflare's global network. This built-in redundancy means that if an individual connection, server, or data center goes down, your origin remains available.</p>
<p><code>cloudflared</code> operates as a secure connector daemon rather than a local reverse proxy. It forwards requests directly to the configured local service without altering request URI paths or performing local load balancing.</p>
<h2 id="replica">Replica</h2>
<p>A replica is an additional instance of <code>cloudflared</code> running the same tunnel on a different host. You can create and configure a tunnel once, then run it through multiple replicas for redundancy. DNS records and Cloudflare Load Balancers continue to point to the tunnel (<code>UUID.cfargotunnel.com</code>), while Cloudflare distributes traffic across the available replicas. There is no guarantee about which replica will be chosen — Cloudflare routes to the geographically closest one. Replicas are typically deployed to keep a tunnel available if a host running <code>cloudflared</code> goes offline.</p>
<h2 id="remotely-managed-tunnel">Remotely-managed tunnel</h2>
<p>A remotely-managed tunnel is a <a href="#tunnel">tunnel</a> that was created in the Cloudflare dashboard under <strong>Networking</strong> &gt; <strong>Tunnels</strong>. Tunnel configuration is stored in Cloudflare, which allows you to manage the tunnel from the dashboard or using the <a href="/api/resources/zero_trust/subresources/tunnels/subresources/cloudflared/subresources/configurations/methods/get/">API</a>.</p>

<h2 id="locally-managed-tunnel">Locally-managed tunnel</h2>
<p>A locally-managed tunnel is a <a href="#tunnel">tunnel</a> that was created by running <code>cloudflared tunnel create &lt;NAME&gt;</code> on the command line. Tunnel configuration is stored in your local <a href="#default-cloudflared-directory">cloudflared directory</a>. For terminology specific to locally-managed tunnels, refer to the <a href="/cloudflare-one/networks/connectors/cloudflare-tunnel/do-more-with-tunnels/local-management/local-tunnel-terms/">Locally-managed tunnel glossary</a>.</p>
<h2 id="quick-tunnels">Quick tunnels</h2>
<p>Quick tunnels, when run, will generate a URL that consists of a random subdomain of the website <code>trycloudflare.com</code>, and point traffic to localhost on port <code>8080</code>. If you have a web service running at that address, users who visit the generated subdomain will be able to visit your web service through Cloudflare's network. Refer to <a href="/cloudflare-one/networks/connectors/cloudflare-tunnel/do-more-with-tunnels/trycloudflare/">TryCloudflare</a> for more information on how to run quick tunnels.</p>
<h2 id="virtual-networks">Virtual networks</h2>
<p>A <a href="/cloudflare-one/networks/connectors/cloudflare-tunnel/private-net/cloudflared/tunnel-virtual-networks/">virtual network</a> is a software abstraction that allows you to logically segregate resources on your private network. Virtual networks are especially useful for exposing resources which have overlapping IP routes. To connect to a resource, end users would select a virtual network in their Cloudflare One Client settings before entering the destination IP.</p>
