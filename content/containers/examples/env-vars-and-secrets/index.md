<p class="article-summary">Pass in environment variables and secrets to your container</p>
<p>Environment variables can be passed into a Container using the <code>envVars</code> field
in the <a href="/containers/reference/container-class/"><code>Container</code></a> class, or by setting manually when the Container starts.</p>
<p>Secrets can be passed into a Container by using <a href="/workers/configuration/secrets/">Worker Secrets</a>
or the <a href="/secrets-store/integrations/workers/">Secret Store</a>, then passing them into the Container
as environment variables.</p>
<p>KV values can be passed into a Container by using <a href="/kv/">Workers KV</a>, then reading
the values and passing them into the Container as environment variables.</p>
<p>These examples show the various ways to pass in secrets, KV values, and environment variables. In each, we will
be passing in:</p>
<ul>
<li>the variable <code>&quot;ENV_VAR&quot;</code> as a hard-coded environment variable</li>
<li>the secret <code>&quot;WORKER_SECRET&quot;</code> as a secret from Worker Secrets</li>
<li>the secret <code>&quot;SECRET_STORE_SECRET&quot;</code> as a secret from the Secret Store</li>
<li>the value <code>&quot;KV_VALUE&quot;</code> as a value from Workers KV</li>
</ul>
<p>In practice, you may just use one of the methods for storing secrets and data, but
we will show all methods for completeness.</p>

<p>Note that <code>&quot;WORKER_SECRET&quot;</code> does not need to be specified in the Wrangler config file, as it is automatically

<p>Also note that we did not configure anything specific for environment variables,

<h2 id="using-envvars-on-the-container-class">Using <code>envVars</code> on the Container class</h2>
<p>Now, let's pass the env vars and secrets to our container using the <code>envVars</code> field in the <code>Container</code> class:</p>
<pre tabindex="0"><code class="language-js">// https://developers.cloudflare.com/workers/runtime-apis/bindings/#importing-env-as-a-global&#10;import { env } from &quot;cloudflare:workers&quot;;&#10;export class MyContainer extends Container {&#10;	defaultPort = 8080;&#10;	sleepAfter = &quot;10s&quot;;&#10;	envVars = {&#10;		WORKER_SECRET: env.WORKER_SECRET,&#10;		ENV_VAR: env.ENV_VAR,&#10;		// we can&#x27;t set the secret store binding or KV values as defaults here, as getting their values is asynchronous&#10;	};&#10;}&#10;</code></pre>
<p>Every instance of this <code>Container</code> will now have these variables and secrets
set as environment variables when it launches.</p>
<h2 id="setting-environment-variables-per-instance">Setting environment variables per-instance</h2>
<p>But what if you want to set environment variables on a per-instance basis?</p>
<p>In this case, use the <code>startAndWaitForPorts()</code> method to pass in environment variables for each instance.</p>
<pre tabindex="0"><code class="language-js">export class MyContainer extends Container {&#10;	defaultPort = 8080;&#10;	sleepAfter = &quot;10s&quot;;&#10;}&#10;&#10;export default {&#10;	async fetch(request, env) {&#10;		if (new URL(request.url).pathname === &quot;/launch-instances&quot;) {&#10;			let instanceOne = env.MY_CONTAINER.getByName(&quot;foo&quot;);&#10;			let instanceTwo = env.MY_CONTAINER.getByName(&quot;bar&quot;);&#10;&#10;			// Each instance gets a different set of environment variables&#10;&#10;			await instanceOne.startAndWaitForPorts({&#10;				startOptions: {&#10;					envVars: {&#10;						ENV_VAR: env.ENV_VAR + &quot;foo&quot;,&#10;						WORKER_SECRET: env.WORKER_SECRET,&#10;						SECRET_STORE_SECRET: await env.SECRET_STORE.get(),&#10;						KV_VALUE: await env.DEMO_KV.get(&quot;KV_VALUE&quot;),&#10;					},&#10;				},&#10;			});&#10;&#10;			await instanceTwo.startAndWaitForPorts({&#10;				startOptions: {&#10;					envVars: {&#10;						ENV_VAR: env.ENV_VAR + &quot;bar&quot;,&#10;						WORKER_SECRET: env.WORKER_SECRET,&#10;						SECRET_STORE_SECRET: await env.SECRET_STORE.get(),&#10;						KV_VALUE: await env.DEMO_KV.get(&quot;KV_VALUE&quot;),&#10;						// You can also read different KV keys for different instances&#10;						INSTANCE_CONFIG: await env.DEMO_KV.get(&quot;instance-bar-config&quot;),&#10;					},&#10;				},&#10;			});&#10;			return new Response(&quot;Container instances launched&quot;);&#10;		}&#10;&#10;		// ... etc ...&#10;	},&#10;};&#10;</code></pre>
<h2 id="reading-kv-values-in-containers">Reading KV values in containers</h2>
<p>KV values are particularly useful for configuration data that changes infrequently but needs to be accessible to your containers. Since KV operations are asynchronous, you must read the values at runtime when starting containers.</p>
<p>Here are common patterns for using KV with containers:</p>
<h3 id="configuration-data">Configuration data</h3>
<pre tabindex="0"><code class="language-js">export default {&#10;	async fetch(request, env) {&#10;		if (new URL(request.url).pathname === &quot;/configure-container&quot;) {&#10;			// Read configuration from KV&#10;			const config = await env.DEMO_KV.get(&quot;container-config&quot;, &quot;json&quot;);&#10;			const apiUrl = await env.DEMO_KV.get(&quot;api-endpoint&quot;);&#10;&#10;			let container = env.MY_CONTAINER.getByName(&quot;configured&quot;);&#10;&#10;			await container.startAndWaitForPorts({&#10;				startOptions: {&#10;					envVars: {&#10;						CONFIG_JSON: JSON.stringify(config),&#10;						API_ENDPOINT: apiUrl,&#10;						DEPLOYMENT_ENV: await env.DEMO_KV.get(&quot;deployment-env&quot;),&#10;					},&#10;				},&#10;			});&#10;&#10;			return new Response(&quot;Container configured and launched&quot;);&#10;		}&#10;	},&#10;};&#10;</code></pre>
<h3 id="feature-flags">Feature flags</h3>
<pre tabindex="0"><code class="language-js">export default {&#10;	async fetch(request, env) {&#10;		if (new URL(request.url).pathname === &quot;/launch-with-features&quot;) {&#10;			// Read feature flags from KV&#10;			const featureFlags = {&#10;				ENABLE_FEATURE_A: await env.DEMO_KV.get(&quot;feature-a-enabled&quot;),&#10;				ENABLE_FEATURE_B: await env.DEMO_KV.get(&quot;feature-b-enabled&quot;),&#10;				DEBUG_MODE: await env.DEMO_KV.get(&quot;debug-enabled&quot;),&#10;			};&#10;&#10;			let container = env.MY_CONTAINER.getByName(&quot;features&quot;);&#10;&#10;			await container.startAndWaitForPorts({&#10;				startOptions: {&#10;					envVars: {&#10;						...featureFlags,&#10;						CONTAINER_VERSION: &quot;1.2.3&quot;,&#10;					},&#10;				},&#10;			});&#10;&#10;			return new Response(&quot;Container launched with feature flags&quot;);&#10;		}&#10;	},&#10;};&#10;</code></pre>
<h2 id="build-time-environment-variables">Build-time environment variables</h2>
<p>Finally, you can also set build-time environment variables that are only available when building the container image via the <code>image_vars</code> field in the Wrangler configuration.</p>
