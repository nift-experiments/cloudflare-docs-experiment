<p class="article-summary">Access the name from within a Durable Object using RpcTarget.</p>
<p>When working with Durable Objects, you will need to access the name that was used to create the Durable Object via <code>idFromName()</code>. This name is typically a meaningful identifier that represents what the Durable Object is responsible for (like a user ID, room name, or resource identifier).</p>
<p>However, there is a limitation in the current implementation: even though you can create a Durable Object with <code>.idFromName(name)</code>, you cannot directly access this name inside the Durable Object via <code>this.ctx.id.name</code>.</p>
<p>The <code>RpcTarget</code> pattern shown below offers a solution by creating a communication layer that automatically carries the name with each method call. This keeps your API clean while ensuring the Durable Object has access to its own name.</p>
<p>Based on your needs, you can either store the metadata temporarily in the <code>RpcTarget</code> class, or use Durable Object storage to persist the metadata for the lifetime of the object.</p>
<p>This example does not persist the Durable Object metadata. It demonstrates how to:</p>
<ol>
<li>Create an <code>RpcTarget</code> class</li>
<li>Set the Durable Object metadata (identifier in this example) in the <code>RpcTarget</code> class</li>
<li>Pass the metadata to a Durable Object method</li>
<li>Clean up the <code>RpcTarget</code> class after use</li>
</ol>
