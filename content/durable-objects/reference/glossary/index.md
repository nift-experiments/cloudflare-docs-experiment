<p>Review the definitions for terms used across Cloudflare's Durable Objects documentation.</p>
<table id="glossary-table"><thead><tr><th>Term</th><th>Definition</th></tr></thead><tbody><tr><td>alarm</td><td><p>A Durable Object alarm is a mechanism that allows you to schedule the Durable Object to be woken up at a time in the future.</p></td></tr><tr><td>bookmark</td><td><p>A bookmark is a mostly alphanumeric string like <code>0000007b-0000b26e-00001538-0c3e87bb37b3db5cc52eedb93cd3b96b</code> which represents a specific state of a SQLite database at a certain point in time. Bookmarks are designed to be lexically comparable: a bookmark representing an earlier point in time compares less than one representing a later point, using regular string comparison.</p></td></tr><tr><td>Durable Object</td><td><p>A Durable Object is an individual instance of a Durable Object class. A Durable Object is globally unique (referenced by ID), provides a global point of coordination for all methods/requests sent to it, and has private, persistent storage that is not shared with other Durable Objects within a namespace.</p></td></tr><tr><td>Durable Object class</td><td><p>The JavaScript class that defines the methods (RPC) and handlers (<code>fetch</code>, <code>alarm</code>) as part of your Durable Object, and/or an optional <code>constructor</code>. All Durable Objects within a single namespace share the same class definition.</p></td></tr><tr><td>Durable Objects</td><td><p>The product name, or the collective noun referring to more than one Durable Object.</p></td></tr><tr><td>input gate</td><td><p>While a storage operation is executing, no events shall be delivered to a Durable Object except for storage completion events. Any other events will be deferred until such a time as the object is no longer executing JavaScript code and is no longer waiting for any storage operations. We say that these events are waiting for the &quot;input gate&quot; to open.</p></td></tr><tr><td>instance</td><td><p>See &quot;Durable Object&quot;.</p></td></tr><tr><td>KV API</td><td><p>API methods part of Storage API that support persisting key-value data.</p></td></tr><tr><td>migration</td><td><p>A Durable Object migration is a mapping process from a class name to a runtime state.
Initiate a Durable Object migration when you need to:</p>
<ul>
<li>Create a new Durable Object class.</li>
<li>Rename a Durable Object class.</li>
<li>Delete a Durable Object class.</li>
<li>Transfer an existing Durable Objects class.</li>
</ul></td></tr><tr><td>namespace</td><td><p>A logical collection of Durable Objects that all share the same Durable Object (class) definition. A single namespace can have (tens of) millions of Durable Objects. Metrics are scoped per namespace.</p>
<ul>
<li>The binding name of the namespace (as it will be exposed inside Worker code) is defined in the Wrangler file under the <code>durable_objects.bindings.name</code> key. Note that the binding name may not uniquely identify a namespace within an account. Instead, each namespace has a unique namespace ID, which you can view from the Cloudflare dashboard.</li>
<li>You can instantiate a unique Durable Object within a namespace using <a href="/durable-objects/api/namespace/#methods">Durable Object namespace methods</a>.</li>
</ul></td></tr><tr><td>output gate</td><td><p>When a storage write operation is in progress, any new outgoing network messages will be held back until the write has completed. We say that these messages are waiting for the &quot;output gate&quot; to open. If the write ultimately fails, the outgoing network messages will be discarded and replaced with errors, while the Durable Object will be shut down and restarted from scratch.</p></td></tr><tr><td>SQL API</td><td><p>API methods part of Storage API that support SQL querying.</p></td></tr><tr><td>Storage API</td><td><p>The transactional and strongly consistent (serializable) <a href="/durable-objects/api/sqlite-storage-api/">Storage API</a> for persisting data within each Durable Object. State stored within a unique Durable Object is &quot;private&quot; to that Durable Object, and not accessible from other Durable Objects.</p>
<p>Storage API includes key-value (KV) API, SQL API, and point-in-time-recovery (PITR) API.</p>
<ul>
<li>Durable Object classes with the key-value storage backend can use KV API.</li>
<li>Durable Object classes with the SQLite storage backend can use KV API, SQL API, and PITR API.</li>
</ul></td></tr><tr><td>Storage Backend</td><td><p>By default, a Durable Object class can use Storage API that leverages a key-value storage backend. New Durable Object classes can opt-in to using a <a href="/durable-objects/best-practices/access-durable-objects-storage/#sqlite-storage-backend">SQLite storage backend</a>.</p></td></tr><tr><td>stub</td><td><p>An object that refers to a unique Durable Object within a namespace and allows you to call into that Durable Object via RPC methods or the <code>fetch</code> API. For example, <code>let stub = env.MY_DURABLE_OBJECT.get(id)</code></p></td></tr></tbody></table>
