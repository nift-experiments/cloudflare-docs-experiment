<p>When you run untrusted or AI-generated code in a dynamic Worker, you need to control what it can access on the network. You might want to:</p>
<ul>
<li>block all outbound access so the dynamic Worker can only use the <a href="/dynamic-workers/usage/bindings/">bindings</a> you give it</li>
<li>restrict outbound requests to a specific set of allowed destinations</li>
<li>inject credentials into outbound requests without exposing secrets to the dynamic Worker</li>
<li>log or audit every outbound request for observability</li>
</ul>
<p>The <code>globalOutbound</code> option in the <code>WorkerCode</code> object returned by <code>get()</code> or passed to <code>load()</code> controls all of this. It intercepts every <code>fetch()</code> and <code>connect()</code> call the dynamic Worker makes.</p>
<h2 id="block-all-outbound-access">Block all outbound access</h2>
<p>Set <code>globalOutbound</code> to <code>null</code> to fully isolate the dynamic Worker from the network:</p>
<pre tabindex="0"><code class="language-js">return {&#10;	mainModule: &quot;index.js&quot;,&#10;	modules: { &quot;index.js&quot;: code },&#10;	globalOutbound: null,&#10;};&#10;</code></pre>
<p>This causes any <code>fetch()</code> or <code>connect()</code> request from the dynamic Worker to throw an exception.</p>
<p>In this mode, you can still give the Dynamic Worker direct access to specific resources and services using <a href="/dynamic-workers/usage/bindings/">bindings</a>. This is the cleanest and most secure way to design your sandbox: block the Internet, then constructively offer specific capabilities via bindings.</p>
<p>That said, if you need to offer compatibility with existing HTTP client libraries running directly inside your Dynamic Worker sandbox, then blocking <code>fetch()</code> may be infeasible, and you may prefer to intercept requests instead.</p>
<h2 id="intercept-outbound-requests">Intercept outbound requests</h2>
<p>To intercept outbound requests, define a <code>WorkerEntrypoint</code> class in the loader Worker that acts as a gateway. Every <code>fetch()</code> and <code>connect()</code> call the dynamic Worker makes goes through this gateway instead of hitting the network directly. Pass the gateway to the dynamic Worker with <code>globalOutbound</code> and <code>ctx.exports</code>:</p>
<pre tabindex="0"><code class="language-js">import { WorkerEntrypoint } from &quot;cloudflare:workers&quot;;&#10;&#10;export class HttpGateway extends WorkerEntrypoint {&#10;	async fetch(request) {&#10;		// Every outbound fetch() from the dynamic Worker arrives here.&#10;		// Inspect, modify, block, or forward the request.&#10;		return fetch(request);&#10;	}&#10;}&#10;&#10;export default {&#10;	async fetch(request, env, ctx) {&#10;		const worker = env.LOADER.get(&quot;my-worker&quot;, async () =&gt; {&#10;			return {&#10;				compatibilityDate: &quot;$today&quot;,&#10;				mainModule: &quot;index.js&quot;,&#10;				modules: { &quot;index.js&quot;: code },&#10;&#10;				// Pass the gateway as a service binding.&#10;				// The dynamic Worker&#x27;s fetch() and connect() calls&#10;				// are routed through HttpGateway instead of going&#10;				// to the network directly.&#10;				globalOutbound: ctx.exports.HttpGateway(),&#10;			};&#10;		});&#10;&#10;		return worker.getEntrypoint().fetch(request);&#10;	},&#10;};&#10;</code></pre>
<p>From here, you can add any logic to the gateway, such as restricting destinations, injecting credentials, or logging requests.</p>
<h2 id="inject-credentials">Inject credentials</h2>
<p>A common pattern is attaching credentials to outbound requests so the dynamic Worker never sees the secret. Similar to <a href="/dynamic-workers/usage/bindings/#custom-bindings-with-dynamic-workers">custom bindings</a>, you can use <a href="/workers/runtime-apis/context/#props"><code>ctx.props</code></a> to pass per-tenant or per-request context to the gateway.</p>
<p>The dynamic Worker calls <code>fetch()</code> normally. <code>HttpGateway</code> intercepts the request, attaches the token from the loader Worker's environment, and forwards it. The dynamic Worker never has access to <code>API_TOKEN</code>.</p>
<pre tabindex="0"><code class="language-js">import { WorkerEntrypoint } from &quot;cloudflare:workers&quot;;&#10;&#10;export class HttpGateway extends WorkerEntrypoint {&#10;	async fetch(request) {&#10;		let url = new URL(request.url);&#10;		const headers = new Headers(request.headers);&#10;&#10;		// For requests to api.example.com, inject credentials.&#10;		if (url.hostname === &quot;api.example.com&quot;) {&#10;			headers.set(&quot;Authorization&quot;, `Bearer ${this.env.API_TOKEN}`);&#10;			headers.set(&quot;X-Tenant-Id&quot;, this.ctx.props.tenantId);&#10;		}&#10;&#10;		return fetch(request, { headers });&#10;	}&#10;}&#10;&#10;export default {&#10;	async fetch(request, env, ctx) {&#10;		const tenantId = getTenantFromRequest(request);&#10;&#10;		const worker = env.LOADER.get(`tenant:${tenantId}`, async () =&gt; {&#10;			return {&#10;				mainModule: &quot;index.js&quot;,&#10;				modules: {&#10;					&quot;index.js&quot;: `&#10;						export default {&#10;							async fetch() {&#10;								const resp = await fetch(&quot;https://api.example.com/data&quot;);&#10;								return new Response(await resp.text());&#10;							},&#10;						};&#10;					`,&#10;				},&#10;				globalOutbound: ctx.exports.HttpGateway({&#10;					props: { tenantId },&#10;				}),&#10;			};&#10;		});&#10;&#10;		return worker.getEntrypoint().fetch(request);&#10;	},&#10;};&#10;</code></pre>
