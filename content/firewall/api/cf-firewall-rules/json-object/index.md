<h2 id="avoiding-priority-conflicts">Avoiding priority conflicts</h2>
<p>Priority plays a key role in configuring firewall rules. With Cloudflare Filters, it is possible to construct conflicting rules such as:</p>
<ul>
<li>Allow requests from the office IP range, and</li>
<li>Block requests with a specific user agent.</li>
</ul>
<p>Requests from the office IP range using the user agent to block would trigger both rules, but we cannot both allow and block the request. To solve this problem, firewall rules follows a strict ordering depending on action and priority.</p>
<p>Cloudflare prioritizes rules in descending order, such that priority 1 is first and rules with no priority are last. For rules of equal priority, Cloudflare orders them by action according to their <a href="/firewall/cf-firewall-rules/actions/#supported-actions">order of precedence</a>. In the example above, if no priority is set, the rule <code>allow request from the office IP range</code> would apply because the <em>allow</em> action has a higher precedence than <em>block</em>.</p>
<p>To reduce the risk of unintended behavior, it is best to explicitly specify the desired priority for potentially conflicting rules.</p>
