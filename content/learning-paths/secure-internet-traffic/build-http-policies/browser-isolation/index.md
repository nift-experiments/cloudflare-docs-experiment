<div class="nb-glossary-definition"><p>Cloudflare Browser Isolation seamlessly executes active webpage content in a secure isolated browser to protect users from zero-day attacks, malware, and phishing.</p></div>
<p>Browser Isolation provides unique and transparent protection for your users using methods that surpass the capabilities of a traditional secure web gateway. This section focuses primarily on Browser Isolation for external services, assuming that most traffic from a device or a network is being forwarded to Cloudflare. For other applications of Browser Isolation, refer to the <a href="/learning-paths/clientless-access/concepts/">Deploy clientless access</a> guide.</p>
<p>As a note, Cloudflare's Browser Isolation technology was built to be used for 100% of your user's daily browsing. These recommendations do not suggest that you should limit or be cautious with your use of Browser Isolation, but instead help identify practical outcomes that balance technology with actualized security benefits.</p>
<h2 id="get-the-most-out-of-browser-isolation">Get the most out of Browser Isolation</h2>
<p>If your organization is interested in implementing Browser Isolation, there are a few methods that Cloudflare recommends exploring.</p>
<h3 id="block-copy-paste-and-upload-download-for-shadow-it">Block copy, paste, and upload/download for shadow IT</h3>
<p>As you have begun deploying Cloudflare Zero Trust, you may have started to visualize user traffic patterns using <a href="/cloudflare-one/insights/analytics/shadow-it-discovery/">Shadow IT Discovery</a>. This feature gives you visibility into detected SaaS applications that your users use. Administrators can categorize applications and services on the basis of proper organizational use. If you do not use Shadow IT Discovery and instead maintain a similar list manually or with other tools, you can port that data into a <a href="/learning-paths/secure-internet-traffic/understand-policies/create-list/">Zero Trust list</a>, update it via the API, and achieve the same outcomes.</p>
<p>You can control potential risk and shape user behavior without applying heavy-handed block policies by applying policies to isolate user traffic to applications that match your defined categories. You can then set additional parameters in the policy, such as the ability to restrict copy/paste and upload/download. Users can still access information in the tools -- if not use the tools to a lesser extent -- while you minimize the risk of data loss.</p>

<h3 id="isolate-all-gray-listed-traffic">Isolate all &quot;gray-listed&quot; traffic</h3>
<p>A common method for using Browser Isolation to protect against unknown or zero-day threats can dramatically enhance your security posture: Separate all HTTP traffic into known acceptable, known malicious, and unknown buckets. Once your sort your traffic, isolate everything in the unknown bucket.</p>
<p>You can accomplish this by creating the following policies:</p>
<ul>
<li>Explicit allow policies for all of your known applications and trusted websites using either Cloudflare application definitions or a list</li>
<li>Explicit block policies for all security risks, known malicious traffic, and against-acceptable-use intentional denies</li>
<li>A policy to isolate all other traffic in this middle</li>
</ul>
<p>In this context, if some traffic is unknown to your organization, Cloudflare will isolate it by default. Cloudflare will also prevent any malicious code from being executed client side, with additional controls available.</p>

<h3 id="vendor-chain-using-link-based-isolation">Vendor-chain using link-based isolation</h3>
<p>Many vendors that may exist within your security framework support URL manipulation. You can use URL manipulation as an on-ramp for Browser Isolation to add additional security controls.</p>
<p>For example, vendors like Zscaler and Proofpoint allow you to prepend links to URLs in a static or dynamic format. You can prepend the clientless isolation link generated for your Cloudflare account to derive additional security benefits for potentially risky clicks. This means that if you have traffic not sent through Cloudflare today (such as through another proxy), you can potentially prepend specific filtered requests with a link to automatically send the traffic to a Cloudflare isolated browser session without an endpoint agent installed.</p>
