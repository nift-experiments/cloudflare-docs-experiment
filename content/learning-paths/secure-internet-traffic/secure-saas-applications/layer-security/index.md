<p>Once you have decided on a model (or mixture of models) to secure front door access to your SaaS applications, you can address other common SaaS security areas of concern by layering multiple Cloudflare controls.</p>
<h2 id="device-posture-controls-for-managed-endpoints">Device posture controls for managed endpoints</h2>
<p>You can control endpoint access to your SaaS applications with device posture controls via either <a href="/learning-paths/secure-internet-traffic/secure-saas-applications/sso-front-door/">Access for SaaS</a> or <a href="/cloudflare-one/team-and-resources/devices/cloudflare-one-client/configure/settings/">WARP enrollment settings</a> in Zero Trust. Device posture can determine what constitutes a managed endpoint accessing a SaaS application.</p>
<p>You can also define what constitutes a healthy or semi-healthy managed endpoint and invoke step-up security policies based on potential security concerns. These controls are separate from the controls enacted for unmanaged endpoints.</p>
<h2 id="inline-security-for-unmanaged-endpoints">Inline security for unmanaged endpoints</h2>
<p>For unmanaged endpoints, you can deliver selective inline security like upload/download controls, HTTP filtering, and data loss detection/prevention policies in SaaS applications without the need to install agents.
You can deliver inline security through Browser Isolation, but it requires a <a href="/learning-paths/secure-internet-traffic/secure-saas-applications/sso-front-door/">front door control</a> (such as Access for SaaS) in order to be applied consistently.</p>
<h2 id="browser-isolation">Browser Isolation</h2>
<p>Cloudflare can deliver isolate SaaS apps in via either the Cloudflare One Client or static links with Clientless Web Isolation.</p>
<h3 id="cloudflare-one-client">Cloudflare One Client</h3>
<p>When your users' devices are enrolled with the Cloudflare One Client, Cloudflare will transparently isolate browser sessions. In other words, a user's browser will display <code>example.com</code>, but Cloudflare will isolate the traffic by rendering it in an isolated browser.</p>
<h3 id="clientless-web-isolation">Clientless Web Isolation</h3>
<p>With <a href="/cloudflare-one/remote-browser-isolation/setup/clientless-browser-isolation/">Clientless Web Isolation</a>, Cloudflare will append a static link to the web address. For example, a user's browser going to <code>example.com</code> in an isolated session will display <code>&lt;your-team-name&gt;.cloudflareaccess.com/browser/https://www.example.com</code>.</p>
<p>When Browser Isolation isolates traffic, Cloudflare can apply the security stack of TLS decryption, HTTP inspection, network inspection, DNS filtering, and DLP policy evaluation to the traffic in the request body. This provides a solution for securing unmanaged endpoint access to sensitive systems and can potentially upgrade traffic from users or services that may have otherwise been deemed as risky. Any method for Browser Isolation attaches the user to your dedicated egress IP addresses so you can apply policies across each method of access consistently.</p>
