<p>Middleware is reusable logic that can be run before your <a href="/pages/functions/api-reference/#onrequests"><code>onRequest</code></a> function. Middlewares are typically utility functions. Error handling, user authentication, and logging are typical candidates for middleware within an application.</p>
<h2 id="add-middleware">Add middleware</h2>
<p>Middleware is similar to standard Pages Functions but middleware is always defined in a <code>_middleware.js</code> file in your project's <code>/functions</code> directory. A <code>_middleware.js</code> file exports an <a href="/pages/functions/api-reference/#onrequests"><code>onRequest</code></a> function. The middleware will run on requests that match any Pages Functions in the same <code>/functions</code> directory, including subdirectories. For example, <code>functions/users/_middleware.js</code> file will match requests for <code>/functions/users/nevi</code>, <code>/functions/users/nevi/123</code> and <code>functions/users</code>.</p>
<p>If you want to run a middleware on your entire application, including in front of static files, create a <code>functions/_middleware.js</code> file.</p>
<p>In <code>_middleware.js</code> files, you may export an <code>onRequest</code> handler or any of its method-specific variants. The following is an example middleware which handles any errors thrown in your project's Pages Functions. This example uses the <code>next()</code> method available in the request handler's context object:</p>
<pre tabindex="0"><code class="language-js">export async function onRequest(context) {&#10;	try {&#10;		return await context.next();&#10;	} catch (err) {&#10;		return new Response(`${err.message}\n${err.stack}`, { status: 500 });&#10;	}&#10;}&#10;</code></pre>
<h2 id="chain-middleware">Chain middleware</h2>
<p>You can export an array of Pages Functions as your middleware handler. This allows you to chain together multiple middlewares that you want to run. In the following example, you can handle any errors generated from your project's Functions, and check if the user is authenticated:</p>
<pre tabindex="0"><code class="language-js">async function errorHandling(context) {&#10;	try {&#10;		return await context.next();&#10;	} catch (err) {&#10;		return new Response(`${err.message}\n${err.stack}`, { status: 500 });&#10;	}&#10;}&#10;&#10;function authentication(context) {&#10;	if (context.request.headers.get(&quot;x-email&quot;) != &quot;admin@example.com&quot;) {&#10;		return new Response(&quot;Unauthorized&quot;, { status: 403 });&#10;	}&#10;&#10;	return context.next();&#10;}&#10;&#10;export const onRequest = [errorHandling, authentication];&#10;</code></pre>
<p>In the above example, the <code>errorHandling</code> function will run first. It will capture any errors in the <code>authentication</code> function and any errors in any other subsequent Pages Functions.</p>
