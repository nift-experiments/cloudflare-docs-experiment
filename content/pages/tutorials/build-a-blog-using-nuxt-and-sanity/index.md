<p>In this tutorial, you will build a blog application using Nuxt.js and Sanity.io and deploy it on Cloudflare Pages. Nuxt.js is a powerful static site generator built on the front-end framework Vue.js. Sanity.io is a headless CMS tool built for managing your application's data without needing to maintain a database.</p>
<h2 id="prerequisites">Prerequisites</h2>
<ul>
<li>A recent version of <a href="https://docs.npmjs.com/getting-started">npm</a> on your computer</li>
<li>A <a href="https://www.sanity.io">Sanity.io</a> account</li>
</ul>
<h2 id="creating-a-new-sanity-project">Creating a new Sanity project</h2>
<p>To begin, create a new Sanity project, using one of Sanity's templates, the blog template. If you would like to customize your configuration, you can modify the schema or pick a custom template.</p>

<h3 id="setting-up-components">Setting up components</h3>
<p>With Sanity configured in your application, you can begin using it to render your blog. You will now set up a few pages to pull data from your Sanity API and render it. Note that if you are not familiar with Nuxt, it is recommended that you review the <a href="https://nuxtjs.org/guide">Nuxt guide</a>, which will teach you some fundamentals concepts around building applications with Nuxt.</p>
<h3 id="setting-up-the-index-page">Setting up the index page</h3>
<p>To begin, update the <code>index</code> page, which will be rendered when you visit the root route (<code>/</code>). In <code>pages/index.vue</code>:</p>
<pre tabindex="0"><code class="language-html">&lt;template&gt;&#10;	&lt;div class=&quot;container&quot;&gt;&#10;		&lt;div&gt;&#10;			&lt;h1 class=&quot;title&quot;&gt;My Blog&lt;/h1&gt;&#10;		&lt;/div&gt;&#10;		&lt;div class=&quot;posts&quot;&gt;&#10;			&lt;div v-for=&quot;post in posts&quot; :key=&quot;post._id&quot;&gt;&#10;				&lt;h2&gt;&lt;a v-bind:href=&quot;post.slug.current&quot; v-text=&quot;post.title&quot; /&gt;&lt;/h2&gt;&#10;			&lt;/div&gt;&#10;		&lt;/div&gt;&#10;	&lt;/div&gt;&#10;&lt;/template&gt;&#10;&#10;&lt;script&gt;&#10;	import { groq } from &quot;@nuxtjs/sanity&quot;;&#10;&#10;	export default {&#10;		async asyncData({ $sanity }) {&#10;			const query = groq`*[_type == &quot;post&quot;]`;&#10;			const posts = await $sanity.fetch(query);&#10;			return { posts };&#10;		},&#10;	};&#10;&lt;/script&gt;&#10;&#10;&lt;style&gt;&#10;	.container {&#10;		margin: 2rem;&#10;		min-height: 100vh;&#10;	}&#10;	.posts {&#10;		margin: 2rem 0;&#10;	}&#10;&lt;/style&gt;&#10;</code></pre>
<p>Vue SFCs, or <em>single file components</em>, are a unique Vue feature that allow you to combine JavaScript, HTML and CSS into a single file. In <code>pages/index.vue</code>, a <code>template</code> tag is provided, which represents the Vue component.</p>
<p>Importantly, <code>v-for</code> is used as a directive to tell Vue to render HTML for each <code>post</code> in an array of <code>posts</code>:</p>
<pre tabindex="0"><code class="language-html">&lt;div v-for=&quot;post in posts&quot; :key=&quot;post._id&quot;&gt;&#10;	&lt;h2&gt;&lt;a v-bind:href=&quot;post.slug.current&quot; v-text=&quot;post.title&quot; /&gt;&lt;/h2&gt;&#10;&lt;/div&gt;&#10;</code></pre>
<p>To populate that <code>posts</code> array, the <code>asyncData</code> function is used, which is provided by Nuxt to make asynchronous calls (for example, network requests) to populate the page's data.</p>
<p>The <code>$sanity</code> object is provided by the Nuxt and Sanity.js integration as a way to make requests to your Sanity dataset. By calling <code>$sanity.fetch</code>, and passing a query, you can retrieve specific data from our Sanity dataset, and return it as your page's data.</p>
<p>If you have not used Sanity before, you will probably be unfamiliar with GROQ, the GRaph Oriented Query language provided by Sanity for interfacing with your dataset. GROQ is a powerful language that allows you to tell the Sanity API what data you want out of your dataset. For our first query, you will tell Sanity to retrieve every object in the dataset with a <code>_type</code> value of <code>post</code>:</p>
<pre tabindex="0"><code class="language-js">const query = groq`*[_type == &quot;post&quot;]`;&#10;const posts = await $sanity.fetch(query);&#10;</code></pre>
<h3 id="setting-up-the-blog-post-page">Setting up the blog post page</h3>
<p>Our <code>index</code> page renders a link for each blog post in our dataset, using the <code>slug</code> value to set the URL for a blog post. For example, if I create a blog post called &quot;Hello World&quot; and set the slug to <code>hello-world</code>, my Nuxt application should be able to handle a request to the page <code>/hello-world</code>, and retrieve the corresponding blog post from Sanity.</p>
<p>Nuxt has built-in support for these kind of pages, by creating a new file in <code>pages</code> in the format <code>_slug.vue</code>. In the <code>asyncData</code> function of your page, you can then use the <code>params</code> argument to reference the slug:</p>
<pre tabindex="0"><code class="language-html">&lt;script&gt;&#10;	export default {&#10;		async asyncData({ params, $sanity }) {&#10;			console.log(params); // { slug: &quot;hello-world&quot; }&#10;		},&#10;	};&#10;&lt;/script&gt;&#10;</code></pre>
<p>With that in mind, you can build <code>pages/_slug.vue</code> to take the incoming <code>slug</code> value, make a query to Sanity to find the matching blog post, and render the <code>post</code> title for the blog post:</p>
<pre tabindex="0"><code class="language-html">&lt;template&gt;&#10;	&lt;div class=&quot;container&quot;&gt;&#10;		&lt;div v-if=&quot;post&quot;&gt;&#10;			&lt;h1 class=&quot;title&quot; v-text=&quot;post.title&quot; /&gt;&#10;			&lt;div class=&quot;content&quot;&gt;&lt;/div&gt;&#10;		&lt;/div&gt;&#10;		&lt;h4&gt;&lt;a href=&quot;/&quot;&gt;← Go back&lt;/a&gt;&lt;/h4&gt;&#10;	&lt;/div&gt;&#10;&lt;/template&gt;&#10;&#10;&lt;script&gt;&#10;	import { groq } from &quot;@nuxtjs/sanity&quot;;&#10;&#10;	export default {&#10;		async asyncData({ params, $sanity }) {&#10;			const query = groq`*[_type == &quot;post&quot; &amp;&amp; slug.current == &quot;${params.slug}&quot;][0]`;&#10;			const post = await $sanity.fetch(query);&#10;			return { post };&#10;		},&#10;	};&#10;&lt;/script&gt;&#10;&#10;&lt;style&gt;&#10;	.container {&#10;		margin: 2rem;&#10;		min-height: 100vh;&#10;	}&#10;&#10;	.content {&#10;		margin: 2rem 0;&#10;		max-width: 38rem;&#10;	}&#10;&#10;	p {&#10;		margin: 1rem 0;&#10;	}&#10;&lt;/style&gt;&#10;</code></pre>
<p>When visiting, for example, <code>/hello-world</code>, Nuxt will take the incoming slug <code>hello-world</code>, and make a GROQ query to Sanity for any objects with a <code>_type</code> of <code>post</code>, as well as a slug that matches the value <code>/hello-world</code>. From that set, you can get the first object in the array (using the array index operator you would find in JavaScript – <code>[0]</code>) and set it as <code>post</code> in your page data.</p>
<h3 id="rendering-content-for-a-blog-post">Rendering content for a blog post</h3>
<p>You have rendered the <code>post</code> title for our blog, but you are still missing the content of the blog post itself. To render this, import the <a href="https://github.com/rdunk/sanity-blocks-vue-component"><code>sanity-blocks-vue-component</code></a> package, which takes Sanity's <a href="https://www.sanity.io/docs/presenting-block-text">Portable Text</a> format and renders it as a Vue component.</p>
<p>First, install the npm package:</p>

<p>In <code>pages/_slug.vue</code>, you can now use the <code>&lt;block-content&gt;</code> component to render your content. This takes the format of a custom HTML component, and takes three arguments: <code>:blocks</code>, which indicates what to render (in our case, <code>child</code>), <code>v-for</code>, which accepts an iterator of where to get <code>child</code> from (in our case, <code>post.body</code>), and <code>:key</code>, which helps Vue <a href="https://vuejs.org/v2/guide/list.html#Maintaining-State">keep track of state rendering</a> by providing a unique value for each post: that is, the <code>_id</code> value.</p>

<h2 id="publishing-with-cloudflare-pages">Publishing with Cloudflare Pages</h2>
<p>Publishing your project with Cloudflare Pages is a two-step process: first, push your project to GitHub, and then in the Cloudflare Pages dashboard, set up a new project based on that GitHub repository. Pages will deploy a new version of your site each time you publish, and will even set up preview deployments whenever you open a new pull request.</p>
<p>To push your project to GitHub, <a href="https://repo.new">create a new repository</a>, and follow the instructions to push your local Git repository to GitHub.</p>
<p>After you have pushed your project to GitHub, deploy your site to Pages:</p>
<ol>
<li>In the Cloudflare dashboard, go to the <strong>Workers &amp; Pages</strong> page.</li>
</ol>
<div class="nb-dash-button"></div>
2. Select **Create application** > **Pages** > **Import an existing Git repository**.
3. Select the new GitHub repository that you created and select **Begin setup**.
4. In the **Set up builds and deployments** section, under **Build settings** > **Framework preset**, choose _Nuxt_. Pages will set the correct fields for you automatically.
<p>When your site has been deployed, you will receive a unique URL to view it in production.</p>
<p>In order to automatically deploy your project when your Sanity.io data changes, you can use <a href="/pages/configuration/deploy-hooks/">Deploy Hooks</a>. Create a new Deploy Hook URL in your <strong>Pages project</strong> &gt; <strong>Settings</strong>. In your Sanity project's Settings page, find the <strong>Webhooks</strong> section, and add the Deploy Hook URL, as seen below:</p>
<p><img src="/assets/upstream/images/pages/tutorials/hooks.png" alt="Adding a Deploy Hook URL on Sanity's dashboard" /></p>
<p>Now, when you make a change to your Sanity.io dataset, Sanity will make a request to your unique Deploy Hook URL, which will begin a new Cloudflare Pages deploy. By doing this, your Pages application will remain up-to-date as you add new blog posts, or edit existing ones.</p>
