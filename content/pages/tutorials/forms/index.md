<p>In this tutorial, you will create a simple <code>&lt;form&gt;</code> using plain HTML and CSS and deploy it to Cloudflare Pages. While doing so, you will learn about some of the HTML form attributes and how to collect submitted data within a Worker.</p>

<p>This tutorial will make heavy use of Cloudflare Pages and <a href="/pages/functions/">its Workers integration</a>. Refer to the <a href="/pages/get-started/">Get started guide</a> guide to familiarize yourself with the platform.</p>
<h2 id="overview">Overview</h2>
<p>On the web, forms are a common point of interaction between the user and the web document. They allow a user to enter data and, generally, submit their data to a server. A form is comprised of at least one form input, which can vary from text fields to dropdowns to checkboxes and more.</p>
<p>Each input should be named – using the <a href="https://developer.mozilla.org/en-US/docs/Web/HTML/Element/input#attr-name"><code>name</code></a> attribute – so that the input's value has an identifiable name when received by the server. Additionally, with the advancement of HTML5, form elements may declare additional attributes to opt into automatic form validation. The available validations vary by input type; for example, a text input that accepts emails (via <a href="https://developer.mozilla.org/en-US/docs/Web/HTML/Element/input#input_types"><code>type=email</code></a>) can ensure that the value looks like a valid email address, a number input (via <code>type=number</code>) will only accept integers or decimal values (if allowed), and generic text inputs can define a custom <a href="https://developer.mozilla.org/en-US/docs/Web/HTML/Element/input#attr-pattern"><code>pattern</code></a> to allow. However, all inputs can declare whether or not a value is <a href="https://developer.mozilla.org/en-US/docs/Web/HTML/Element/input#attr-required"><code>required</code></a>.</p>
<p>Below is an example HTML5 form with a few inputs and their validation rules defined:</p>
<pre tabindex="0"><code class="language-html">&lt;form method=&quot;POST&quot; action=&quot;/api/submit&quot;&gt;&#10;	&lt;input type=&quot;text&quot; name=&quot;fullname&quot; pattern=&quot;[A-Za-z]+&quot; required /&gt;&#10;	&lt;input type=&quot;email&quot; name=&quot;email&quot; required /&gt;&#10;	&lt;input type=&quot;number&quot; name=&quot;age&quot; min=&quot;18&quot; required /&gt;&#10;&#10;	&lt;button type=&quot;submit&quot;&gt;Submit&lt;/button&gt;&#10;&lt;/form&gt;&#10;</code></pre>
<p>If an HTML5 form has validation rules defined, browsers will automatically check all rules when the user attempts to submit the form. Should there be any errors, the submission is prevented and the browser displays the error message(s) to the user for correction. The <code>&lt;form&gt;</code> will only <code>POST</code> data to the <code>/submit</code> endpoint when there are no outstanding validation errors. This entire process is native to HTML5 and only requires the appropriate form and input attributes to exist — no JavaScript is required.</p>
<p>Form elements may also have a <a href="https://developer.mozilla.org/en-US/docs/Web/HTML/Element/label"><code>&lt;label&gt;</code></a> element associated with them, allowing you to clearly describe each input. This is great for visual clarity, of course, but it also allows for more accessible user experiences since the HTML markup is more well-defined. Assistive technologies directly benefit from this; for example, screen readers can announce which <code>&lt;input&gt;</code> is focused. And when a <code>&lt;label&gt;</code> is clicked, its assigned form input is focused instead, increasing the activation area for the input.</p>
<p>To enable this, you must create a <code>&lt;label&gt;</code> element for each input and assign each <code>&lt;input&gt;</code> element and unique <code>id</code> attribute value. The <code>&lt;label&gt;</code> must also possess a <a href="https://developer.mozilla.org/en-US/docs/Web/HTML/Element/label#attr-for"><code>for</code></a> attribute that reflects its input's unique <code>id</code> value. Amending the previous snippet should produce the following:</p>
<pre tabindex="0"><code class="language-html">&lt;form method=&quot;POST&quot; action=&quot;/api/submit&quot;&gt;&#10;	&lt;label for=&quot;i-fullname&quot;&gt;Full Name&lt;/label&gt;&#10;	&lt;input&#10;		id=&quot;i-fullname&quot;&#10;		type=&quot;text&quot;&#10;		name=&quot;fullname&quot;&#10;		pattern=&quot;[A-Za-z]+&quot;&#10;		required&#10;	/&gt;&#10;&#10;	&lt;label for=&quot;i-email&quot;&gt;Email Address&lt;/label&gt;&#10;	&lt;input id=&quot;i-email&quot; type=&quot;email&quot; name=&quot;email&quot; required /&gt;&#10;&#10;	&lt;label for=&quot;i-age&quot;&gt;Your Age&lt;/label&gt;&#10;	&lt;input id=&quot;i-age&quot; type=&quot;number&quot; name=&quot;age&quot; min=&quot;18&quot; required /&gt;&#10;&#10;	&lt;button type=&quot;submit&quot;&gt;Submit&lt;/button&gt;&#10;&lt;/form&gt;&#10;</code></pre>

<p>When this <code>&lt;form&gt;</code> is submitted with valid data, its data contents are sent to the server. You may customize how and where this data is sent by declaring attributes on the form itself. If you do not provide these details, the <code>&lt;form&gt;</code> will GET the data to the current URL address, which is rarely the desired behavior. To fix this, at minimum, you need to define an <a href="https://developer.mozilla.org/en-US/docs/Web/HTML/Element/form#attr-action"><code>action</code></a> attribute with the target URL address, but declaring a <a href="https://developer.mozilla.org/en-US/docs/Web/HTML/Element/form#attr-method"><code>method</code></a> is often recommended too, even if you are redeclaring the default <code>GET</code> value.</p>
<p>By default, HTML forms send their contents in the <code>application/x-www-form-urlencoded</code> MIME type. This value will be reflected in the <code>Content-Type</code> HTTP header, which the receiving server must read to determine how to parse the data contents. You may customize the MIME type through the <a href="https://developer.mozilla.org/en-US/docs/Web/HTML/Element/form#attr-enctype"><code>enctype</code></a> attribute. For example, to accept files (via <code>type=file</code>), you must change the <code>enctype</code> to the <code>multipart/form-data</code> value:</p>
<pre tabindex="0"><code class="language-html">&lt;form method=&quot;POST&quot; action=&quot;/api/submit&quot; enctype=&quot;multipart/form-data&quot;&gt;&#10;	&lt;label for=&quot;i-fullname&quot;&gt;Full Name&lt;/label&gt;&#10;	&lt;input&#10;		id=&quot;i-fullname&quot;&#10;		type=&quot;text&quot;&#10;		name=&quot;fullname&quot;&#10;		pattern=&quot;[A-Za-z]+&quot;&#10;		required&#10;	/&gt;&#10;&#10;	&lt;label for=&quot;i-email&quot;&gt;Email Address&lt;/label&gt;&#10;	&lt;input id=&quot;i-email&quot; type=&quot;email&quot; name=&quot;email&quot; required /&gt;&#10;&#10;	&lt;label for=&quot;i-age&quot;&gt;Your Age&lt;/label&gt;&#10;	&lt;input id=&quot;i-age&quot; type=&quot;number&quot; name=&quot;age&quot; min=&quot;18&quot; required /&gt;&#10;&#10;	&lt;label for=&quot;i-avatar&quot;&gt;Profile Picture&lt;/label&gt;&#10;	&lt;input id=&quot;i-avatar&quot; type=&quot;file&quot; name=&quot;avatar&quot; required /&gt;&#10;&#10;	&lt;button type=&quot;submit&quot;&gt;Submit&lt;/button&gt;&#10;&lt;/form&gt;&#10;</code></pre>
<p>Because the <code>enctype</code> changed, the browser changes how it sends data to the server too. The <code>Content-Type</code> HTTP header will reflect the new approach and the HTTP request's body will conform to the new MIME type. The receiving server must accommodate the new format and adjust its request parsing method.</p>

<h3 id="worker">Worker</h3>
<p>The HTML form is complete and ready for deployment. When the user submits this form, all data will be sent in a <code>POST</code> request to the <code>/api/submit</code> URL. This is due to the form's <code>method</code> and <code>action</code> attributes. However, there is currently no request handler at the <code>/api/submit</code> address. You will now create it.</p>
<p>Cloudflare Pages offers a <a href="/pages/functions/">Functions</a> feature, which allows you to define and deploy Workers for dynamic behaviors.</p>
<p>Functions are linked to the <code>functions</code> directory and conveniently construct URL request handlers in relation to the <code>functions</code> file structure. For example, the <code>functions/about.js</code> file will map to the <code>/about</code> URL and <code>functions/hello/[name].js</code> will handle the <code>/hello/:name</code> URL pattern, where <code>:name</code> is any matching URL segment. Refer to the <a href="/pages/functions/routing/">Functions routing</a> documentation for more information.</p>
<p>To define a handler for <code>/api/submit</code>, you must create a <code>functions/api/submit.js</code> file. This means that your <code>functions</code> and <code>public</code> directories should be siblings, with a total project structure similar to the following:</p>
<pre tabindex="0"><code class="language-txt">├── functions&#10;│   └── api&#10;│       └── submit.js&#10;└── public&#10;    └── index.html&#10;</code></pre>
<p>The <code>&lt;form&gt;</code> will send <code>POST</code> requests, which means that the <code>functions/api/submit.js</code> file needs to export an <code>onRequestPost</code> handler:</p>
<pre tabindex="0"><code class="language-js">/**&#10; &#42; POST /api/submit&#10; &#42;/&#10;export async function onRequestPost(context) {&#10;	// TODO: Handle the form submission&#10;}&#10;</code></pre>
<p>The <code>context</code> parameter is an object filled with several values of potential interest. For this example, you only need the <a href="/workers/runtime-apis/request/"><code>Request</code></a> object, which can be accessed through the <code>context.request</code> key.</p>
<p>As mentioned, a <code>&lt;form&gt;</code> defaults to the <code>application/x-www-form-urlencoded</code> MIME type when submitting. And, for more advanced scenarios, the <code>enctype=&quot;multipart/form-data&quot;</code> attribute is needed. Luckily, both MIME types can be parsed and treated as <a href="https://developer.mozilla.org/en-US/docs/Web/API/FormData"><code>FormData</code></a>. This means that with Workers – which includes Pages Functions – you are able to use the native <a href="https://developer.mozilla.org/en-US/docs/Web/API/Request/formData"><code>Request.formData</code></a> parser.</p>
<p>For illustrative purposes, the example application's form handler will reply with all values it received. A <code>Response</code> must always be returned by the handler, too:</p>
<pre tabindex="0"><code class="language-js">/**&#10; &#42; POST /api/submit&#10; &#42;/&#10;export async function onRequestPost(context) {&#10;	try {&#10;		let input = await context.request.formData();&#10;		let pretty = JSON.stringify([...input], null, 2);&#10;		return new Response(pretty, {&#10;			headers: {&#10;				&quot;Content-Type&quot;: &quot;application/json;charset=utf-8&quot;,&#10;			},&#10;		});&#10;	} catch (err) {&#10;		return new Response(&quot;Error parsing JSON content&quot;, { status: 400 });&#10;	}&#10;}&#10;</code></pre>
<p>With this handler in place, the example is now fully functional. When a submission is received, the Worker will reply with a JSON list of the <code>FormData</code> key-value pairs.</p>
<p>However, if you want to reply with a JSON object instead of the key-value pairs (an Array of Arrays), then you must do so manually. Recently, JavaScript added the <a href="https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Object/fromEntries"><code>Object.fromEntries</code></a> utility. This works well in some cases; however, the example <code>&lt;form&gt;</code> includes a <code>movies</code> checklist that allows for multiple values. If using <code>Object.fromEntries</code>, the generated object would only keep one of the <code>movies</code> values, discarding the rest. To avoid this, you must write your own <code>FormData</code> to <code>Object</code> utility instead:</p>
<pre tabindex="0"><code class="language-js">/**&#10; &#42; POST /api/submit&#10; &#42;/&#10;export async function onRequestPost(context) {&#10;	try {&#10;		let input = await context.request.formData();&#10;&#10;		// Convert FormData to JSON&#10;		// NOTE: Allows multiple values per key&#10;		let output = {};&#10;		for (let [key, value] of input) {&#10;			let tmp = output[key];&#10;			if (tmp === undefined) {&#10;				output[key] = value;&#10;			} else {&#10;				output[key] = [].concat(tmp, value);&#10;			}&#10;		}&#10;&#10;		let pretty = JSON.stringify(output, null, 2);&#10;		return new Response(pretty, {&#10;			headers: {&#10;				&quot;Content-Type&quot;: &quot;application/json;charset=utf-8&quot;,&#10;			},&#10;		});&#10;	} catch (err) {&#10;		return new Response(&quot;Error parsing JSON content&quot;, { status: 400 });&#10;	}&#10;}&#10;</code></pre>
<p>The final snippet (above) allows the Worker to retain all values, returning a JSON response with an accurate representation of the <code>&lt;form&gt;</code> submission.</p>
