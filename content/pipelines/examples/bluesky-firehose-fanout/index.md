<p class="article-summary">Consume the Bluesky Jetstream firehose in a Durable Object, ingest it into a single Pipelines stream, and use one pipeline with multiple SQL statements to route events into separate R2 Data Catalog tables by type.</p>
<p>In this example, you will consume the public <a href="https://github.com/bluesky-social/jetstream">Bluesky Jetstream</a> firehose, a live WebSocket stream of every post, like, repost, follow, and block on the network, and land it in <a href="/r2-data-catalog/">R2 Data Catalog</a> as queryable Apache Iceberg tables.</p>
<p>You will learn a core Pipelines pattern: send every event to one stream, then use a single pipeline with multiple SQL statements to route (&quot;fan out&quot;) that stream into several destination tables, one per event type, without running a separate pipeline for each.</p>
<pre tabindex="0"><code class="language-mermaid">flowchart TD&#10;    A[Bluesky Jetstream WebSocket] --&gt; B[Durable Object]&#10;    B --&gt;|send| C[bsky_events_stream]&#10;    C --&gt; D[bsky_pipeline]&#10;    D --&gt; E[bsky_post]&#10;    D --&gt; F[bsky_like]&#10;    D --&gt; G[bsky_repost]&#10;    D --&gt; H[bsky_follow]&#10;    D --&gt; I[bsky_block]&#10;</code></pre>

<p>Now create one pipeline whose SQL contains multiple <code>INSERT</code> statements, one per route. Each statement filters the stream by <code>event_type</code> and projects only the columns that matter for its table.</p>
<p>Create a <code>fanout.sql</code> file:</p>
<pre tabindex="0"><code class="language-sql">INSERT INTO bsky_post_sink&#10;  SELECT event_id, did, operation, event_time, created_at, text, langs&#10;  FROM bsky_events_stream WHERE event_type = &#x27;post&#x27;;&#10;&#10;INSERT INTO bsky_like_sink&#10;  SELECT event_id, did, operation, event_time, created_at, subject_uri&#10;  FROM bsky_events_stream WHERE event_type = &#x27;like&#x27;;&#10;&#10;INSERT INTO bsky_repost_sink&#10;  SELECT event_id, did, operation, event_time, created_at, subject_uri&#10;  FROM bsky_events_stream WHERE event_type = &#x27;repost&#x27;;&#10;&#10;INSERT INTO bsky_follow_sink&#10;  SELECT event_id, did, operation, event_time, created_at, subject_did&#10;  FROM bsky_events_stream WHERE event_type = &#x27;follow&#x27;;&#10;&#10;INSERT INTO bsky_block_sink&#10;  SELECT event_id, did, operation, event_time, created_at, subject_did&#10;  FROM bsky_events_stream WHERE event_type = &#x27;block&#x27;;&#10;</code></pre>

<h2 id="conclusion">Conclusion</h2>
<p>You consumed a high-velocity public WebSocket firehose with a Durable Object, ingested it into one Pipelines stream, and used a single pipeline with multiple SQL statements to fan the stream out into five Iceberg tables by event type.</p>
<p>This one-stream-to-many-tables pattern generalizes to any tagged event source: clickstreams (by <code>event_type</code>), logs (by <code>service</code> or <code>status</code>), or IoT telemetry (by <code>device_class</code>). To extend it, add a sink and a matching <code>INSERT ... WHERE</code> statement.</p>
