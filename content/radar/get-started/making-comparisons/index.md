<p>When comparing time series, across locations/time ranges/etc., in endpoints that normalize values using <a href="/radar/concepts/normalization">min-max</a>, you must do so in the same request. This is done by asking for multiple series. All values will then be normalized using the same minimum and maximum value and can safely be compared against each other.</p>
<p><a href="/radar/investigate/netflows">NetFlows</a> values are normalized using <a href="/radar/concepts/normalization">min0-max</a>, so we will use it as an example. Refer to <a href="/api/resources/radar/subresources/netflows/methods/timeseries/">Get NetFlow time series</a> for more information.</p>
<h2 id="compare-locations">Compare locations</h2>
<p>In the following example, we will compare the traffic change across two different locations — United States and Portugal. The example will use <a href="https://en.wikipedia.org/wiki/ISO_3166-1_alpha-2#Officially_assigned_code_elements">alpha-2 codes</a> for the last seven days:</p>
<pre tabindex="0"><code class="language-bash">curl &quot;https://api.cloudflare.com/client/v4/radar/netflows/timeseries?name=us_data&amp;dateRange=7d&amp;location=US&amp;name=pt_data&amp;dateRange=7d&amp;location=PT&amp;format=json&quot; \&#10;&#45;-header &quot;Authorization: Bearer &lt;API_TOKEN&gt;&quot;&#10;</code></pre>
<p>In the example above we are asking for two timeseries. The first series has the following parameters:</p>
<p><code>name=us_data&amp;dateRange=7d&amp;location=US</code></p>
<p>The second series has the following parameters:</p>
<p><code>name=pt_data&amp;dateRange=7d&amp;location=PT</code></p>
<p>All of these parameters are arrays, and it is the position in the array that defines the series the filter belongs to. Refer to <a href="/api/resources/radar/subresources/netflows/methods/timeseries/">NetFlow's endpoint</a> for more information on the available parameters.</p>
<p>The response (shortened below for brevity) uses the provided <code>name</code> property to wrap the timestamps and corresponding values. If we chart this data, it becomes obvious that Cloudflare received much less traffic from Portugal than from the United States.</p>
<pre tabindex="0"><code class="language-json">{&#10;  &quot;success&quot;: true,&#10;  &quot;errors&quot;: [],&#10;  &quot;result&quot;: {&#10;    &quot;us_data&quot;: {&#10;      &quot;timestamps&quot;: [ &quot;2022-10-26T17:00:00Z&quot;, &quot;2022-11-02T15:00:00Z&quot; ],&#10;      &quot;values&quot;: [ &quot;0.871752&quot;, &quot;1&quot; ]&#10;    },&#10;    &quot;pt_data&quot;: {&#10;      &quot;timestamps&quot;: [ &quot;2022-10-26T17:00:00Z&quot;, &quot;2022-11-02T15:00:00Z&quot; ],&#10;      &quot;values&quot;: [ &quot;0.020457&quot;, &quot;0.012313&quot; ]&#10;    },&#10;    &quot;meta&quot;: {&#10;      &quot;dateRange&quot;: {&#10;        &quot;startTime&quot;: &quot;2022-10-26T17:00:00Z&quot;,&#10;        &quot;endTime&quot;: &quot;2022-11-02T17:00:00Z&quot;&#10;      },&#10;      &quot;aggInterval&quot;: &quot;ONE_HOUR&quot;,&#10;			// ...&#10;    }&#10;  }&#10;}&#10;</code></pre>
<p>Comparisons can be made in most endpoints, not just endpoints that use <code>min-max</code>.</p>
<h2 id="compare-date-ranges">Compare date ranges</h2>
<p>In the next example, we will compare the United States across different date ranges using the shortcuts <code>7d</code> and <code>7dControl</code>. These mean the last seven days and the last seven days before those, respectively — or, in other words, this week versus the previous week.</p>
<pre tabindex="0"><code class="language-bash">curl &quot;https://api.cloudflare.com/client/v4/radar/netflows/timeseries?name=this_week&amp;dateRange=7d&amp;location=US&amp;name=previous_week&amp;dateRange=7dControl&amp;location=US&amp;format=json&quot; \&#10;&#45;-header &quot;Authorization: Bearer &lt;API_TOKEN&gt;&quot;&#10;</code></pre>
<p>The first series has these parameters:</p>
<p><code>name=this_week&amp;dateRange=7d&amp;location=US</code></p>
<p>The second series has the following parameters:</p>
<p><code>name=previous_week&amp;dateRange=7dControl&amp;location=US</code></p>
<p>Now, in the <code>result</code> property, you should get something like this:</p>
<pre tabindex="0"><code class="language-json">{&#10;  &quot;this_week&quot;: {&#10;    &quot;timestamps&quot;: [ &quot;2022-10-27T13:00:00Z&quot;, &quot;2022-10-27T14:00:00Z&quot;, &quot;...&quot;, &quot;2022-11-03T12:00:00Z&quot; ],&#10;    &quot;values&quot;: [ &quot;0.794321&quot;, &quot;1&quot;, &quot;...&quot;, &quot;0.718433&quot;]&#10;  },&#10;  &quot;previous_week&quot;: {&#10;    &quot;timestamps&quot;: [ &quot;2022-10-20T13:00:00Z&quot;, &quot;2022-10-20T14:00:00Z&quot;, &quot;...&quot;, &quot;2022-10-27T12:00:00Z&quot; ],&#10;    &quot;values&quot;: [ &quot;0.774392&quot;, &quot;0.835071&quot;, &quot;...&quot;, &quot;0.720181&quot;]&#10;  }&#10;}&#10;</code></pre>
<p>Examining this information, we can conclude that the maximum value was reached at <code>2022-10-27T14:00:00Z</code> (all Radar timestamps are in Coordinated Universal Time (UTC)). We can also check what the date range shortcuts <code>7d</code> and <code>7dControl</code> were resolved to at the time this was run.</p>
<h3 id="use-specific-timestamps">Use specific timestamps</h3>
<p>You can also request for specific timestamps. In the following example, we will ask for data relative to <a href="https://blog.cloudflare.com/tonga-internet-outage/">Tonga</a> in October versus January 2022, when there was an outage.</p>
<pre tabindex="0"><code class="language-bash">curl &quot;https://api.cloudflare.com/client/v4/radar/netflows/timeseries?name=tonga&amp;dateStart=2022-10-15T02%3A00%3A00Z&amp;dateEnd=2022-10-15T05%3A00%3A00Z&amp;location=TO&amp;name=tonga_outage&amp;dateStart=2022-01-15T02%3A00%3A00Z&amp;dateEnd=2022-01-15T05%3A00%3A00Z&amp;location=TO&amp;format=json&amp;aggInterval=1h&quot; \&#10;&#45;-header &quot;Authorization: Bearer &lt;API_TOKEN&gt;&quot;&#10;</code></pre>
<p>The first series has these parameters (URL encoded):</p>
<p><code>name=tonga&amp;dateStart=2022-10-15T02%3A00%3A00Z&amp;dateEnd=2022-10-15T05%3A00%3A00Z%&amp;location=TO</code></p>
<p>The second series has these parameters:</p>
<p><code>name=tonga_outage&amp;dateStart=2022-01-15T02%3A00%3A00Z&amp;&amp;dateEnd=2022-01-15T05%3A00%3A00Z&amp;location=TO</code></p>
<p>In the above example, we requested for an <a href="/radar/concepts/aggregation-intervals">aggregation interval</a> of one hour (<code>aggInterval=1h</code>), so that the results could be shown in this page. <code>format</code> and <code>aggInterval</code> are not arrays, as specified in the <a href="/api/resources/radar/subresources/netflows/methods/timeseries/">API reference</a>, and apply globally to all series in the request.</p>
<p>The <code>result</code> property should return a response like this:</p>
<pre tabindex="0"><code class="language-json">{&#10;	&quot;tonga&quot;: {&#10;		&quot;timestamps&quot;: [&quot;2022-10-15T02:00:00Z&quot;, &quot;2022-10-15T03:00:00Z&quot;, &quot;2022-10-15T04:00:00Z&quot;, &quot;2022-10-15T05:00:00Z&quot;],&#10;		&quot;values&quot;: [&quot;1.0&quot;, &quot;0.832473&quot;, &quot;0.820083&quot;, &quot;0.79408&quot;]&#10;	},&#10;	&quot;tonga_outage&quot;: {&#10;		&quot;timestamps&quot;: [&quot;2022-01-15T02:00:00Z&quot;, &quot;2022-01-15T03:00:00Z&quot;, &quot;2022-01-15T04:00:00Z&quot;, &quot;2022-01-15T05:00:00Z&quot;],&#10;		&quot;values&quot;: [&quot;0.354105&quot;, &quot;0.357287&quot;, &quot;0.181811&quot;, &quot;0.044198&quot;]&#10;	}&#10;}&#10;</code></pre>
<p>This shows how traffic dropped to almost zero during the outage. If we chart it and set the end date to January 18 to make it clearer, we get the following:</p>
