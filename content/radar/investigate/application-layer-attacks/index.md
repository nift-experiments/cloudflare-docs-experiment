<p>While in <a href="/radar/investigate/http-requests">HTTP requests</a> you can examine all kinds of web requests, in application layer attacks you have access only to mitigated HTTP requests. These requests can be mitigated by one of several Cloudflare products, like <a href="/waf/">WAF</a>, <a href="/ddos-protection/">Cloudflare DDoS Protection</a>, <a href="/bots/">Cloudflare bot solutions</a> and others.</p>
<aside class="nb-aside note">
<h3 class="nb-aside-title" id="mitigated-traffic">Mitigated traffic</h3>
@markup("md", "content/.markup/bodies/11560.md")
</aside>
<p>Since we are examining attacks, we can inspect both sides of an attack — both the source location and the target location of the attack. For the source of the attack Cloudflare uses the location the attack is coming from associated with the IP (note that the human orchestrator of the attack may be in a different location than the computer the attack is originating from). For the target location of the attacks, Cloudflare uses the billing location associated with the zone under attack.</p>
<p>This ability to filter by both sides of the attack is only available in the <code>top locations</code> endpoints. Unless otherwise specified, other endpoints are filtered by source location, like the origin location of the attack.</p>
<p>The magnitude of the attack is defined by the total number of mitigated requests.</p>
<p>Like in <a href="/radar/investigate/http-requests">HTTP requests</a>, these endpoints can be split into the ability to fetch a timeseries, a single value summarizing the entire date range, and a list of top locations.</p>
