<h2 id="introduction">Introduction</h2>
<p>Internet service providers are constantly exploring new revenue opportunities to expand their business, and many are now turning to security as a value-added service alongside their connectivity offerings. Traditionally, integrating security with connectivity posed significant challenges due to the reliance on legacy solutions that required costly on-premises hardware. This makes it difficult to deploy and manage and introduces post-deployment struggles with scalability and availability.</p>
<p>Today these limitations can be addressed through cloud-based solutions like <a href="/cloudflare-one/traffic-policies/">Cloudflare Gateway</a>, our Secure Web Gateway service. Cloudflare Gateway's DNS filtering capabilities allow service providers to offer enhanced security as a value-added service for residential and mobile subscribers or B2B clients. With easy-to-create policies backed by Cloudflare's <a href="https://www.cloudflare.com/en-gb/security/">extensive threat intelligence</a>, service providers can effectively safeguard their customers from accessing potentially <a href="/cloudflare-one/traffic-policies/domain-categories/#security-categories">harmful domains</a>.</p>
<p>Moreover, Cloudflare Gateway eliminates concerns around availability, performance, and scalability, as it is built on <a href="/1.1.1.1/">Cloudflare's 1.1.1.1 public DNS resolver</a>, one of the <a href="https://www.dnsperf.com/#!dns-providers">fastest</a> and most widely-used DNS resolvers in the world.</p>
<p>Furthermore, this solution opens up opportunities for developing additional services beyond security, such as parental controls or tailored filtering profiles for B2B clients.</p>
<h2 id="solution">Solution</h2>
<p>Providing DNS security to the service providers' end customers with Cloudflare is straightforward. Service providers simply forward their public DNS requests to their Cloudflare tenant, and Cloudflare will filter DNS queries in accordance with the configured DNS filtering policies.</p>
<p><img src="/assets/upstream/images/reference-architecture/gateway-dns-for-isp/gateway-dns-for-isp-image-01.svg" alt="Figure 1: The service provider subscribers send DNS queries to the service provider DNS server, which will forward them to Cloudflare Gateway to apply DNS filtering policies." /></p>
<p>Cloudflare Gateway, like all Cloudflare services, utilizes <a href="https://www.cloudflare.com/learning/cdn/glossary/anycast-network/">anycast technology</a>, ensuring that all service provider DNS queries are directed to the nearest Cloudflare point of presence.</p>
<p>To distinguish queries originating from the service provider from those coming from other customers, admins configure a <a href="/cloudflare-one/networks/resolvers-and-proxies/dns/locations/">location</a> in their Cloudflare tenant dashboard. When a DNS location is created, Gateway assigns IPv4/IPv6 addresses and DoT/DoH hostnames for that location. These assigned IP addresses and hostnames are then used by the service provider to send DNS queries for resolution. In turn, the service provider configures the location object with the public IP addresses of their on-premises DNS servers, allowing Cloudflare to accurately associate queries with the corresponding location.</p>

<p>DNS filtering is then enforced through DNS policies set up by the service provider to detect domains linked to <a href="/cloudflare-one/traffic-policies/domain-categories/#security-categories">security risks</a>. Cloudflare continuously updates the list of risky domains using <a href="https://www.cloudflare.com/en-gb/security/">its extensive threat intelligence</a>. When a DNS query matches a flagged domain, the corresponding action specified in the DNS policy is executed. This action can be a '<a href="/cloudflare-one/traffic-policies/dns-policies/#block">Block</a>,' where Gateway responds with <code>0.0.0.0</code> for IPv4 queries or <code>::</code> for IPv6 queries, or displays a <a href="/cloudflare-one/reusable-components/custom-pages/gateway-block-page/">custom block page hosted by Cloudflare</a>. Alternatively, an <code>[Override](/cloudflare-one/traffic-policies/dns-policies/#override)</code> action or <a href="/cloudflare-one/reusable-components/custom-pages/gateway-block-page/#redirect-to-a-block-page">block page URL redirect</a> can redirect the DNS query to a block page hosted by the service provider.</p>
<p><img src="/assets/upstream/images/reference-architecture/gateway-dns-for-isp/gateway-dns-for-isp-image-02.svg" alt="Figure 2: A DNS policy to prevent users from navigating to malicious domains. The action is to override and redirect the DNS query to a block page hosted by the service provider." /></p>
<p>To achieve more precise control over which domains are allowed or blocked, the service provider can configure additional Allowed Domain and Blocked Domains policies. By setting these policies with <a href="/cloudflare-one/traffic-policies/order-of-enforcement/#order-of-precedence">lower precedence</a> than the Security Risks policy, the service provider can override the Security Risks policy for specific domains.</p>
<p>To streamline the management of allowed and blocked domains, use <a href="/cloudflare-one/reusable-components/lists/">lists</a>. Lists are easily updated through the dashboard or via <a href="/api/resources/zero_trust/subresources/gateway/subresources/lists/methods/update/">APIs</a>, making policy adjustments more efficient.</p>
<p><img src="/assets/upstream/images/reference-architecture/gateway-dns-for-isp/gateway-dns-for-isp-image-03.svg" alt="Figure 3: DNS policies are applied according to their order of precedence. In this example, the 'Allow List Policy' and 'Block List Policy' will be considered before the 'Security List' policy." /></p>
<p>Additionally, all DNS queries forwarded to Cloudflare Gateway are logged and can be exported to external systems using <a href="/cloudflare-one/insights/logs/logpush/">Logpush</a>.</p>

<h2 id="additional-offerings-based-on-dns-filtering-capabilities">Additional offerings based on DNS filtering capabilities</h2>
<p>Service providers can enhance their offerings by using Cloudflare Gateway DNS policies to deliver additional value-added services alongside the base DNS security service. By using the same solution, service providers can develop customized content category filtering services. These services can be easily constructed using Cloudflare's built-in <a href="/cloudflare-one/traffic-policies/domain-categories/#content-categories">content categories</a> and <a href="/cloudflare-one/traffic-policies/application-app-types/">application types</a>, as well as the service provider's own custom allow and block lists.</p>
<p>Some potential applications include:</p>
<ul>
<li><strong>Parental Control Services</strong>: This service can block categories such as adult themes, child abuse, violence, and questionable content to ensure a safer online environment for children.</li>
<li><strong>Educational Services</strong>: Designed for schools and educational organizations, this service can extend beyond parental controls by blocking additional categories like CIPA, gambling, and entertainment, thereby promoting a focused learning atmosphere.</li>
<li><strong>Enterprise Services</strong>: This offering allows businesses to easily restrict access to non-work-related domains, including categories such as entertainment, social networking, gambling, shopping &amp; auctions, society &amp; lifestyle, and sports.</li>
</ul>
<p>To differentiate these additional services from the core DNS security offering, the service provider would create additional DNS locations, one for each service. Cloudflare would be able to distinguish DNS queries for these services if the service provider sends them to one of the unique identifiers of a location. Each location has a unique <a href="/cloudflare-one/networks/resolvers-and-proxies/dns/locations/dns-resolver-ips/#dns-over-https-doh">DoH</a> and <a href="/cloudflare-one/networks/resolvers-and-proxies/dns/locations/dns-resolver-ips/#dns-over-tls-dot">DoT</a> hostname and a unique <a href="/cloudflare-one/networks/resolvers-and-proxies/dns/locations/dns-resolver-ips/#ipv4ipv6-address">destination IPv6 address</a>. Cloudflare can also provision <a href="/cloudflare-one/networks/resolvers-and-proxies/dns/locations/dns-resolver-ips/#dns-resolver-ip">dedicated destination IPv4 addresses</a> per location.</p>
