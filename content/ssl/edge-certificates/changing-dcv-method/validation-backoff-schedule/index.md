<p>Domain control validation (DCV) has to happen before a certificate authority (CA) will issue a certificate for a domain. If DCV fails during issuance or renewal, Cloudflare automatically retries it on a schedule.</p>
<p>If you use <a href="/ssl/edge-certificates/changing-dcv-method/methods/delegated-dcv/">Delegated DCV</a> or if <a href="/ssl/edge-certificates/changing-dcv-method/">Cloudflare automatically performs DCV for you</a>, this page is only informational. If you have to manually perform DCV, consider the following sections about the validation schedule and remember that DCV tokens have a <a href="#dcv-tokens-validity">fixed validity period</a>.</p>
<aside class="nb-aside note">
@markup("md", "content/.markup/bodies/14097.md")
</aside>
<hr />
<h2 id="dcv-tokens-validity">DCV tokens validity</h2>
<p>The DCV process relies on tokens that are generated by the issuing certificate authority. These tokens have a validity period defined by each CA:</p>
<ul>
<li>Google Trust Services - 14 days</li>
<li>Let's Encrypt - 7 days</li>
<li>SSL.com - 14 days</li>
</ul>
<p>After this period, DCV tokens expire as dictated by the <a href="https://cabforum.org/baseline-requirements-documents/">CA/B Baseline Requirements</a>, and new, valid tokens must be placed.</p>
<aside class="nb-aside caution">
@markup("md", "content/.markup/bodies/14096.md")
</aside>
<hr />
<h2 id="successive-checks-function">Successive checks function</h2>
<p>Cloudflare caps the check backoff to a maximum of four hours to avoid the function growing exponentially, which would result in large gaps between checks towards the end of the month.</p>
<pre><code class="language-txt">now() + min((floor(60 * pow(1.05, retry_attempt)) * INTERVAL &#x27;1 second&#x27;), INTERVAL &#x27;4 hours&#x27;)&#10;</code></pre>
<hr />
<h2 id="capped-attempts-reference-table">Capped attempts reference table</h2>
<p>As presented in the following table, most of the checks take place on the first day after the DCV token is generated.</p>
<p>In manual processes, it is possible that you fall behind schedule when you place the token, meaning that it may not be validated immediately.</p>
<p>In automatic processes, most validations complete within the first five minutes, unless there is a setup misconfiguration.</p>
<h3 id="cloudflare-for-saas">Cloudflare for SaaS</h3>
<p>For <a href="/cloudflare-for-platforms/cloudflare-for-saas/">custom hostnames</a>, the same backoff schedule applies to automatic DCV retries. If you need to trigger an immediate recheck — for example, after your customer has placed the DCV token — send a <a href="/api/resources/custom_hostnames/methods/edit/">PATCH request</a> to the custom hostname with the current <code>ssl</code> settings. This resets the backoff timer and triggers a new validation attempt immediately.</p>
