<p><a href="/cloudflare-one/">Cloudflare One</a> replaces legacy corporate security perimeters with Cloudflare's global network, making access to the Internet and to corporate resources faster and safer for teams around the world.</p>
<p>Organizations can obtain end-to-end post-quantum encryption of their private network traffic by sending it over Cloudflare One's post-quantum on-ramps and off-ramps. This protects traffic against <a href="https://en.wikipedia.org/wiki/Harvest_now,_decrypt_later">harvest-now, decrypt-later</a> attacks even if the individual applications are not yet upgraded to post-quantum encryption.</p>
<p>Post-quantum encryption is offered in all major Cloudflare One network configurations, including the following on-ramps:</p>
<ul>
<li>Agentless <a href="#agentless-cloudflare-access">browser access to Cloudflare-proxied applications</a> (including self-hosted apps behind Cloudflare Access)</li>
<li><a href="/cloudflare-one/team-and-resources/devices/cloudflare-one-client/">Cloudflare One Client</a> (on the end-user device)</li>
<li><a href="/cloudflare-wan/reference/gre-ipsec-tunnels/">Cloudflare IPsec</a> on-ramp</li>
</ul>
<p>And off-ramps:</p>
<ul>
<li><a href="/cloudflare-one/networks/connectors/cloudflare-tunnel/">Cloudflare Tunnel</a> off-ramp (using <code>cloudflared</code>)</li>
<li>Cloudflare IPsec off-ramp</li>
</ul>
<p>For traffic that egresses to the public Internet, <a href="/cloudflare-one/traffic-policies/http-policies/">Cloudflare Gateway</a> also provides post-quantum encryption as a Secure Web Gateway (SWG).</p>
<p>These on-ramps and off-ramps all use <a href="/ssl/post-quantum-cryptography/#hybrid-key-agreement">hybrid post-quantum key agreement</a>.</p>
<p><img src="/assets/upstream/images/ssl/pqc-cloudflare-one-overview.png" alt="Overview diagram of post-quantum Cloudflare One network configurations showing on-ramps and off-ramps" /></p>
<p>The sample configurations below illustrate how Cloudflare One's post-quantum on-ramps and off-ramps fit together for several common use cases. For the broader status of post-quantum support across all Cloudflare products and connections, refer to <a href="/ssl/post-quantum-cryptography/pqc-cloudflare-products/">PQC in Cloudflare products</a>.</p>
<h2 id="browser-to-self-hosted-application-agentless-cloudflare-access">Browser to self-hosted application </h2>
<p>A common configuration is browser access to a <a href="/cloudflare-one/access-controls/applications/http-apps/self-hosted-public-app/">self-hosted application</a> that is exposed to Cloudflare's network via a <a href="/cloudflare-one/networks/connectors/cloudflare-tunnel/">Cloudflare Tunnel</a>. This is often combined with <a href="/cloudflare-one/access-controls/policies/">Cloudflare Access</a> for identity-based policy enforcement; refer to the <a href="/learning-paths/clientless-access/initial-setup/">agentless access learning path</a> for guidance.</p>
<p>Even if the application itself has not yet migrated to post-quantum cryptography, traffic to it will be protected against harvest-now, decrypt-later attacks.</p>
<p><img src="/assets/upstream/images/ssl/pqc-clientless-access.png" alt="Diagram of how post-quantum cryptography works for browser-based access to a self-hosted application via Cloudflare Tunnel" />.</p>
<p>Here is how it works today:</p>
<p><strong>1. Connection via browser</strong></p>
<p>As long as the end user uses a <a href="/ssl/post-quantum-cryptography/pqc-support/#browsers">modern web browser that supports post-quantum key agreement</a>, the connection from the device to Cloudflare's network is secured via TLS 1.3 with post-quantum key agreement.</p>
<p><strong>2. Within Cloudflare's global network</strong></p>
<p>If the user and origin server are geographically distant, then the user's traffic will enter Cloudflare's global network in one geographic location (such as Frankfurt), and exit at another (such as San Francisco). As this traffic moves from one data center to another inside Cloudflare's global network, these hops through the network are secured via TLS 1.3 with post-quantum key agreement.</p>
<p><strong>3. Cloudflare Tunnel</strong></p>
<p>Customers establish a <a href="/cloudflare-one/networks/connectors/cloudflare-tunnel/">Cloudflare Tunnel</a> from their data center or public cloud — where their corporate web application is hosted — to Cloudflare's network. This tunnel is secured using TLS 1.3 with post-quantum key agreement.</p>
<p>This configuration provides end-to-end post-quantum protection for browser access to corporate HTTPS applications without requiring customers to upgrade the security of the applications themselves.</p>
<h2 id="cloudflare-one-client">Cloudflare One Client</h2>
<p><a href="/cloudflare-one/team-and-resources/devices/cloudflare-one-client/">Cloudflare One Client</a> (formerly WARP) tunnels traffic from the end-user device to Cloudflare's global network. The following is an example network configuration with a Cloudflare One Client on-ramp and a Cloudflare Tunnel off-ramp.</p>
<p><img src="/assets/upstream/images/ssl/pqc-cloudflare-one-client.png" alt="Diagram of post-quantum network configuration using Cloudflare One Client on-ramp and Cloudflare Tunnel off-ramp" /></p>
<p><em>Note: Labels in this image may reflect a previous product name.</em></p>
<p><strong>1. Connection via Cloudflare One Client</strong></p>
<p>The Cloudflare One Client uses the MASQUE protocol to connect from the device to Cloudflare's global network, using TLS 1.3 with hybrid ML-KEM.</p>
<p><strong>2. Within Cloudflare's global network</strong></p>
<p>The traffic then travels across Cloudflare's global network over TLS 1.3 with hybrid ML-KEM.</p>
<p><strong>3. Cloudflare Tunnel</strong></p>
<p><a href="/cloudflare-one/networks/connectors/cloudflare-tunnel/">Cloudflare Tunnel</a> supports post-quantum key agreement.</p>
<p>With this network configuration, traffic is encapsulated in tunnels protected with post-quantum encryption without requiring individual upgrades of networks or applications. This provides comprehensive protection for any protocol that can be sent through these tunnels, not just for HTTPS.</p>
<h2 id="cloudflare-ipsec">Cloudflare IPsec</h2>
<p>The following is a sample network configuration that uses the Cloudflare One Client on-ramp to connect an end-user device to a server behind a <a href="/cloudflare-wan/configuration/appliance/">Cloudflare One Appliance</a> off-ramp. Traffic to the server is protected by post-quantum cryptography as it travels over the public Internet, even if the server itself does not support post-quantum cryptography.</p>
<p><img src="/assets/upstream/images/ssl/pqc-cloudflare-ipsec.png" alt="Diagram of post-quantum network configuration using Cloudflare One Client on-ramp to Cloudflare One Appliance off-ramp" /></p>
<p><strong>1. Connection via Cloudflare One Client</strong></p>
<p>The Cloudflare One Client uses the MASQUE protocol, as described in the <a href="#cloudflare-one-client">Cloudflare One Client</a> section above.</p>
<p><strong>2. Within Cloudflare's global network</strong></p>
<p>The traffic then travels across Cloudflare's global network over TLS 1.3 with hybrid ML-KEM.</p>
<p><strong>3. Cloudflare IPsec with Cloudflare One Appliance</strong></p>
<p>Traffic leaves the Cloudflare network over a post-quantum Cloudflare IPsec link that is terminated at a Cloudflare One Appliance. The Cloudflare One Appliance uses a non-IKE keying protocol built into the control plane, secured with TLS, that establishes the keys used to encrypt dataplane traffic in the IPsec ESP protocol. From Appliance version 2026.2.0, the control plane establishes keys over TLS 1.3 protected with hybrid ML-KEM.</p>
<h2 id="cloudflare-ipsec-with-third-party-devices">Cloudflare IPsec with third-party devices</h2>
<p><a href="/cloudflare-wan/reference/gre-ipsec-tunnels/">Cloudflare IPsec</a> also supports post-quantum key agreement with compatible third-party network devices using standard IKEv2. This extends post-quantum protection to organizations that connect their own routers and firewalls to Cloudflare's global network instead of using the Cloudflare One Appliance.</p>
<p>The hybrid key agreement is negotiated using ML-KEM as an additional Key Exchange to classical Diffie-Hellman during the IKEv2 handshake, as defined in <a href="https://datatracker.ietf.org/doc/rfc9370/">RFC 9370</a> and <a href="https://datatracker.ietf.org/doc/draft-ietf-ipsecme-ikev2-mlkem/">draft-ietf-ipsecme-ikev2-mlkem</a>. For the list of validated third-party platforms and their supported parameters, refer to <a href="/cloudflare-wan/reference/gre-ipsec-tunnels/#tested-third-party-vendor-interoperability">Tested third-party vendor interoperability</a>.</p>
<p>Cloudflare also supports downgrade protection for IPsec tunnels via the <a href="https://datatracker.ietf.org/doc/draft-ietf-ipsecme-ikev2-downgrade-prevention/"><code>IKE_SA_INIT_FULL_TRANSCRIPT_AUTH</code></a> extension. Both the initiator and Cloudflare (responder) must support the extension for protection to be effective. Refer to <a href="/cloudflare-wan/reference/gre-ipsec-tunnels/#improved-downgrade-protection-beta">Downgrade protection</a>.</p>
<h2 id="secure-web-gateway">Secure Web Gateway</h2>
<p>A <a href="https://www.cloudflare.com/learning/access-management/what-is-a-secure-web-gateway/">secure web gateway (SWG)</a> is used to secure access to third-party websites on the public Internet by intercepting and inspecting TLS traffic.</p>
<p><a href="/cloudflare-one/traffic-policies/http-policies/">Cloudflare Gateway</a> <a href="/cloudflare-one/traffic-policies/http-policies/tls-decryption/#post-quantum-support">supports post-quantum cryptography for HTTPS traffic</a>. As long as the third-party website that is being inspected supports post-quantum key agreement, Cloudflare's SWG also supports post-quantum key agreement.</p>
<p>Cloudflare Gateway's HTTPS filtering feature involves two post-quantum connections, as follows:</p>
<p><strong>1. Connection from the client to Gateway</strong></p>
<p>The client reaches Gateway through one of the post-quantum on-ramps: the <a href="#cloudflare-one-client">Cloudflare One Client</a> or a <a href="#cloudflare-ipsec">Cloudflare IPsec</a> tunnel. These on-ramps carry the client's traffic to Gateway with post-quantum key agreement.</p>
<p><strong>2. Connection from Gateway to the origin server</strong></p>
<p>A TLS connection is initiated from a data center in Cloudflare's network to the origin server, which is typically controlled by a third party. The connection from Cloudflare's SWG supports post-quantum key agreement, as long as the third-party origin server also supports post-quantum key agreement. You can test this out by using <a href="https://pq.cloudflareresearch.com/">https://pq.cloudflareresearch.com/</a> as your third-party origin server.</p>
