<h2 id="basic-post-request">Basic POST request</h2>
<p>If your end user's video is under 200 MB and their connection is reliable, we recommend using this method. If your end user's connection is unreliable, we recommend using the <a href="#direct-creator-uploads-with-tus-protocol">tus protocol</a> instead.</p>
<p>To enable direct creator uploads with a <code>POST</code> request:</p>

<h3 id="step-2-upload-the-video-to-the-one-time-url">Step 2: Upload the video to the one-time URL</h3>
<p>With the <code>uploadURL</code> from the previous step, users can upload video files that are limited to 200 MB in size. Refer to the example request below.</p>
<pre><code class="language-bash">curl --request POST \&#10;  &#45;-form file=@/Users/mickie/Downloads/example_video.mp4 \&#10;  https://upload.videodelivery.net/f65014bc6ff5419ea86e7972a047ba22&#10;</code></pre>
<p>A successful upload returns a <code>200</code> HTTP status code response. If the upload does not meet
the upload constraints defined at time of creation or is larger than 200 MB in size, the response returns a <code>4xx</code> HTTP status code.</p>
<h2 id="direct-creator-uploads-with-tus-protocol">Direct creator uploads with tus protocol</h2>
<p>If your end user's video is over 200 MB, you must use the tus protocol. Even if the file is under 200 MB, if the end user's connection is potentially unreliable, Cloudflare recommends using the tus protocol because it is resumable. For detailed information about tus protocol requirements, additional client examples, and upload options, refer to <a href="/stream/uploading-videos/resumable-uploads/">Resumable and large files (tus)</a>.</p>

<p>The example below shows how to build a Worker that returns a one-time upload URL to your end users. For tus protocol uploads, your backend must pass the <code>Tus-Resumable</code>, <code>Upload-Length</code>, and <code>Upload-Metadata</code> headers. <pre><code class="language-javascript">export async function onRequest(context) {&#10;	const { request, env } = context;&#10;	const { CLOUDFLARE_ACCOUNT_ID, CLOUDFLARE_API_TOKEN } = env;&#10;	const endpoint = `https://api.cloudflare.com/client/v4/accounts/${CLOUDFLARE_ACCOUNT_ID}/stream?direct_user=true`;&#10;&#10;	const response = await fetch(endpoint, {&#10;		method: &quot;POST&quot;,&#10;		headers: {&#10;			Authorization: `bearer ${CLOUDFLARE_API_TOKEN}`,&#10;			&quot;Tus-Resumable&quot;: &quot;1.0.0&quot;,&#10;			&quot;Upload-Length&quot;: request.headers.get(&quot;Upload-Length&quot;),&#10;			&quot;Upload-Metadata&quot;: request.headers.get(&quot;Upload-Metadata&quot;),&#10;		},&#10;	});&#10;&#10;	const destination = response.headers.get(&quot;Location&quot;);&#10;&#10;	return new Response(null, {&#10;		headers: {&#10;			&quot;Access-Control-Expose-Headers&quot;: &quot;Location&quot;,&#10;			&quot;Access-Control-Allow-Headers&quot;: &quot;*&quot;,&#10;			&quot;Access-Control-Allow-Origin&quot;: &quot;*&quot;,&#10;			Location: destination,&#10;		},&#10;	});&#10;}&#10;</code></pre>

<h2 id="upload-metadata-header-syntax">Upload-Metadata header syntax</h2>
<p>You can apply the <a href="/api/resources/stream/subresources/direct_upload/methods/create/">same constraints</a> as Direct Creator Upload via basic upload when using tus. To do so, you must pass the <code>expiry</code> and <code>maxDurationSeconds</code> as part of the <code>Upload-Metadata</code> request header as part of the first request (made by the Worker in the example above.) The <code>Upload-Metadata</code> values are ignored from subsequent requests that do the actual file upload.</p>
<p>The <code>Upload-Metadata</code> header should contain key-value pairs. The keys are text and the values should be encoded in base64. Separate the key and values by a space, <em>not</em> an equal sign. To join multiple key-value pairs, include a comma with no additional spaces.</p>
<p>In the example below, the <code>Upload-Metadata</code> header is instructing Stream to only accept uploads with max video duration of 10 minutes, uploaded prior to the expiry timestamp, and to make this video private:</p>
<p><code>'Upload-Metadata: maxDurationSeconds NjAw,requiresignedurls,expiry MjAyNC0wMi0yN1QwNzoyMDo1MFo='</code></p>
<p><code>NjAw</code> is the base64 encoded value for &quot;600&quot; (or 10 minutes).</p>
<p><code>MjAyNC0wMi0yN1QwNzoyMDo1MFo=</code> is the base64 encoded value for &quot;2024-02-27T07:20:50Z&quot; (an RFC3339 format timestamp)</p>
<h2 id="track-upload-progress">Track upload progress</h2>
<p>After the creation of a unique one-time upload URL, you should retain the unique identifier (<code>uid</code>) returned in the response to track the progress of a user's upload.</p>
<p>You can track upload progress in the following ways:</p>
<ul>
<li>
<p><a href="/api/resources/stream/methods/get/">Use the get video details API endpoint</a> with the <code>uid</code>.</p>
</li>
<li>
<p><a href="/stream/manage-video-library/using-webhooks/">Create a webhook subscription</a> to receive notifications about the video status. These notifications include the <code>uid</code>.</p>
</li>
</ul>
