<p>UI elements are the interactive parts of a product. They are used to build the software's interface. When describing UI elements in writing, we focus on what users need to do without focusing on the UI.</p>
<p>To clarify instructions for complex interfaces, you may need to identify elements by name.</p>

<h2 id="interactions">Interactions</h2>
<p>When describing navigation elements, such as menus, use <code>go to</code> instead of <code>navigate</code>. When describing elements you can activate, such as checkboxes and toggles, use <code>turn on</code>/<code>turn off</code> instead of <code>enable</code>/<code>disable</code>.</p>
<p>For information on physical inputs, such as mouse buttons, refer to <a href="/style-guide/style-and-grammar/formatting/keyboard-keys/">Keyboard keys</a>.</p>
<h2 id="symbols-in-ui-element-names">Symbols in UI element names</h2>
<h3 id="icons-or-non-alphabetic-characters">Icons or non-alphabetic characters</h3>
<p>The names or labels on buttons and other UI elements may include icons or symbols. For example, a button named <strong>+ Add element</strong> includes a plus sign. When writing these names or labels in procedures, do not include symbols. They are usually redundant and can be removed safely.</p>
<p>If an element has no text other than the symbol (for example, just <code>+</code>), you can keep the symbol in the instructions. This especially applies to instructions in interfaces for third-party products.</p>
<h3 id="ellipses">Ellipses</h3>
<p>An ellipsis is a set of three dots (<code>...</code>) that might be used as a variable or wildcard. For example, a <strong>Save As...</strong> menu item might display a dialog box where you can save a file in different places. If you refer to a menu item or button that has an ellipsis, do not include the ellipsis. In text, ellipses can be distracting.</p>
