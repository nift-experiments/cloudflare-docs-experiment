<header><h1>SASE - Protect your users from Internet risks</h1></header>
<section class="video-content" aria-label="Video">
<p>The Internet has become part of your corporate network; however, browsing the web comes with hidden risks including malware, phishing attacks, and malicious websites. In this video, we will explore how Cloudflare's Secure Web Gateway (SWG) helps keep users safe by filtering and inspecting Internet traffic in real time. Whether you are protecting a remote workforce or securing an entire organization, Cloudflare ensures that users can access the web securely — without sacrificing speed or productivity.</p>

But connecting devices and networks into Cloudflare can also help secure public</p><p>Internet access and increase visibility and control over company data.</p><p>Let's take a look at an example of a company that has already connected its corporate HQ</p><p>network, along with a few branch offices and many remote user devices.</p><p>You can see that all these methods of on ramping traffic to Cloudflare result in user</p><p>traffic flowing through our network.</p><p>Sometimes the traffic is destined for a private application or network,</p><p>but a lot of the traffic is just heading for the public Internet.</p><p>Cloudflare has the ability to inspect that traffic using another part of our SASE</p><p>platform, the Secure Web Gateway.</p><p>It can examine traffic either at the DNS request,</p><p>the network level, or we can even inspect the contents of a HTTP request.</p><p>Do you want to deny users from accessing websites known to be part of a phishing</p><p>campaign or ransomware attack, or only allow users coming from IP addresses</p><p>in the US to access your Workday instance?</p><p>Or more seriously, do you want to prevent employees from sending sensitive information</p><p>like financial data or source code to AI sites like ChatGPT?</p><p>Policies in the Secure Web Gateway allow you to achieve this,</p><p>and they can be written using a wide variety of attributes.</p><p>We can even isolate a website by running not in the user's browser,</p><p>but by rendering it in our headless browser, running on our own network.</p><p>And then we send the results down to the user device,</p><p>and this protects them from any nasty code running in that website.</p><p>Let's take a look at the different ways our Secure Web Gateway can help protect your</p><p>organization. We have built-in DLP profiles for matching common data,</p><p>such as health or financial information, source code or privately identifiable</p><p>information such as social security or tax identifiers.</p><p>You can also create your own DLP profiles by either defining patterns to match sensitive</p><p>data, or just by uploading a list of known customer accounts.</p><p>Now, when users attempt to download or upload any content that matches these profiles,</p><p>you have the ability to block it.</p><p>Sometimes the risk for a website isn't well known.</p><p>For example, you might deem social media websites to be a little risky,</p><p>but your marketing department still requires access.</p><p>Newly registered domains might sometimes be part of a phishing campaign,</p><p>or they might just be a legitimate new website.</p><p>In these examples, Cloudflare has a really cool capability.</p><p>You can write a policy that when a user makes a request for a website you think is a little</p><p>risky, instead of their machine receiving all the content directly,</p><p>we spin up a headless browser on our network and render the content first.</p><p>Here we isolate any potential bad behavior in a secure,</p><p>isolated environment.
