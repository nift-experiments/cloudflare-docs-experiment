<p>Security Analytics displays information about all incoming HTTP requests for your domain, including requests not handled by Cloudflare security products. This gives you visibility into your full traffic profile, not only the requests that triggered a security rule.</p>
<p>By default, Security Analytics shows requests from end users (requests to your site directly, as opposed to requests generated by Cloudflare products). Requests generated by <a href="/workers/">Cloudflare Workers</a> subrequests are not included.</p>
<p>Use the Security Analytics dashboard to:</p>
<ul>
<li>View the traffic distribution for your domain.</li>
<li>Understand which traffic is being <span class="nb-glossary-tooltip" title="mitigated request">mitigated</span> by Cloudflare security products, and where non-mitigated traffic is being served from (Cloudflare global network or <a href="https://www.cloudflare.com/learning/cdn/glossary/origin-server/">origin server</a>).</li>
<li>Analyze suspicious traffic and create tailored WAF custom rules based on applied filters.</li>
<li>Review Cloudflare's security scores (<span class="nb-glossary-tooltip" title="attack score">attack score</span>, <a href="/bots/concepts/bot-score/">bot score</a>, <a href="/waf/detections/malicious-uploads/">malicious uploads</a>, and <a href="/waf/detections/leaked-credentials/">leaked credentials</a> results) with real data from your traffic.</li>
<li><a href="/waf/detections/attack-signature-detection/analyze-attack-signatures/">Analyze attack signature matches</a> by Ref, category, and WAF Attack Score.</li>
<li><a href="/waf/rate-limiting-rules/find-rate-limit/">Find an appropriate rate limit</a> for incoming traffic.</li>
<li>Analyze suspicious traffic (<a href="/security/">new security dashboard</a> only).</li>
</ul>
<p>Security Analytics shows all traffic, whether or not Cloudflare acted on it. If you are looking for requests that Cloudflare security products acted on or flagged, refer to <a href="/waf/analytics/security-events/">Security Events</a> instead.</p>

<p>Take the following into account when entering filter values:</p>
<ul>
<li>Do not add quotes around values.</li>
<li>Do not enter the <code>AS</code> prefix when entering ASN numbers. For example, enter <code>1423</code> instead of <code>AS1423</code>.</li>

<p>Select the time frame you wish to analyze from the <em>Previous 24 hours</em> drop-down list.</p>
<h2 id="create-custom-rule-from-current-filters">Create custom rule from current filters</h2>
<p>To create a <a href="/waf/custom-rules/">custom rule</a> with an expression based on the filters you applied in Security Analytics, select <strong>Create custom security rule</strong> above the main chart.</p>

<h2 id="main-dashboard-areas">Main dashboard areas</h2>
<p>The <a href="/security/">new security dashboard</a> and the old dashboard have a few differences, including the order of the various sections on the Security Analytics page.</p>
<h3 id="suspicious-activity">Suspicious activity</h3>
<aside class="nb-aside note">
@markup("md", "content/.markup/bodies/15410.md")

<p>The suspicious activity section gives you information about suspicious requests that were identified by the Cloudflare detections you have enabled. The supported detections include:</p>
<ul>
<li><a href="/bots/additional-configurations/detection-ids/account-takeover-detections/">Account takeover</a></li>
<li><a href="/waf/detections/leaked-credentials/">Leaked credential check</a> (only for user and password leaked)</li>
<li><a href="/waf/detections/malicious-uploads/">Malicious uploads</a></li>
<li><a href="/waf/detections/attack-score/">WAF attack score</a></li>
<li><a href="/waf/detections/ai-security-for-apps/">AI Security for Apps</a></li>
</ul>
<p>Each suspicious activity is classified with a severity score that can vary from critical to low. You can use the filter option to investigate further.</p>
<h3 id="request-activity">Request activity</h3>
<p>The main chart displays the following data for the selected time frame, according to the selected tab:</p>
<ul>
<li>
<p><strong>Traffic analysis</strong>: Traffic mitigated by the Cloudflare security platform, served by Cloudflare, and served by the origin server, according to the following classification:</p>
<ul>
<li><strong>Mitigated by WAF</strong>: Requests blocked or <a href="/cloudflare-challenges/challenge-types/challenge-pages/#actions">challenged</a> by Cloudflare's application security products such as the WAF and HTTP DDoS protection. Requests with <em>Log</em>, <em>Skip</em>, or <em>Allow</em> <a href="/ruleset-engine/rules-language/actions/">actions</a> are not counted as mitigated.</li>
<li><strong>Served by Cloudflare</strong>: Requests served by the Cloudflare global network such as cached content and redirects.</li>
<li><strong>Served by origin</strong>: Requests served by your origin server.</li>
</ul>
</li>
<li>
<p><strong>Attack analysis</strong>: <a href="/waf/detections/attack-score/">WAF attack score</a> and <a href="/waf/detections/attack-signature-detection/analyze-attack-signatures/">attack signature</a> analysis of incoming requests.</p>
</li>
<li>
<p><strong>Bot analysis</strong>: <a href="/bots/concepts/bot-score/">Bot score</a> analysis of incoming requests, classifying them as <em>Automated</em>, <em>Likely automated</em>, <em>Likely human</em>, or <em>Verified bot</em>.</p>
</li>
<li>
<p><strong>Request rate analysis</strong>: Displays data on the request rate for traffic matching the selected filters and time period. Use this tab to <a href="/waf/rate-limiting-rules/find-rate-limit/">find an appropriate rate limit</a> for incoming traffic matching the applied filters.</p>
</li>
<li>
<p><strong>Cloudy analysis</strong> (beta): Get insights about your application security by using plain language to interrogate your data. For more information, refer to <a href="https://blog.cloudflare.com/security-analytics-ai-assistant">our blog post</a>.</p>
</li>
</ul>

<h3 id="insights">Insights</h3>
<aside class="nb-aside note">
@markup("md", "content/.markup/bodies/15408.md")
</aside>
<p>The provided insights show statistics for commonly used filters when doing security analyses, without immediately applying these filters to the displayed data.</p>
<p>If you find a high value in one or more insights, this can mean that there is a set of suspicious requests that you should investigate. Additionally, these insights are a good starting point for applying a first set of filters to the dashboard.</p>
<p>To apply the filters for an insight to the data displayed in the Security Analytics dashboard, select <strong>Filter</strong> next to the insight.</p>
<h3 id="score-based-analyses">Score-based analyses</h3>
<aside class="nb-aside note">
@markup("md", "content/.markup/bodies/15407.md")
</aside>
<p>The <strong>Attack analysis</strong>, <strong>Bot analysis</strong>, <strong>Malicious uploads</strong>, and <strong>Account abuse detection</strong> sections display statistics related to Cloudflare's security scores for incoming requests in the selected time frame:</p>
<ul>
<li><strong>Attack analysis</strong>: Uses <a href="/waf/detections/attack-score/">WAF attack scores</a> to classify requests based on the likelihood that the request is malicious.</li>
<li><strong>Bot analysis</strong>: Uses <a href="/bots/concepts/bot-score/">bot scores</a> to classify requests based on the likelihood they come from automated traffic.</li>
<li><strong>Malicious uploads</strong>: Uses <a href="/waf/detections/malicious-uploads/">WAF content scanning</a> scores to detect potentially malicious content uploaded in requests.</li>
<li><strong>Account abuse detection</strong>: Uses <a href="/waf/detections/leaked-credentials/">leaked credentials detection</a> to identify login attempts with credentials that have been exposed in data breaches. All plans include access to the <strong>Leaked credential check</strong> under this section. For more information on what to do if you have leaked credentials, refer to <a href="/waf/detections/leaked-credentials/examples/">Example mitigation rules</a>.</li>
</ul>
<p>You can examine different traffic segments according to the current metric (attack score, bot score, or content scanning). To apply score filters for different segments, select the buttons below the traffic chart. For example, select <strong>Likely attack</strong> under <strong>Attack analysis</strong> to filter requests that are likely an attack (requests with WAF attack score values between 21 and 50).</p>
<p>Additionally, you can use the slider tool below the chart to filter incoming requests according to the current metric. This allows you to filter traffic groups outside the predefined segments.</p>
<h3 id="logs">Logs</h3>
<p>Security Analytics shows request logs for the selected time frame and applied filters, along with detailed information and security analyses of those requests.</p>
<p>By default, Security Analytics uses sampled logs (a subset of your traffic rather than every individual request). Sampling allows Cloudflare to return results in seconds, even when query volumes are large. If you are subscribed to <a href="/log-explorer/">Log Explorer</a>, you may also have access to <a href="#raw-logs">raw logs</a>.</p>
<h4 id="sampled-logs">Sampled logs</h4>
<p>This section contains detailed log information for individual (<a href="#sampling">sampled</a>) requests in the selected time frame.</p>
<p><img src="/assets/upstream/images/waf/security-analytics/security-analytics-sampled-logs.png" alt="The Sampled logs section of Security Analytics showing an expanded log entry with additional details." /></p>
<p>The displayed information includes:</p>
<ul>
<li>Mitigation action applied to the request</li>
<li>Cache status</li>
<li>Status code returned by the origin server to Cloudflare (in case of a cache miss)</li>
<li>Status code returned by Cloudflare to the client</li>
<li>Security scores for the request (attack, bot, uploaded content scanning)</li>
<li>Request properties</li>
</ul>
<h4 id="raw-logs">Raw logs <span class="nb-badge">Beta</span></h4>
<aside class="nb-aside note">
@markup("md", "content/.markup/bodies/15406.md")
</aside>
<p>When performing a forensic analysis, you sometimes select a very short time frame and apply several filters to identify a specific set of requests. In this situation, to get a better understanding of the incoming requests at a given point in time, you would require the full list of requests and not just a sample.</p>
<p>By default, Security Analytics shows sampled logs based on the filters you apply. Under certain conditions, you can switch to <strong>Raw logs</strong>. This view shows all the request logs for the selected time frame and filters instead of sampled logs. At this time, this view is only available when the number of sampled logs shown in the Security Analytics page is lower than 100.</p>
<h5 id="view-raw-logs">View raw logs</h5>
<p>To switch from sampled logs to raw logs, select <strong>Switch to raw logs</strong> under <strong>Sampled logs</strong>. This option is only available when the number of (sampled) logs for the selected time frame is lower than 100.</p>
<p>To switch from raw logs back to sampled logs, select <strong>Switch back to sampled logs</strong>.</p>
<h5 id="query-raw-logs-using-log-explorer">Query raw logs using Log Explorer</h5>
<p>You can switch to <a href="/log-explorer/">Log Explorer</a> to dive deeper on your analysis while applying the same filters you used in Security Analytics. Raw logs in Security Analytics are based on the same data source used in Log Explorer.</p>
