<h2 id="create-a-custom-rule-checking-for-exposed-credentials">Create a custom rule checking for exposed credentials</h2>
<aside class="nb-aside note">
@markup("md", "content/.markup/bodies/15658.md")
</aside>
<p>You can create rules that check for exposed credentials using the <a href="/ruleset-engine/rulesets-api/">Rulesets API</a>. Include these rules in a custom ruleset, which you must create at the account level, and then deploy the custom ruleset to a phase.</p>
<p>A rule checking for exposed credentials has a match when both the rule expression and the result from the exposed credentials check are true.</p>
<p>To check for exposed credentials in a custom rule, include the <code>exposed_credential_check</code> object in the rule definition. This object must have the following properties:</p>
<ul>
<li><code>username_expression</code> — Expression that selects the user ID used in the credentials check. This property can have up to 1024 characters.</li>
<li><code>password_expression</code> — Expression that selects the password used in the credentials check. This property can have up to 1024 characters.</li>
</ul>
<aside class="nb-aside note">
@markup("md", "content/.markup/bodies/15657.md")
</aside>
<p>You can use the <code>exposed_credential_check</code> object in rules with one of the following actions: <code>rewrite</code>, <code>log</code>, <code>block</code>, <code>js_challenge</code> (Non-Interactive Challenge), or <code>challenge</code> (Interactive Challenge). Cloudflare recommends that you only use exposed credentials checks with the following actions: <code>rewrite</code> and <code>log</code>.</p>
<p>To create and deploy a custom ruleset, follow the workflow described in <a href="/ruleset-engine/custom-rulesets/">Work with custom rulesets</a>.</p>
<h3 id="example-a">Example A</h3>
<p>This <code>POST</code> request example creates a new custom ruleset with a rule that checks for exposed credentials. The rule has a match if both the rule expression and the <code>exposed_credential_check</code> result are <code>true</code>. When there is a match, the rule will log the request with exposed credentials in the Cloudflare logs.</p>
<pre class="nb-api-request"><code class="language-bash">curl --request POST \&#10;  --url https://api.cloudflare.com/client/v4/accounts/{account_id}/rulesets \&#10;  --header &quot;Authorization: Bearer $CLOUDFLARE_API_TOKEN&quot; \&#10;  --data &#x27;{&#10;  &quot;name&quot;: &quot;Custom Ruleset A&quot;,&#10;  &quot;kind&quot;: &quot;custom&quot;,&#10;  &quot;description&quot;: &quot;This ruleset includes a rule checking for exposed credentials.&quot;,&#10;  &quot;rules&quot;: [&#10;    {&#10;      &quot;action&quot;: &quot;log&quot;,&#10;      &quot;description&quot;: &quot;Exposed credentials check on login.php page&quot;,&#10;      &quot;expression&quot;: &quot;http.request.method == \&quot;POST\&quot; &amp;&amp; http.request.uri == \&quot;/login.php\&quot;&quot;,&#10;      &quot;exposed_credential_check&quot;: {&#10;        &quot;username_expression&quot;: &quot;url_decode(http.request.body.form[\&quot;username\&quot;][0])&quot;,&#10;        &quot;password_expression&quot;: &quot;url_decode(http.request.body.form[\&quot;password\&quot;][0])&quot;&#10;      }&#10;    }&#10;  ],&#10;  &quot;phase&quot;: &quot;http_request_firewall_custom&quot;&#10;}&#x27;</code></pre>
<p>The response returns the created ruleset. Note the presence of the <code>exposed_credential_check</code> object on the rule definition.</p>
<pre><code class="language-json">{&#10;	&quot;result&quot;: {&#10;		&quot;id&quot;: &quot;&lt;CUSTOM_RULESET_ID&gt;&quot;,&#10;		&quot;name&quot;: &quot;Custom Ruleset A&quot;,&#10;		&quot;description&quot;: &quot;This ruleset includes a rule checking for exposed credentials.&quot;,&#10;		&quot;kind&quot;: &quot;custom&quot;,&#10;		&quot;version&quot;: &quot;1&quot;,&#10;		&quot;rules&quot;: [&#10;			{&#10;				&quot;id&quot;: &quot;&lt;CUSTOM_RULE_ID&gt;&quot;,&#10;				&quot;version&quot;: &quot;1&quot;,&#10;				&quot;action&quot;: &quot;log&quot;,&#10;				&quot;description&quot;: &quot;Exposed credentials check on login.php page&quot;,&#10;				&quot;expression&quot;: &quot;http.request.method == \&quot;POST\&quot; &amp;&amp; http.request.uri == \&quot;/login.php\&quot;&quot;,&#10;				&quot;exposed_credential_check&quot;: {&#10;					&quot;username_expression&quot;: &quot;url_decode(http.request.body.form[\&quot;username\&quot;][0])&quot;,&#10;					&quot;password_expression&quot;: &quot;url_decode(http.request.body.form[\&quot;password\&quot;][0])&quot;&#10;				},&#10;				&quot;last_updated&quot;: &quot;2021-03-19T10:48:04.057775Z&quot;,&#10;				&quot;ref&quot;: &quot;&lt;CUSTOM_RULE_REF&gt;&quot;,&#10;				&quot;enabled&quot;: true&#10;			}&#10;		],&#10;		&quot;last_updated&quot;: &quot;2021-03-19T10:48:04.057775Z&quot;,&#10;		&quot;phase&quot;: &quot;http_request_firewall_custom&quot;&#10;	},&#10;	&quot;success&quot;: true,&#10;	&quot;errors&quot;: [],&#10;	&quot;messages&quot;: []&#10;}&#10;</code></pre>
<p>The example uses the <code>url_decode()</code> function because fields in the request body (available in <code>http.request.body.form</code>) are URL-encoded when the content type is <code>application/x-www-form-urlencoded</code>.</p>
<p>After creating the custom ruleset, deploy it to a phase so that it executes. You will need the ruleset ID to deploy the custom ruleset. For more information, refer to <a href="/ruleset-engine/custom-rulesets/deploy-custom-ruleset/">Deploy a custom ruleset</a>.</p>
<h3 id="example-b">Example B</h3>
<p>This <code>POST</code> request example creates a new custom ruleset with a rule that checks for exposed credentials in JSON responses. The rule has a match if both the rule expression and the <code>exposed_credential_check</code> result are <code>true</code>. When there is a match, the rule will add an <code>Exposed-Credential-Check</code> HTTP header to the request with value <code>1</code>.</p>
<pre class="nb-api-request"><code class="language-bash">curl --request POST \&#10;  --url https://api.cloudflare.com/client/v4/accounts/{account_id}/rulesets \&#10;  --header &quot;Authorization: Bearer $CLOUDFLARE_API_TOKEN&quot; \&#10;  --data &#x27;{&#10;  &quot;name&quot;: &quot;Custom Ruleset B&quot;,&#10;  &quot;kind&quot;: &quot;custom&quot;,&#10;  &quot;description&quot;: &quot;This ruleset includes a rule checking for exposed credentials.&quot;,&#10;  &quot;rules&quot;: [&#10;    {&#10;      &quot;action&quot;: &quot;rewrite&quot;,&#10;      &quot;action_parameters&quot;: {&#10;        &quot;headers&quot;: {&#10;          &quot;Exposed-Credential-Check&quot;: {&#10;            &quot;operation&quot;: &quot;set&quot;,&#10;            &quot;value&quot;: &quot;1&quot;&#10;          }&#10;        }&#10;      },&#10;      &quot;description&quot;: &quot;Exposed credentials check on login endpoint with JSON body&quot;,&#10;      &quot;expression&quot;: &quot;http.request.method == \&quot;POST\&quot; &amp;&amp; http.request.uri == \&quot;/login.php\&quot; &amp;&amp; any(http.request.headers[\&quot;content-type\&quot;][*] == \&quot;application/json\&quot;)&quot;,&#10;      &quot;exposed_credential_check&quot;: {&#10;        &quot;username_expression&quot;: &quot;lookup_json_string(http.request.body.raw, \&quot;username\&quot;)&quot;,&#10;        &quot;password_expression&quot;: &quot;lookup_json_string(http.request.body.raw, \&quot;password\&quot;)&quot;&#10;      }&#10;    }&#10;  ],&#10;  &quot;phase&quot;: &quot;http_request_firewall_custom&quot;&#10;}&#x27;</code></pre>
<p>The response returns the created ruleset. Note the presence of the following elements in the rule definition:</p>
<ul>
<li>The <code>rewrite</code> action.</li>
<li>The <code>action_parameters</code> object configuring the HTTP header added to requests with exposed credentials.</li>
<li>The <code>exposed_credential_check</code> object.</li>
</ul>
<pre><code class="language-json">{&#10;	&quot;result&quot;: {&#10;		&quot;id&quot;: &quot;&lt;CUSTOM_RULESET_ID&gt;&quot;,&#10;		&quot;name&quot;: &quot;Custom Ruleset B&quot;,&#10;		&quot;description&quot;: &quot;This ruleset includes a rule checking for exposed credentials.&quot;,&#10;		&quot;kind&quot;: &quot;custom&quot;,&#10;		&quot;version&quot;: &quot;1&quot;,&#10;		&quot;rules&quot;: [&#10;			{&#10;				&quot;id&quot;: &quot;&lt;CUSTOM_RULE_ID&gt;&quot;,&#10;				&quot;version&quot;: &quot;1&quot;,&#10;				&quot;action&quot;: &quot;rewrite&quot;,&#10;				&quot;action_parameters&quot;: {&#10;					&quot;headers&quot;: {&#10;						&quot;Exposed-Credential-Check&quot;: {&#10;							&quot;operation&quot;: &quot;set&quot;,&#10;							&quot;value&quot;: &quot;1&quot;&#10;						}&#10;					}&#10;				},&#10;				&quot;description&quot;: &quot;Exposed credentials check on login endpoint with JSON body&quot;,&#10;				&quot;expression&quot;: &quot;http.request.method == \&quot;POST\&quot; &amp;&amp; http.request.uri == \&quot;/login.php\&quot; &amp;&amp; any(http.request.headers[\&quot;content-type\&quot;][*] == \&quot;application/json\&quot;)&quot;,&#10;				&quot;exposed_credential_check&quot;: {&#10;					&quot;username_expression&quot;: &quot;lookup_json_string(http.request.body.raw, \&quot;username\&quot;)&quot;,&#10;					&quot;password_expression&quot;: &quot;lookup_json_string(http.request.body.raw, \&quot;password\&quot;)&quot;&#10;				},&#10;				&quot;last_updated&quot;: &quot;2022-03-19T12:48:04.057775Z&quot;,&#10;				&quot;ref&quot;: &quot;&lt;CUSTOM_RULE_REF&gt;&quot;,&#10;				&quot;enabled&quot;: true&#10;			}&#10;		],&#10;		&quot;last_updated&quot;: &quot;2022-03-19T12:48:04.057775Z&quot;,&#10;		&quot;phase&quot;: &quot;http_request_firewall_custom&quot;&#10;	},&#10;	&quot;success&quot;: true,&#10;	&quot;errors&quot;: [],&#10;	&quot;messages&quot;: []&#10;}&#10;</code></pre>
<p>After creating the custom ruleset, deploy it to a phase so that it executes. You will need the ruleset ID to deploy the custom ruleset. For more information, refer to <a href="/ruleset-engine/custom-rulesets/deploy-custom-ruleset/">Deploy a custom ruleset</a>.</p>
