<p>To enable the Cloudflare OWASP Core Ruleset for a given zone using the API, create a rule with <code>execute</code> action in the entry point ruleset for the <code>http_request_firewall_managed</code> phase. For more information on deploying a managed ruleset, refer to <a href="/ruleset-engine/managed-rulesets/deploy-managed-ruleset/">Deploy a managed ruleset</a>.</p>
<p>To configure the Cloudflare OWASP Core Ruleset using the API, create <a href="/ruleset-engine/managed-rulesets/override-managed-ruleset/">overrides</a> using the Rulesets API. You can perform the following configurations:</p>
<ul>
<li><a href="#set-the-paranoia-level">Set the paranoia level</a>.</li>
<li><a href="#configure-the-score-threshold-and-the-action">Configure the score threshold</a>.</li>
<li><a href="#configure-the-score-threshold-and-the-action">Specify the action to perform</a> when the threat score is greater than the threshold.</li>
</ul>
<p>You can also disable specific rules in the managed ruleset using <a href="/ruleset-engine/managed-rulesets/override-managed-ruleset/">rule overrides</a>.</p>
<h2 id="set-the-paranoia-level">Set the paranoia level</h2>
<p>To enable all the rules up to a specific <a href="/waf/managed-rules/reference/owasp-core-ruleset/concepts/#paranoia-level">paranoia level</a>, create <a href="/ruleset-engine/managed-rulesets/override-managed-ruleset/#work-with-overrides">tag overrides</a> that disable all the rules associated with higher paranoia levels.</p>
<p>The tags associated with the different paranoia levels are the following:</p>
<ul>
<li><code>paranoia-level-1</code></li>
<li><code>paranoia-level-2</code></li>
<li><code>paranoia-level-3</code></li>
<li><code>paranoia-level-4</code></li>
</ul>
<p>For example, to enable all the rules associated with Paranoia Level 2 (PL2), disable the rules associated with tags <code>paranoia-level-3</code> and <code>paranoia-level-4</code>. All rules associated with paranoia levels up to the desired paranoia level will be enabled (in this example, all the rules associated with PL1 and PL2).</p>

<h2 id="configure-the-score-threshold-and-the-action">Configure the score threshold and the action</h2>
<p>To define the <a href="/waf/managed-rules/reference/owasp-core-ruleset/concepts/#score-threshold">score threshold</a>, or to specify the <a href="/ruleset-engine/rules-language/actions/">action</a> to perform when the threat score is greater than the threshold, create a <a href="/ruleset-engine/managed-rulesets/override-managed-ruleset/#work-with-overrides">rule override</a> for the last rule in the managed ruleset that:</p>
<ul>
<li>Specifies the action to take in the <code>action</code> property. The available actions are: <code>js_challenge</code> (Non-Interactive Challenge), <code>managed_challenge</code> (Managed Challenge), <code>block</code> (default), <code>challenge</code> (Interactive Challenge), and <code>log</code>.</li>
<li>Defines the desired anomaly score threshold (an integer value) in the <code>score_threshold</code> property.</li>
</ul>
