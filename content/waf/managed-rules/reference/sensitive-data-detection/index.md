</aside>
<p>The Cloudflare Sensitive Data Detection managed ruleset helps identify data leaks generated by your origin servers. Its rules run on the body of the response looking for patterns of common sensitive data, including:</p>
<ul>
<li><a href="https://www.cloudflare.com/learning/privacy/what-is-pii/">Personally identifiable information</a> (PII) — For example, passport numbers.</li>
<li>Financial information — For example, credit card numbers.</li>
<li>Secrets — For example, API keys.</li>
</ul>
<p>Turning on Cloudflare Sensitive Data Detection will not introduce additional latency, since the detection occurs outside the response path. For this reason, rules are always deployed with the <em>Log</em> action (you cannot block a response that was already sent), providing you with visibility on the sensitive data leaving your origin servers.</p>
<aside class="nb-aside note">
@markup("md", "content/.markup/bodies/15601.md")
</aside>
<h2 id="additional-remarks">Additional remarks</h2>
<p>When turned on, Cloudflare Sensitive Data Detection will check all responses sent to visitors (according to your custom filter expression, if defined), including responses from cache and responses handled by <a href="/workers/">Workers</a>.</p>
<p>The detection will handle text, HTML, JSON, and XML content in the response up to 1 MB.</p>
<p>Currently, Cloudflare Sensitive Data Detection does not support <a href="/waf/managed-rules/payload-logging/">matched payload logging</a>.</p>

<h2 id="configure-via-api">Configure via API</h2>
<p>To deploy the Cloudflare Sensitive Data Detection ruleset for a given zone using the API, create a rule with <code>execute</code> action in the <a href="/ruleset-engine/about/rulesets/#entry-point-ruleset">entry point ruleset</a> for the <code>http_response_firewall_managed</code> phase.</p>
<h3 id="example">Example</h3>
<p>This example deploys the Cloudflare Sensitive Data Detection ruleset to the <code>http_response_firewall_managed</code> phase of a given zone (<code>$ZONE_ID</code>) by creating a rule that executes the managed ruleset. The rules in the managed ruleset are executed for all incoming requests.</p>
<ol>
<li></li>
</ol>

You will need the <a href="/fundamentals/account/find-account-and-zone-ids/">zone ID</a> for this task.</p>

<h2 id="review-detected-leaks">Review detected leaks</h2>
<p>To check for any data leaks detected by Cloudflare Sensitive Data Detection, you can do the following:</p>
<ul>
<li>Regularly check <a href="/waf/analytics/security-events/">Security Events</a> for any events generated by the managed ruleset.</li>
<li>Configure <a href="/waf/reference/alerts/">WAF alerts</a> to be alerted of any spike of WAF events. For the Advanced Security Events Alert, you can filter by one or more domains on Enterprise plans and by the <code>Data Loss Protection</code> service to receive specific alerts about Sensitive Data Detection.</li>
</ul>
