<p>Workers AI supports OpenAI compatible endpoints for <a href="/workers-ai/models/">text generation</a> (<code>/v1/chat/completions</code>) and <a href="/workers-ai/models/">text embedding models</a> (<code>/v1/embeddings</code>). This allows you to use the same code as you would for your OpenAI commands, but swap in Workers AI easily.
<br /></p>
<h2 id="usage">Usage</h2>
<h3 id="workers-ai">Workers AI</h3>
<p>Normally, Workers AI requires you to specify the model name in the cURL endpoint or within the <code>env.AI.run</code> function.</p>
<p>With OpenAI compatible endpoints, you can leverage the <a href="https://github.com/openai/openai-node">openai-node sdk</a> to make calls to Workers AI. This allows you to use Workers AI by simply changing the base URL and the model name.</p>
<pre><code class="language-js">import OpenAI from &quot;openai&quot;;&#10;&#10;const openai = new OpenAI({&#10;	apiKey: env.CLOUDFLARE_API_KEY,&#10;	baseURL: `https://api.cloudflare.com/client/v4/accounts/${env.CLOUDFLARE_ACCOUNT_ID}/ai/v1`,&#10;});&#10;&#10;// Use chat completions&#10;const chatCompletion = await openai.chat.completions.create({&#10;	messages: [{ role: &quot;user&quot;, content: &quot;Make some robot noises&quot; }],&#10;	model: &quot;@cf/meta/llama-3.1-8b-instruct&quot;,&#10;});&#10;&#10;// Use responses&#10;const response = await openai.responses.create({&#10;	model: &quot;@cf/openai/gpt-oss-120b&quot;,&#10;	input: &quot;Talk to me about open source&quot;,&#10;});&#10;&#10;const embeddings = await openai.embeddings.create({&#10;	model: &quot;@cf/baai/bge-large-en-v1.5&quot;,&#10;	input: &quot;I love matcha&quot;,&#10;});&#10;</code></pre>
<pre><code class="language-bash">curl --request POST \&#10;  &#45;-url https://api.cloudflare.com/client/v4/accounts/{account_id}/ai/v1/chat/completions \&#10;  &#45;-header &quot;Authorization: Bearer {api_token}&quot; \&#10;  &#45;-header &quot;Content-Type: application/json&quot; \&#10;  &#45;-data &#x27;&#10;    {&#10;      &quot;model&quot;: &quot;@cf/meta/llama-3.1-8b-instruct&quot;,&#10;      &quot;messages&quot;: [&#10;        {&#10;          &quot;role&quot;: &quot;user&quot;,&#10;          &quot;content&quot;: &quot;how to build a wooden spoon in 3 short steps? give as short as answer as possible&quot;&#10;        }&#10;      ]&#10;    }&#10;&#x27;&#10;</code></pre>
<h3 id="fail-fast-when-capacity-is-unavailable">Fail fast when capacity is unavailable</h3>
<p>For synchronous Chat Completions, set <code>options.rejectIfBusy</code> in the top-level request body. This makes the request fail instead of waiting in a capacity queue.</p>
<p>OpenAI clients that preserve custom fields can send this option. Clients that remove unknown fields do not apply it, so requests proceed normally.</p>
<p>Refer to <a href="/workers-ai/features/reject-if-busy/">Reject busy requests</a> for examples and error behavior.</p>
