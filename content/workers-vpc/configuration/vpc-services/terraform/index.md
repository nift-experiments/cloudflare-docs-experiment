<p>VPC Services can be managed as infrastructure using the <a href="https://registry.terraform.io/providers/cloudflare/cloudflare/latest/docs/resources/connectivity_directory_service"><code>cloudflare_connectivity_directory_service</code></a> resource in the <a href="/terraform/">Cloudflare Terraform provider</a>.</p>
<p>This maps directly to the <a href="/api/resources/connectivity/subresources/directory/subresources/services/">connectivity directory</a> — the underlying API that the dashboard and Wrangler CLI also use to create and manage VPC Services. The same <a href="/workers-vpc/configuration/vpc-services/#vpc-service-configuration">VPC Service configuration fields</a> (type, host, ports, tunnel ID) apply regardless of how the service is created.</p>
<aside class="nb-aside note">
@markup("md", "content/.markup/bodies/15888.md")
</aside>
<h2 id="vpc-service-resource">VPC Service resource</h2>
<p>The <code>cloudflare_connectivity_directory_service</code> resource creates a VPC Service in the connectivity directory. Each resource corresponds to one VPC Service entry that a Worker can bind to.</p>
<h3 id="hostname-based-configuration">Hostname-based configuration</h3>
<p>When using a hostname, provide <code>host.hostname</code> with a <code>resolver_network</code> block. This parallels the hostname-based <a href="/workers-vpc/configuration/vpc-services/#configuration-examples">JSON configuration example</a>.</p>
<pre tabindex="0"><code class="language-tf">resource &quot;cloudflare_connectivity_directory_service&quot; &quot;my_private_api&quot; {&#10;  account_id = var.account_id&#10;  name       = &quot;my-private-api&quot;&#10;  type       = &quot;http&quot;&#10;  http_port  = 80&#10;  https_port = 443&#10;&#10;  host = {&#10;    hostname = &quot;internal-api.example.com&quot;&#10;    resolver_network = {&#10;      tunnel_id = var.tunnel_id&#10;    }&#10;  }&#10;}&#10;</code></pre>
<p>To use a custom DNS resolver within your private network, add <code>resolver_ips</code>:</p>
<pre tabindex="0"><code class="language-tf">resource &quot;cloudflare_connectivity_directory_service&quot; &quot;my_private_api&quot; {&#10;  account_id = var.account_id&#10;  name       = &quot;my-private-api&quot;&#10;  type       = &quot;http&quot;&#10;&#10;  host = {&#10;    hostname = &quot;internal-api.example.com&quot;&#10;    resolver_network = {&#10;      tunnel_id    = var.tunnel_id&#10;      resolver_ips = [&quot;10.0.0.53&quot;]&#10;    }&#10;  }&#10;}&#10;</code></pre>
<h3 id="ip-based-configuration">IP-based configuration</h3>
<p>When using IP addresses, provide <code>host.ipv4</code> and/or <code>host.ipv6</code> with a <code>network</code> block. This parallels the IP-based <a href="/workers-vpc/configuration/vpc-services/#configuration-examples">JSON configuration example</a>.</p>
<pre tabindex="0"><code class="language-tf">resource &quot;cloudflare_connectivity_directory_service&quot; &quot;my_private_api&quot; {&#10;  account_id = var.account_id&#10;  name       = &quot;my-private-api&quot;&#10;  type       = &quot;http&quot;&#10;  http_port  = 8080&#10;  https_port = 8443&#10;&#10;  host = {&#10;    ipv4 = &quot;10.0.1.50&quot;&#10;    ipv6 = &quot;fe80::1&quot;&#10;    network = {&#10;      tunnel_id = var.tunnel_id&#10;    }&#10;  }&#10;}&#10;</code></pre>
<h3 id="tcp-service-configuration">TCP service configuration</h3>
<p>For TCP services (for example, databases), set <code>type = &quot;tcp&quot;</code> and provide a <code>tcp_port</code>. You can optionally specify an <code>app_protocol</code> of <code>postgresql</code> or <code>mysql</code>.</p>
<pre tabindex="0"><code class="language-tf">resource &quot;cloudflare_connectivity_directory_service&quot; &quot;my_database&quot; {&#10;  account_id   = var.account_id&#10;  name         = &quot;my-postgres-db&quot;&#10;  type         = &quot;tcp&quot;&#10;  tcp_port     = 5432&#10;  app_protocol = &quot;postgresql&quot;&#10;&#10;  host = {&#10;    ipv4 = &quot;10.0.0.5&quot;&#10;    network = {&#10;      tunnel_id = var.tunnel_id&#10;    }&#10;  }&#10;}&#10;</code></pre>
<h3 id="tls-certificate-verification">TLS certificate verification</h3>
<p>To configure the TLS certificate verification mode for the connection to the origin, add a <code>tls_settings</code> block:</p>
<pre tabindex="0"><code class="language-tf">resource &quot;cloudflare_connectivity_directory_service&quot; &quot;my_database&quot; {&#10;  account_id   = var.account_id&#10;  name         = &quot;my-postgres-db&quot;&#10;  type         = &quot;tcp&quot;&#10;  tcp_port     = 5432&#10;  app_protocol = &quot;postgresql&quot;&#10;&#10;  host = {&#10;    ipv4 = &quot;10.0.0.5&quot;&#10;    network = {&#10;      tunnel_id = var.tunnel_id&#10;    }&#10;  }&#10;&#10;  tls_settings = {&#10;    cert_verification_mode = &quot;verify_ca&quot;&#10;  }&#10;}&#10;</code></pre>
<p>Valid values for <code>cert_verification_mode</code> are:</p>
<ul>
<li><code>verify_full</code> (default)</li>
<li><code>verify_ca</code></li>
<li><code>disabled</code></li>
</ul>
<p>Refer to <a href="/workers-vpc/configuration/vpc-services/#tls-certificate-verification-mode">TLS certificate verification mode</a> for details.</p>
<h3 id="port-configuration">Port configuration</h3>
<p>For HTTP services, ports are optional and default to 80 (HTTP) and 443 (HTTPS). To enforce a single scheme, provide only one of <code>http_port</code> or <code>https_port</code>. Refer to <a href="/workers-vpc/configuration/vpc-services/#vpc-service-configuration">VPC Service configuration</a> for how scheme enforcement and port behavior work.</p>
<p>For TCP services, <code>tcp_port</code> is required.</p>
<h2 id="workers-binding-configuration">Workers binding configuration</h2>
<p>Once a VPC Service exists, bind it to a Worker using the <code>vpc_service</code> binding type in the <code>bindings</code> array of a <code>cloudflare_worker_version</code> resource. This is equivalent to the <a href="/workers-vpc/configuration/vpc-services/#workers-binding-configuration"><code>vpc_services</code> array in Wrangler configuration</a>.</p>
<pre tabindex="0"><code class="language-tf">resource &quot;cloudflare_worker_version&quot; &quot;my_worker_version&quot; {&#10;  account_id         = var.account_id&#10;  worker_id          = cloudflare_worker.my_worker.id&#10;  compatibility_date = &quot;2025-02-21&quot; # Set this to today&#x27;s date&#10;  main_module        = &quot;worker.js&quot;&#10;&#10;  modules = [{&#10;    name         = &quot;worker.js&quot;&#10;    content_type = &quot;application/javascript+module&quot;&#10;    content_file = &quot;build/worker.js&quot;&#10;  }]&#10;&#10;  bindings = [{&#10;    type       = &quot;vpc_service&quot;&#10;    name       = &quot;PRIVATE_API&quot;&#10;    service_id = cloudflare_connectivity_directory_service.my_private_api.service_id&#10;  }]&#10;}&#10;</code></pre>
<p>Multiple VPC Service bindings can be added to the same Worker:</p>
<pre tabindex="0"><code class="language-tf">bindings = [&#10;  {&#10;    type       = &quot;vpc_service&quot;&#10;    name       = &quot;PRIVATE_API&quot;&#10;    service_id = cloudflare_connectivity_directory_service.api.service_id&#10;  },&#10;  {&#10;    type       = &quot;vpc_service&quot;&#10;    name       = &quot;PRIVATE_DATABASE&quot;&#10;    service_id = cloudflare_connectivity_directory_service.database.service_id&#10;  }&#10;]&#10;</code></pre>
<p>The Worker code accesses each binding through <code>env.PRIVATE_API.fetch()</code> and <code>env.PRIVATE_DATABASE.fetch()</code>, as described in the <a href="/workers-vpc/api/">Workers Binding API</a>.</p>
<p>For more details on managing Workers and bindings with Terraform, refer to <a href="/workers/platform/infrastructure-as-code/">Workers Infrastructure as Code</a>.</p>
<h2 id="data-sources">Data sources</h2>
<p>The Terraform provider includes data sources for reading existing VPC Services without managing their lifecycle.</p>
<h3 id="look-up-a-single-vpc-service">Look up a single VPC Service</h3>
<pre tabindex="0"><code class="language-tf">data &quot;cloudflare_connectivity_directory_service&quot; &quot;existing&quot; {&#10;  account_id = var.account_id&#10;  service_id = &quot;182bd5e5-6e1a-4fe4-a799-aa6d9a6ab26e&quot;&#10;}&#10;</code></pre>
<p>This is useful for binding to a VPC Service that is managed outside of your Terraform configuration (for example, created through the dashboard or Wrangler CLI).</p>
<h3 id="list-vpc-services">List VPC Services</h3>
<pre tabindex="0"><code class="language-tf">data &quot;cloudflare_connectivity_directory_services&quot; &quot;all_http&quot; {&#10;  account_id = var.account_id&#10;  type       = &quot;http&quot;&#10;}&#10;&#10;data &quot;cloudflare_connectivity_directory_services&quot; &quot;all_tcp&quot; {&#10;  account_id = var.account_id&#10;  type       = &quot;tcp&quot;&#10;}&#10;</code></pre>
<h2 id="resource-schema-reference">Resource schema reference</h2>
<pre tabindex="0"><code class="language-tf">resource &quot;cloudflare_connectivity_directory_service&quot; &quot;example&quot; {&#10;  &#35; Required&#10;  account_id = &quot;your-account-id&quot;        # Account identifier&#10;  name       = &quot;my-private-api&quot;         # Human-readable name&#10;  type       = &quot;http&quot;                   # Service type: &quot;http&quot; or &quot;tcp&quot;&#10;&#10;  &#35; HTTP-specific (optional, defaults to 80/443)&#10;  http_port  = 80                       # HTTP port&#10;  https_port = 443                      # HTTPS port&#10;&#10;  &#35; TCP-specific (tcp_port is required when type = &quot;tcp&quot;)&#10;  &#35; tcp_port     = 5432                 # TCP port&#10;  &#35; app_protocol = &quot;postgresql&quot;         # Optional: &quot;postgresql&quot; or &quot;mysql&quot;&#10;&#10;  host = {&#10;    &#35; Use hostname OR ipv4/ipv6, not both&#10;&#10;    &#35; Option A: Hostname-based&#10;    hostname = &quot;internal-api.example.com&quot;&#10;    resolver_network = {&#10;      tunnel_id    = &quot;tunnel-uuid&quot;      # Required — Cloudflare Tunnel ID&#10;      resolver_ips = [&quot;10.0.0.53&quot;]      # Optional — custom DNS resolver IPs&#10;    }&#10;&#10;    &#35; Option B: IP-based&#10;    &#35; ipv4 = &quot;10.0.1.50&quot;               # IPv4 address&#10;  &#35; }&#10;&#10;  &#35; Read-only (computed by the API)&#10;  &#35; id         — Terraform resource ID&#10;  &#35; service_id — VPC Service ID (use this for Worker bindings)&#10;  &#35; created_at — Creation timestamp&#10;  &#35; updated_at — Last update timestamp&#10;}&#10;</code></pre>
<p>For the full schema, refer to the <a href="https://registry.terraform.io/providers/cloudflare/cloudflare/latest/docs/resources/connectivity_directory_service">Terraform registry documentation</a>.</p>
