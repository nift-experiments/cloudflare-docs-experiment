<p>Whether you are using Wrangler or the <a href="https://developers.cloudflare.com/workers/vite-plugin/">Cloudflare Vite plugin</a>, your workflow for <strong>accessing</strong> data during local development remains the same. However, you can only <a href="/workers/local-development/local-data/#populating-local-resources-with-data">populate local resources with data</a> via the Wrangler CLI.</p>
<h3 id="how-it-works">How it works</h3>
<p>When you run either <code>wrangler dev</code> or <a href="https://vite.dev/guide/cli#dev-server"><code>vite</code></a>, <a href="/workers/testing/miniflare/">Miniflare</a> automatically creates <strong>local versions</strong> of your resources (like <a href="/kv">KV</a>, <a href="/d1/">D1</a>, or <a href="/r2">R2</a>). This means you <strong>don’t</strong> need to manually set up separate local instances for each service. However, newly created local resources <strong>won’t</strong> contain any data — you'll need to use Wrangler commands with the <code>--local</code> flag to populate them. Changes made to local resources won’t affect production data.</p>
<h2 id="populating-local-resources-with-data">Populating local resources with data</h2>
<p>When you first start developing, your local resources will be empty. You'll need to populate them with data using the Wrangler CLI.</p>

<h3 id="durable-objects">Durable Objects</h3>
<p>For Durable Objects, unlike KV, D1, and R2, there are no CLI commands to populate them with local data. To add data to Durable Objects during local development, you must write application code that creates Durable Object instances and <a href="/durable-objects/best-practices/access-durable-objects-storage/">calls methods on them that store state</a>. This typically involves creating development endpoints or test routes that initialize your Durable Objects with the desired data.</p>
<h2 id="where-local-data-gets-stored">Where local data gets stored</h2>
<p>By default, both Wrangler and the Vite plugin store local binding data in the same location: the <code>.wrangler/state</code> folder in your project directory. This folder stores data in subdirectories for all local bindings: KV namespaces, R2 buckets, D1 databases, Durable Objects, etc.</p>
<h3 id="clearing-local-storage">Clearing local storage</h3>
<p>You can delete the <code>.wrangler/state</code> folder at any time to reset your local environment, and Miniflare will recreate it the next time you run your <code>dev</code> command. You can also delete specific sub-folders within <code>.wrangler/state</code> for more targeted clean-up.</p>
<h3 id="changing-the-local-data-directory">Changing the local data directory</h3>
<p>If you prefer to specify a different directory for local storage, you can do so through the Wrangler CLI or in the Vite plugin's configuration.</p>
