<p>When building complex applications, you may want to run multiple Workers during development. This guide covers the different approaches for running multiple Workers locally and when to use each approach.</p>
<h2 id="single-dev-command">Single dev command</h2>
<aside class="nb-aside note">
@markup("md", "content/.markup/bodies/16266.md")
</aside>
<p>You can run multiple Workers in a single dev command by passing multiple configuration files to your dev server:</p>
<p><strong>Using Wrangler</strong></p>

<p>The first config (<code>./app/wrangler.jsonc</code>) is treated as the primary Worker, exposed at <code>http://localhost:8787</code>. Additional configs (e.g. <code>./api/wrangler.jsonc</code>) run as auxiliary Workers, available via service bindings or tail consumers from the primary Worker.</p>
<p><strong>Using the Vite plugin</strong></p>
<p>Configure <code>auxiliaryWorkers</code> in your Vite configuration:</p>
<pre><code class="language-js">import { defineConfig } from &quot;vite&quot;;&#10;import { cloudflare } from &quot;@cloudflare/vite-plugin&quot;;&#10;&#10;export default defineConfig({&#10;  plugins: [&#10;    cloudflare({&#10;      configPath: &quot;./app/wrangler.jsonc&quot;,&#10;      auxiliaryWorkers: [&#10;        {&#10;          configPath: &quot;./api/wrangler.jsonc&quot;,&#10;        },&#10;      ],&#10;    }),&#10;  ],&#10;});&#10;</code></pre>
<p>Then run:</p>

<p><strong>Use this approach when:</strong></p>
<ul>
<li>You want the simplest setup for development</li>
<li>Workers are part of the same application or codebase</li>
<li>You need to access a Durable Object namespace or Workflow from another Worker using <code>script_name</code>, or set up Queues where the producer and consumer Workers are separated.</li>
</ul>

<p>These Workers run in different dev commands but can still communicate with each other via service bindings or tail consumers <strong>regardless of whether they are started with <code>wrangler dev</code> or <code>vite dev</code></strong>.</p>
<aside class="nb-aside note">
@markup("md", "content/.markup/bodies/16265.md")
</aside>
<p><strong>Use this approach when:</strong></p>
<ul>
<li>You want each Worker to be accessible on its own local URL during development, since only the primary Worker is exposed when using a single dev command</li>
<li>Each Worker has its own build setup or tooling — for example, one uses Vite with custom plugins while another is a vanilla Wrangler project</li>
<li>You need the flexibility to run and develop Workers independently without restructuring your project or consolidating configs</li>
</ul>
<p>This setup is especially useful in larger projects where each team maintains a subset of Workers. Running everything in a single dev command might require significant restructuring or build integration that isn't always practical.</p>
