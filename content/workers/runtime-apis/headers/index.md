<h2 id="background">Background</h2>
<p>All HTTP request and response headers are available through the <a href="https://developer.mozilla.org/en-US/docs/Web/API/Headers">Headers API</a>.</p>
<p>When a header name possesses multiple values, those values will be concatenated as a single, comma-delimited string value. This means that <code>Headers.get</code> will always return a string or a <code>null</code> value. This applies to all header names except for <code>Set-Cookie</code>, which requires <code>Headers.getAll</code>. This is documented below in <a href="#differences">Differences</a>.</p>
<pre><code class="language-js">let headers = new Headers();&#10;&#10;headers.get(&#x27;x-foo&#x27;); //=&gt; null&#10;&#10;headers.set(&#x27;x-foo&#x27;, &#x27;123&#x27;);&#10;headers.get(&#x27;x-foo&#x27;); //=&gt; &quot;123&quot;&#10;&#10;headers.set(&#x27;x-foo&#x27;, &#x27;hello&#x27;);&#10;headers.get(&#x27;x-foo&#x27;); //=&gt; &quot;hello&quot;&#10;&#10;headers.append(&#x27;x-foo&#x27;, &#x27;world&#x27;);&#10;headers.get(&#x27;x-foo&#x27;); //=&gt; &quot;hello, world&quot;&#10;</code></pre>
<h2 id="differences">Differences</h2>
<p>The Workers implementation of the <code>Headers</code> API differs from the web standard in several ways. These differences are intentional, and reflect the server-side nature of the Workers runtime.</p>

<h3 id="getall-method"><code>getAll()</code> method</h3>
<p>Despite the fact that the <code>Headers.getAll</code> method has been made obsolete in web browsers, Workers still provides this method for use with the <code>Set-Cookie</code> header. This is because cookies often contain date strings, which include commas. This can make parsing multiple values in a <code>Set-Cookie</code> header difficult.</p>
<p>Any attempts to use <code>Headers.getAll</code> with other header names will throw an error. A brief history of <code>Headers.getAll</code> is available in this <a href="https://github.com/whatwg/fetch/issues/973">GitHub issue</a>.</p>
<h3 id="set-cookie-handling"><code>Set-Cookie</code> handling</h3>
<p>Due to <a href="https://www.rfc-editor.org/rfc/rfc6265">RFC 6265</a> prohibiting folding multiple <code>Set-Cookie</code> headers into a single header, the <code>Headers.append</code> method allows you to set multiple <code>Set-Cookie</code> response headers instead of appending the value onto the existing header.</p>
<pre><code class="language-js">const headers = new Headers();&#10;&#10;headers.append(&quot;Set-Cookie&quot;, &quot;cookie1=value_for_cookie_1; Path=/; HttpOnly;&quot;);&#10;headers.append(&quot;Set-Cookie&quot;, &quot;cookie2=value_for_cookie_2; Path=/; HttpOnly;&quot;);&#10;&#10;console.log(headers.getAll(&quot;Set-Cookie&quot;));&#10;// Array(2) [ cookie1=value_for_cookie_1; Path=/; HttpOnly;, cookie2=value_for_cookie_2; Path=/; HttpOnly; ]&#10;</code></pre>

<h2 id="cloudflare-headers">Cloudflare headers</h2>
<p>Cloudflare sets a number of its own custom headers on incoming requests and outgoing responses. While some may be used for its own tracking and bookkeeping, many of these can be useful to your own applications – or Workers – too.</p>
<p>For a list of documented Cloudflare request headers, refer to <a href="/fundamentals/reference/http-headers/">Cloudflare HTTP headers</a>.</p>
