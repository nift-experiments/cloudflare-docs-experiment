<h2 id="background">Background</h2>
<p>The Workers runtime supports a subset of the <a href="https://developer.mozilla.org/en-US/docs/Web/API/Performance"><code>Performance</code> API</a>, used to measure timing and performance, as well as timing of subrequests and other operations.</p>
<h3 id="performance-now"><code>performance.now()</code></h3>
<p>The <a href="https://developer.mozilla.org/en-US/docs/Web/API/Performance/now"><code>performance.now()</code> method</a> returns timestamp in milliseconds, representing the time elapsed since <code>performance.timeOrigin</code>.</p>
<p>When Workers are deployed to Cloudflare, as a security measure to <a href="/workers/reference/security-model/#step-1-disallow-timers-and-multi-threading">mitigate against Spectre attacks</a>, APIs that return timers, including <a href="https://developer.mozilla.org/en-US/docs/Web/API/Performance/now"><code>performance.now()</code></a> and <a href="https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Date/now"><code>Date.now()</code></a>, only advance or increment after I/O occurs. Consider the following examples:</p>
<pre tabindex="0"><code class="language-typescript">const start = performance.now();&#10;for (let i = 0; i &lt; 1e6; i++) {&#10;  // do expensive work&#10;}&#10;const end = performance.now();&#10;const timing = end - start; // 0&#10;</code></pre>
<pre tabindex="0"><code class="language-typescript">const start = performance.now();&#10;const response = await fetch(&quot;https://developers.cloudflare.com/&quot;);&#10;const end = performance.now();&#10;const timing = end - start; // duration of the subrequest to developers.cloudflare.com&#10;</code></pre>
<p>By wrapping a subrequest in calls to <code>performance.now()</code> or <code>Date.now()</code> APIs, you can measure the timing of a subrequest, fetching a key from KV, an object from R2, or any other form of I/O in your Worker.</p>
<p>In local development, however, timers will increment regardless of whether I/O happens or not. This means that if you need to measure timing of a piece of code that is CPU intensive, that does not involve I/O, you can run your Worker locally, via <a href="/workers/wrangler/">Wrangler</a>, which uses the open-source Workers runtime, <a href="https://github.com/cloudflare/workerd">workerd</a> — the same runtime that your Worker runs in when deployed to Cloudflare.</p>
<h3 id="performance-timeorigin"><code>performance.timeOrigin</code></h3>
<p>The <a href="https://developer.mozilla.org/en-US/docs/Web/API/Performance/timeOrigin"><code>performance.timeOrigin</code></a> API is a read-only property that returns a baseline timestamp to base other measurements off of.</p>
<p>In the Workers runtime, the <code>timeOrigin</code> property returns 0.</p>
