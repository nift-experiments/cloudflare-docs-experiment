<p>Running <a href="/workers/languages/typescript/#generate-types"><code>wrangler types</code></a> generates runtime types including the <code>Service</code> and <code>DurableObjectNamespace</code> types, each of which accepts a single type parameter for the <a href="/workers/runtime-apis/bindings/service-bindings/rpc"><code>WorkerEntrypoint</code></a> or <a href="/durable-objects/best-practices/create-durable-object-stubs-and-send-requests/#call-rpc-methods"><code>DurableObject</code></a> types.</p>
<p>Using higher-order types, we automatically generate client-side stub types (e.g., forcing all methods to be async).</p>
<p><a href="/workers/languages/typescript/#generate-types"><code>wrangler types</code></a> also generates types for the <code>env</code> object. You can pass in the path to the config files of the Worker or Durable Object being called so that the generated types include the type parameters for the <code>Service</code> and <code>DurableObjectNamespace</code> types.</p>
<p>For example, if your client Worker had bindings to a Worker in <code>../sum-worker/</code> and a Durable Object in <code>../counter/</code>, you should generate types for the client Worker's <code>env</code> by running:</p>

<p>This will produce a <code>worker-configuration.d.ts</code> file that includes:</p>
<pre tabindex="0"><code class="language-ts">interface Env {&#10;	SUM_SERVICE: Service&lt;import(&quot;../sum-worker/src/index&quot;).SumService&gt;;&#10;	COUNTER_OBJECT: DurableObjectNamespace&lt;&#10;		import(&quot;../counter/src/index&quot;).Counter&#10;	&gt;;&#10;}&#10;</code></pre>
<p>Now types for RPC method like the <code>env.SUM_SERVICE.sum</code> method will be exposed to the client Worker.</p>
<pre tabindex="0"><code class="language-ts">export default {&#10;	async fetch(req, env, ctx): Promise&lt;Response&gt; {&#10;		const result = await env.SUM_SERVICE.sum(1, 2);&#10;		return new Response(result.toString());&#10;	},&#10;} satisfies ExportedHandler&lt;Env&gt;;&#10;</code></pre>
