<h2 id="security-model">Security Model</h2>
<p>The Workers RPC system is intended to allow safe communications between Workers that do not trust each other. The system does not allow either side of an RPC session to access arbitrary objects on the other side, much less invoke arbitrary code. Instead, each side can only invoke the objects and functions for which they have explicitly received stubs via previous calls.</p>
<p>This security model is commonly known as Object Capabilities, or Capability-Based Security. Workers RPC is built on <a href="https://capnproto.org/rpc.html">Cap'n Proto RPC</a>, which in turn is based on CapTP, the object transport protocol used by the <a href="https://www.crockford.com/ec/etut.html">distributed programming language E</a>.</p>
<h2 id="visibility-of-methods-and-properties">Visibility of Methods and Properties</h2>
<h3 id="private-properties">Private properties</h3>
<p><a href="https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Classes/Private_properties">Private properties</a> of classes are not directly exposed over RPC.</p>
<h3 id="arrow-functions">Arrow functions</h3>
<p>Arrow function expressions are not exposed over RPC because they are defined on class instances, not on the class prototype. They <a href="https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Functions/Arrow_functions#cannot_be_used_as_methods">should not be used as class methods</a> of <code>WorkerEntrypoint</code> classes.</p>
<pre><code class="language-js">import { WorkerEntrypoint } from &quot;cloudflare:workers&quot;;&#10;&#10;export default class extends WorkerEntrypoint {&#10;  // add() is exposed over RPC.&#10;  add(a, b) {&#10;    return a + b;&#10;  }&#10;&#10;  // subtract() is NOT exposed over RPC.&#10;  subtract = (a, b) =&gt; a - b;&#10;}&#10;</code></pre>
<h3 id="class-instance-properties">Class instance properties</h3>
<p>When you send an instance of an application-defined class, the recipient can only access methods and properties declared on the class, not properties of the instance. For example:</p>
<pre><code class="language-js">class Foo extends RpcTarget {&#10;  constructor() {&#10;    super();&#10;&#10;    // i CANNOT be accessed over RPC&#10;    this.i = 0;&#10;&#10;    // funcProp CANNOT be called over RPC&#10;    this.funcProp = () =&gt; {}&#10;  }&#10;&#10;  // value CAN be accessed over RPC&#10;  get value() {&#10;    return this.i;&#10;  }&#10;&#10;  // method CAN be called over RPC&#10;  method() {}&#10;}&#10;</code></pre>
<p>This behavior is intentional — it is intended to protect you from accidentally exposing private class internals. Generally, instance properties should be declared private, <a href="https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Classes/Private_properties">by prefixing them with <code>#</code></a>. However, private properties are a relatively new feature of JavaScript, and are not yet widely used in the ecosystem.</p>
<p>Since the RPC interface between two of your Workers may be a security boundary, we need to be extra-careful, so instance properties are always private when communicating between Workers using RPC, whether or not they have the <code>#</code> prefix. You can always declare an explicit getter at the class level if you wish to expose the property, as shown above.</p>
<p>These visibility rules apply only to objects that extend <code>RpcTarget</code>, <code>WorkerEntrypoint</code>, or <code>DurableObject</code>, and do not apply to plain objects. Plain objects are passed &quot;by value&quot;, sending all of their &quot;own&quot; properties.</p>
<h3 id="own-properties-of-functions">&quot;Own&quot; properties of functions</h3>
<p>When you pass a function over RPC, the caller can access the &quot;own&quot; properties of the function object itself.</p>
<pre><code class="language-js">someRpcMethod() {&#10;  let func = () =&gt; {};&#10;  func.prop = 123;  // `prop` is visible over RPC&#10;  return func;&#10;}&#10;</code></pre>
<p>Such properties on a function are accessed asynchronously, like class properties of an RpcTarget. But, unlike the <code>RpcTarget</code> example above, the function's instance properties that are accessible to the caller. In practice, properties are rarely added to functions.</p>
