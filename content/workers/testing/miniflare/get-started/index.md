<p>The Miniflare API allows you to dispatch events to workers without making actual HTTP requests, simulate connections between Workers, and interact with local emulations of storage products like <a href="/workers/testing/miniflare/storage/kv">KV</a>, <a href="/workers/testing/miniflare/storage/r2">R2</a>, and <a href="/workers/testing/miniflare/storage/durable-objects">Durable Objects</a>. This makes it great for writing tests, or other advanced use cases where you need finer-grained control.</p>

<h2 id="usage">Usage</h2>
<p>In all future examples, we'll assume Node.js is running in ES module mode. You
can do this by setting the <code>type</code> field in your <code>package.json</code>:</p>
<pre><code class="language-json">{&#10;	...&#10;	&quot;type&quot;: &quot;module&quot;&#10;	...&#10;}&#10;</code></pre>
<p>To initialise Miniflare, import the <code>Miniflare</code> class from <code>miniflare</code>:</p>
<pre><code class="language-js">import { Miniflare } from &quot;miniflare&quot;;&#10;&#10;const mf = new Miniflare({&#10;	modules: true,&#10;	script: `&#10;  export default {&#10;    async fetch(request, env, ctx) {&#10;      return new Response(&quot;Hello Miniflare!&quot;);&#10;    }&#10;  }&#10;  `,&#10;});&#10;&#10;const res = await mf.dispatchFetch(&quot;http://localhost:8787/&quot;);&#10;console.log(await res.text()); // Hello Miniflare!&#10;await mf.dispose();&#10;</code></pre>
<p>The <a href="/workers/testing/miniflare/core/fetch">rest of these docs</a> go into more detail on configuring
specific features.</p>
<h3 id="string-and-file-scripts">String and File Scripts</h3>
<p>Note in the above example we're specifying <code>script</code> as a string. We could've
equally put the script in a file such as <code>worker.js</code>, then used the <code>scriptPath</code>
property instead:</p>
<pre><code class="language-js">const mf = new Miniflare({&#10;	scriptPath: &quot;worker.js&quot;,&#10;});&#10;</code></pre>
<h3 id="watching-reloading-and-disposing">Watching, Reloading and Disposing</h3>
<p>Miniflare's API is primarily intended for testing use cases, where file watching isn't usually required. If you need to watch files, consider using a separate file watcher like <a href="https://nodejs.org/api/fs.html#fswatchfilename-options-listener">fs.watch()</a> or <a href="https://github.com/paulmillr/chokidar">chokidar</a>, and calling setOptions() with your original configuration on change.</p>
<p>To cleanup and stop listening for requests, you should <code>dispose()</code> your instances:</p>
<pre><code class="language-js">await mf.dispose();&#10;</code></pre>
<p>You can also manually reload scripts (main and Durable Objects') and options by calling <code>setOptions()</code> with the original configuration object.</p>
<h3 id="updating-options-and-the-global-scope">Updating Options and the Global Scope</h3>
<p>You can use the <code>setOptions</code> method to update the options of an existing
<code>Miniflare</code> instance. This accepts the same options object as the
<code>new Miniflare</code> constructor, applies those options, then reloads the worker.</p>
<pre><code class="language-js">const mf = new Miniflare({&#10;	script: &quot;...&quot;,&#10;	kvNamespaces: [&quot;TEST_NAMESPACE&quot;],&#10;	bindings: { KEY: &quot;value1&quot; },&#10;});&#10;&#10;await mf.setOptions({&#10;	script: &quot;...&quot;,&#10;	kvNamespaces: [&quot;TEST_NAMESPACE&quot;],&#10;	bindings: { KEY: &quot;value2&quot; },&#10;});&#10;</code></pre>
<h3 id="dispatching-events">Dispatching Events</h3>
<p><code>getWorker</code> dispatches <code>fetch</code>, <code>queues</code>, and <code>scheduled</code> events
to workers respectively:</p>
<pre><code class="language-js">import { Miniflare } from &quot;miniflare&quot;;&#10;&#10;const mf = new Miniflare({&#10;	modules: true,&#10;	script: `&#10;	let lastScheduledController;&#10;	let lastQueueBatch;&#10;	export default {&#10;		async fetch(request, env, ctx) {&#10;			const { pathname } = new URL(request.url);&#10;			if (pathname === &quot;/scheduled&quot;) {&#10;				return Response.json({&#10;					scheduledTime: lastScheduledController?.scheduledTime,&#10;					cron: lastScheduledController?.cron,&#10;				});&#10;			} else if (pathname === &quot;/queue&quot;) {&#10;				return Response.json({&#10;					queue: lastQueueBatch.queue,&#10;					messages: lastQueueBatch.messages.map((message) =&gt; ({&#10;					id: message.id,&#10;					timestamp: message.timestamp.getTime(),&#10;					body: message.body,&#10;					bodyType: message.body.constructor.name,&#10;					})),&#10;				});&#10;			} else if (pathname === &quot;/get-url&quot;) {&#10;				return new Response(request.url);&#10;			} else {&#10;				return new Response(null, { status: 404 });&#10;			}&#10;		},&#10;		async scheduled(controller, env, ctx) {&#10;			lastScheduledController = controller;&#10;			if (controller.cron === &quot;* * * * *&quot;) controller.noRetry();&#10;		},&#10;		async queue(batch, env, ctx) {&#10;			lastQueueBatch = batch;&#10;			if (batch.queue === &quot;needy&quot;) batch.retryAll();&#10;			for (const message of batch.messages) {&#10;				if (message.id === &quot;perfect&quot;) message.ack();&#10;			}&#10;		}&#10;	}`,&#10;});&#10;&#10;const res = await mf.dispatchFetch(&quot;http://localhost:8787/&quot;, {&#10;	headers: { &quot;X-Message&quot;: &quot;Hello Miniflare!&quot; },&#10;});&#10;console.log(await res.text()); // Hello Miniflare!&#10;&#10;const worker = await mf.getWorker();&#10;&#10;const scheduledResult = await worker.scheduled({&#10;	cron: &quot;* * * * *&quot;,&#10;});&#10;console.log(scheduledResult); // { outcome: &quot;ok&quot;, noRetry: true });&#10;&#10;const queueResult = await worker.queue(&quot;needy&quot;, [&#10;	{ id: &quot;a&quot;, timestamp: new Date(1000), body: &quot;a&quot;, attempts: 1 },&#10;	{ id: &quot;b&quot;, timestamp: new Date(2000), body: { b: 1 }, attempts: 1 },&#10;]);&#10;console.log(queueResult); // { outcome: &quot;ok&quot;, retryAll: true, ackAll: false, explicitRetries: [], explicitAcks: []}&#10;</code></pre>
<p>See <a href="/workers/testing/miniflare/core/fetch">📨 Fetch Events</a> and <a href="/workers/testing/miniflare/core/scheduled">⏰ Scheduled Events</a>
for more details.</p>
<h3 id="http-server">HTTP Server</h3>
<p>Miniflare starts an HTTP server automatically. To wait for it to be ready, <code>await</code> the <code>ready</code> property:</p>
<pre><code class="language-js">import { Miniflare } from &quot;miniflare&quot;;&#10;&#10;const mf = new Miniflare({&#10;	modules: true,&#10;	script: `&#10;  export default {&#10;    async fetch(request, env, ctx) {&#10;      return new Response(&quot;Hello Miniflare!&quot;);&#10;    })&#10;  }&#10;  `,&#10;	port: 5000,&#10;});&#10;await mf.ready;&#10;console.log(&quot;Listening on :5000&quot;);&#10;</code></pre>
<h4 id="request-cf-object"><code>Request#cf</code> Object</h4>
<p>By default, Miniflare will fetch the <code>Request#cf</code> object from a trusted
Cloudflare endpoint and cache it to <code>node_modules/.mf/cf.json</code>. You can disable this behaviour, using the <code>cf</code> option:</p>
<pre><code class="language-js">const mf = new Miniflare({&#10;	cf: false,&#10;});&#10;</code></pre>
<p>You can also provide a custom cf object via a filepath:</p>
<pre><code class="language-js">const mf = new Miniflare({&#10;	cf: &quot;cf.json&quot;,&#10;});&#10;</code></pre>
<p>You can also control this behaviour using <a href="/workers/wrangler/system-environment-variables/">system environment variables</a>, which is useful when you are not using the Miniflare API directly (for example, when running <code>wrangler dev</code>):</p>
<pre><code class="language-sh">&#35; Disable cf fetching entirely (uses fallback data)&#10;export CLOUDFLARE_CF_FETCH_ENABLED=false&#10;npx wrangler dev&#10;&#10;&#35; Use a custom cache location for cf.json&#10;export CLOUDFLARE_CF_FETCH_PATH=/tmp/.cf-cache.json&#10;npx wrangler dev&#10;</code></pre>
<p>The explicit <code>cf</code> option in the Miniflare API takes precedence over both environment variables.</p>
<h3 id="https-server">HTTPS Server</h3>
<p>To start an HTTPS server instead, set the <code>https</code> option. To use the <a href="https://github.com/cloudflare/workers-sdk/tree/main/packages/miniflare/src/http/cert.ts">default shared self-signed certificate</a>, set <code>https</code> to <code>true</code>:</p>
<pre><code class="language-js">const mf = new Miniflare({&#10;	https: true,&#10;});&#10;</code></pre>
<p>To load an existing certificate from the file system:</p>
<pre><code class="language-js">const mf = new Miniflare({&#10;	// These are all optional, you don&#x27;t need to include them all&#10;	httpsKeyPath: &quot;./key.pem&quot;,&#10;	httpsCertPath: &quot;./cert.pem&quot;,&#10;});&#10;</code></pre>
<p>To load an existing certificate from strings instead:</p>
<pre><code class="language-js">const mf = new Miniflare({&#10;	// These are all optional, you don&#x27;t need to include them all&#10;	httpsKey: &quot;-----BEGIN RSA PRIVATE KEY-----...&quot;,&#10;	httpsCert: &quot;-----BEGIN CERTIFICATE-----...&quot;,&#10;});&#10;</code></pre>
<p>If both a string and path are specified for an option (e.g. <code>httpsKey</code> and
<code>httpsKeyPath</code>), the string will be preferred.</p>
<h3 id="logging">Logging</h3>
<p>By default, <code>[mf:*]</code> logs are disabled when using the API. To
enable these, set the <code>log</code> property to an instance of the <code>Log</code> class. Its only
parameter is a log level indicating which messages should be logged:</p>
<pre><code class="language-js">import { Miniflare, Log, LogLevel } from &quot;miniflare&quot;;&#10;&#10;const mf = new Miniflare({&#10;	scriptPath: &quot;worker.js&quot;,&#10;	log: new Log(LogLevel.DEBUG), // Enable debug messages&#10;});&#10;</code></pre>
