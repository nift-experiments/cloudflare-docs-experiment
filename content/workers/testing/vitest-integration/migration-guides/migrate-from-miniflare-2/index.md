<p><a href="https://github.com/cloudflare/miniflare?tab=readme-ov-file">Miniflare 2</a> provided custom environments for Jest and Vitest in the <code>jest-environment-miniflare</code> and <code>vitest-environment-miniflare</code> packages respectively.
The <code>@cloudflare/vitest-plugin</code> package provides similar functionality using modern Miniflare versions and the <a href="https://github.com/cloudflare/workerd"><code>workerd</code> runtime</a>. <code>workerd</code> is the same JavaScript/WebAssembly runtime that powers Cloudflare Workers. Using <code>workerd</code> reduces behavior mismatches between your tests and deployed code. Refer to the <a href="https://blog.cloudflare.com/miniflare-and-workerd">Miniflare 3 announcement</a> for more information.</p>

<h2 id="install-the-workers-vitest-integration">Install the Workers Vitest integration</h2>
<p>First, uninstall the old environment and install the Vitest plugin. Vitest environments can only customize the global scope, whereas the plugin runs tests using a different runtime. In this case, the plugin runs your tests inside <a href="https://github.com/cloudflare/workerd"><code>workerd</code></a> instead of Node.js.</p>
<pre tabindex="0"><code class="language-sh">npm uninstall vitest-environment-miniflare&#10;npm install --save-dev vitest@^4.1.0&#10;npm install --save-dev @cloudflare/vitest-plugin&#10;</code></pre>
<h2 id="update-your-vitest-configuration-file">Update your Vitest configuration file</h2>
<p>After installing the Workers Vitest integration, update your Vitest configuration file to use the <code>cloudflareTest()</code> Vite plugin instead. Most Miniflare configuration previously specified in <code>environmentOptions</code> can be moved to the <code>miniflare</code> option in <code>cloudflareTest()</code>. Refer to <a href="https://github.com/cloudflare/workers-sdk/blob/main/packages/miniflare/README.md#interface-workeroptions">Miniflare's <code>WorkerOptions</code> interface</a> for supported options and the <a href="/workers/testing/miniflare/migrations/from-v2/">Miniflare version 2 to 3 migration guide</a> for more information. If you relied on configuration stored in a Wrangler file, set <code>wrangler.configPath</code> too.</p>
<pre tabindex="0"><code class="language-diff">&#43; import { cloudflareTest } from &quot;@cloudflare/vitest-plugin&quot;;&#10;&#43; import { defineConfig } from &quot;vitest/config&quot;;&#10;&#10;&#45; export default defineWorkersConfig({&#10;&#45;   test: {&#10;&#45;     environment: &quot;miniflare&quot;,&#10;&#45;     environmentOptions: { ... },&#10;&#45;   },&#10;&#45; });&#10;&#43; export default defineConfig({&#10;&#43;   plugins: [&#10;&#43;     cloudflareTest({&#10;&#43;       miniflare: { ... },&#10;&#43;       wrangler: { configPath: &quot;./wrangler.jsonc&quot; },&#10;&#43;     }),&#10;&#43;   ],&#10;&#43; });&#10;</code></pre>
<h2 id="update-your-typescript-configuration-file">Update your TypeScript configuration file</h2>
<p>If you are using TypeScript, update your <code>tsconfig.json</code> to include the correct ambient <code>types</code>:</p>
<pre tabindex="0"><code class="language-diff">  {&#10;    &quot;compilerOptions&quot;: {&#10;      ...,&#10;      &quot;types&quot;: [&#10;				...&#10;&#45;       &quot;vitest-environment-miniflare/globals&quot;&#10;&#43;       &quot;@cloudflare/vitest-plugin/types&quot;&#10;      ]&#10;    },&#10;  }&#10;</code></pre>
<h2 id="access-bindings">Access bindings</h2>
<p>To access <a href="/workers/runtime-apis/bindings/">bindings</a> in your tests, use the <code>env</code> helper from the <code>cloudflare:workers</code> module.</p>
<pre tabindex="0"><code class="language-diff">  import { it } from &quot;vitest&quot;;&#10;&#43; import { env } from &quot;cloudflare:workers&quot;;&#10;&#10;  it(&quot;does something&quot;, () =&gt; {&#10;&#45;   const env = getMiniflareBindings();&#10;    // ...&#10;  });&#10;</code></pre>
<p>If you are using TypeScript, you need to define the type of <code>env</code> for your tests. Refer to <a href="/workers/testing/vitest-integration/write-your-first-test/#define-types">Define types</a> for setup instructions.</p>
<h2 id="storage-isolation">Storage isolation</h2>
<p>Storage isolation is per test file by default. You no longer need to include <code>setupMiniflareIsolatedStorage()</code> in your tests.</p>
<pre tabindex="0"><code class="language-diff">&#45; const describe = setupMiniflareIsolatedStorage();&#10;&#43; import { describe } from &quot;vitest&quot;;&#10;</code></pre>
<h2 id="work-with-waituntil">Work with <code>waitUntil()</code></h2>
<p>The <code>new ExecutionContext()</code> constructor and <code>getMiniflareWaitUntil()</code> function are now <code>createExecutionContext()</code> and <code>waitOnExecutionContext()</code> respectively. Note <code>waitOnExecutionContext()</code> now returns an empty <code>Promise&lt;void&gt;</code> instead of a <code>Promise</code> resolving to the results of all <code>waitUntil()</code>ed <code>Promise</code>s.</p>
<pre tabindex="0"><code class="language-diff">&#43; import { createExecutionContext, waitOnExecutionContext } from &quot;cloudflare:test&quot;;&#10;&#10;  it(&quot;does something&quot;, () =&gt; {&#10;    // ...&#10;&#45;   const ctx = new ExecutionContext();&#10;&#43;   const ctx = createExecutionContext();&#10;    const response = worker.fetch(request, env, ctx);&#10;&#45;   await getMiniflareWaitUntil(ctx);&#10;&#43;   await waitOnExecutionContext(ctx);&#10;  });&#10;</code></pre>
<h2 id="mock-outbound-requests">Mock outbound requests</h2>
<p>The <code>getMiniflareFetchMock()</code> function is no longer available. To mock outbound requests, use <a href="https://github.com/mswjs/cloudflare"><code>@msw/cloudflare</code></a>. Refer to <a href="/workers/testing/vitest-integration/mock-outbound-requests/">Mock outbound requests</a> for setup instructions.</p>
<h2 id="use-durable-object-helpers">Use Durable Object helpers</h2>
<p>The <code>getMiniflareDurableObjectStorage()</code>, <code>getMiniflareDurableObjectState()</code>, <code>getMiniflareDurableObjectInstance()</code>, and <code>runWithMiniflareDurableObjectGates()</code> functions have all been replaced with a single <code>runInDurableObject()</code> function from the <code>cloudflare:test</code> module. The <code>runInDurableObject()</code> function accepts a <code>DurableObjectStub</code> with a callback accepting the Durable Object and corresponding <code>DurableObjectState</code> as arguments. Consolidating these functions into a single function simplifies the API surface, and ensures instances are accessed with the correct request context and <a href="https://blog.cloudflare.com/durable-objects-easy-fast-correct-choose-three/">gating behavior</a>. Refer to the <a href="/workers/testing/vitest-integration/test-apis/">Test APIs page</a> for more details.</p>
<pre tabindex="0"><code class="language-diff">&#43; import { env } from &quot;cloudflare:workers&quot;;&#10;&#43; import { runInDurableObject } from &quot;cloudflare:test&quot;;&#10;&#10;  it(&quot;does something&quot;, async () =&gt; {&#10;&#45;   const env = getMiniflareBindings();&#10;    const id = env.OBJECT.newUniqueId();&#10;&#43;   const stub = env.OBJECT.get(id);&#10;&#10;&#45;   const storage = await getMiniflareDurableObjectStorage(id);&#10;&#45;   doSomethingWith(storage);&#10;&#43;   await runInDurableObject(stub, async (instance, state) =&gt; {&#10;&#43;     doSomethingWith(state.storage);&#10;&#43;   });&#10;&#10;&#45;   const state = await getMiniflareDurableObjectState(id);&#10;&#45;   doSomethingWith(state);&#10;&#43;   await runInDurableObject(stub, async (instance, state) =&gt; {&#10;&#43;     doSomethingWith(state);&#10;&#43;   });&#10;&#10;&#45;   const instance = await getMiniflareDurableObjectInstance(id);&#10;&#45;   await runWithMiniflareDurableObjectGates(state, async () =&gt; {&#10;&#45;     doSomethingWith(instance);&#10;&#45;   });&#10;&#43;   await runInDurableObject(stub, async (instance) =&gt; {&#10;&#43;     doSomethingWith(instance);&#10;&#43;   });&#10;  });&#10;</code></pre>
<p>The <code>flushMiniflareDurableObjectAlarms()</code> function has been replaced with the <code>runDurableObjectAlarm()</code> function from the <code>cloudflare:test</code> module. The <code>runDurableObjectAlarm()</code> function accepts a single <code>DurableObjectStub</code> and returns a <code>Promise</code> that resolves to <code>true</code> if an alarm was scheduled and the <code>alarm()</code> handler was executed, or <code>false</code> otherwise. To &quot;flush&quot; multiple instances' alarms, call <code>runDurableObjectAlarm()</code> in a loop.</p>
<pre tabindex="0"><code class="language-diff">&#43; import { env } from &quot;cloudflare:workers&quot;;&#10;&#43; import { runDurableObjectAlarm } from &quot;cloudflare:test&quot;;&#10;&#10;  it(&quot;does something&quot;, async () =&gt; {&#10;&#45;   const env = getMiniflareBindings();&#10;    const id = env.OBJECT.newUniqueId();&#10;&#45;   await flushMiniflareDurableObjectAlarms([id]);&#10;&#43;   const stub = env.OBJECT.get(id);&#10;&#43;   const ran = await runDurableObjectAlarm(stub);&#10;  });&#10;</code></pre>
<p>Finally, the <code>getMiniflareDurableObjectIds()</code> function has been replaced with the <code>listDurableObjectIds()</code> function from the <code>cloudflare:test</code> module. The <code>listDurableObjectIds()</code> function now accepts a <code>DurableObjectNamespace</code> instance instead of a namespace <code>string</code> to provide stricter typing. Note the <code>listDurableObjectIds()</code> function respects storage isolation. IDs of objects created in other test files will not be returned.</p>
<pre tabindex="0"><code class="language-diff">&#43; import { env } from &quot;cloudflare:workers&quot;;&#10;&#43; import { listDurableObjectIds } from &quot;cloudflare:test&quot;;&#10;&#10;  it(&quot;does something&quot;, async () =&gt; {&#10;&#45;   const ids = await getMiniflareDurableObjectIds(&quot;OBJECT&quot;);&#10;&#43;   const ids = await listDurableObjectIds(env.OBJECT);&#10;  });&#10;</code></pre>
