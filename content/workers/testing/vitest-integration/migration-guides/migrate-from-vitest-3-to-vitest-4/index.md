<p><code>@cloudflare/vitest-pool-workers</code> v0.13.0 adds support for <a href="https://vitest.dev/blog/vitest-4">Vitest 4</a>. v0.12.x is the last version to support Vitest 3.x. It continues to work if you are not ready to migrate.</p>
<aside class="nb-aside note">
@markup("md", "content/.markup/bodies/17368.md")
</aside>
<p>Version 0.13.0 rearchitects the integration around a Vite plugin model. This change breaks the configuration API, but it also resolves a number of issues that were not fixable under the previous architecture:</p>
<ul>
<li>Library imports that previously required SSR optimizer workarounds, such as Stripe, now resolve without extra configuration.</li>
<li>Bare Node.js specifiers such as <code>node:url</code> now resolve in test files.</li>
<li><code>nodejs_compat_v2</code> and Node.js module flags are enabled automatically during tests, matching production behavior.</li>
<li>The <code>provide</code> data channel is no longer limited to ~8 KB. It now uses WebSocket messages.</li>
<li>Storage is isolated per test file instead of per test, consistent with standard Vitest behavior.</li>
<li>The Vitest UI works correctly with Workers tests.</li>
</ul>
<p>This guide covers migrating an existing project from v0.12.x to v0.13.x.</p>

<h2 id="review-the-configuration-changes">Review the configuration changes</h2>
<p><code>defineWorkersProject</code> and <code>defineWorkersConfig</code> from <code>@cloudflare/vitest-pool-workers/config</code> have both been removed. They are replaced by a <code>cloudflareTest()</code> Vite plugin exported from <code>@cloudflare/vitest-pool-workers</code>, with options previously nested under <code>test.poolOptions.workers</code> passed directly to <code>cloudflareTest()</code>.</p>
<p>The codemod migrates configurations that use <code>defineWorkersProject</code>. If your configuration uses <code>defineWorkersConfig</code>, or calls <code>defineWorkersProject</code> with a function instead of an object, the codemod cannot transform it. Apply the change manually using the following example.</p>
<p>Before:</p>
<pre><code class="language-ts">import { defineWorkersProject } from &quot;@cloudflare/vitest-pool-workers/config&quot;;&#10;&#10;export default defineWorkersProject({&#10;	test: {&#10;		poolOptions: {&#10;			workers: {&#10;				wrangler: { configPath: &quot;./wrangler.jsonc&quot; },&#10;			},&#10;		},&#10;	},&#10;});&#10;</code></pre>
<p>After:</p>
<pre><code class="language-ts">import { cloudflareTest } from &quot;@cloudflare/vitest-pool-workers&quot;;&#10;import { defineConfig } from &quot;vitest/config&quot;;&#10;&#10;export default defineConfig({&#10;	plugins: [&#10;		cloudflareTest({&#10;			wrangler: { configPath: &quot;./wrangler.jsonc&quot; },&#10;		}),&#10;	],&#10;});&#10;</code></pre>
<h3 id="remove-isolatedstorage-and-singleworker">Remove <code>isolatedStorage</code> and <code>singleWorker</code></h3>
<p>The <code>isolatedStorage</code> and <code>singleWorker</code> options have been removed. Storage isolation is now per test file, matching Vitest's own isolation model. The codemod copies your existing <code>test.poolOptions.workers</code> options into <code>cloudflareTest()</code>, so if you previously set either option, remove it from the <code>cloudflareTest()</code> call. To make test files share the same storage instead, pass the <code>--max-workers=1 --no-isolate</code> flags to the Vitest command in your <code>package.json</code>.</p>
<h2 id="update-your-test-files">Update your test files</h2>
<p>The following changes must be made manually to your test files.</p>
<h3 id="update-deprecated-cloudflare-test-imports">Update deprecated <code>cloudflare:test</code> imports</h3>
<p>The <code>env</code> and <code>SELF</code> exports from <code>cloudflare:test</code> are deprecated in favor of <code>cloudflare:workers</code>. Replace <code>import { env, SELF } from &quot;cloudflare:test&quot;</code> with <code>import { env, exports } from &quot;cloudflare:workers&quot;</code>. <code>exports.default.fetch()</code> behaves the same as <code>SELF.fetch()</code>, except that it does not expose Assets. To test Assets, use the <code>env.ASSETS</code> binding or write an integration test using <a href="/workers/testing/unstable_startworker/"><code>startDevWorker()</code></a>. The deprecated exports still work, so this change is recommended rather than required.</p>
<pre><code class="language-diff">&#45; import { env, SELF } from &quot;cloudflare:test&quot;;&#10;&#43; import { env, exports } from &quot;cloudflare:workers&quot;;&#10;&#10;  it(&quot;dispatches fetch event&quot;, async () =&gt; {&#10;&#45;   const response = await SELF.fetch(&quot;https://example.com&quot;);&#10;&#43;   const response = await exports.default.fetch(&quot;https://example.com&quot;);&#10;  });&#10;</code></pre>
<h3 id="replace-fetchmock">Replace fetchMock</h3>
<p>The <code>import { fetchMock } from &quot;cloudflare:test&quot;</code> import has been removed. Mock <code>globalThis.fetch</code> directly or use ecosystem libraries such as <a href="https://mswjs.io/">MSW</a>. Refer to the <a href="https://github.com/cloudflare/workers-sdk/blob/1aee99059d6025c7ea8ef88b3ea421922eee6354/fixtures/vitest-pool-workers-examples/request-mocking/test/imperative.test.ts">request mocking example</a> for a complete example.</p>
