<p>In this tutorial, you will build a <a href="https://slack.com">Slack</a> bot using <a href="/workers/">Cloudflare Workers</a>. Your bot will make use of GitHub webhooks to send messages to a Slack channel when issues are updated or created, and allow users to write a command to look up GitHub issues from inside Slack.</p>
<p><img src="/assets/upstream/images/workers/tutorials/slackbot/issue-command.png" alt="After following this tutorial, you will be able to create a Slackbot like the one in this example. Continue reading to build your Slackbot." /></p>
<p>This tutorial is recommended for people who are familiar with writing web applications. You will use TypeScript as the programming language and <a href="https://hono.dev/">Hono</a> as the web framework. If you have built an application with tools like <a href="https://nodejs.org">Node</a> and <a href="https://expressjs.com">Express</a>, this project will feel very familiar to you. If you are new to writing web applications or have wanted to build something like a Slack bot in the past, but were intimidated by deployment or configuration, Workers will be a way for you to focus on writing code and shipping projects.</p>
<p>If you would like to review the code or how the bot works in an actual Slack channel before proceeding with this tutorial, you can access the final version of the codebase <a href="https://github.com/yusukebe/workers-slack-bot">on GitHub</a>. From GitHub, you can add your own Slack API keys and deploy it to your own Slack channels for testing.</p>

<h3 id="configure-a-slack-application">Configure a Slack application</h3>
<p>To post messages from your Cloudflare Worker into a Slack channel, you will need to create an application in Slack’s UI. To do this, go to Slack’s API section, at <a href="https://api.slack.com/apps">api.slack.com/apps</a>, and select <strong>Create New App</strong>.</p>
<p><img src="/assets/upstream/images/workers/tutorials/slackbot/create-a-slack-app.png" alt="To create a Slackbot, first create a Slack App" /></p>
<p>Slack applications have many features. You will make use of two of them, Incoming Webhooks and Slash Commands, to build your Worker-powered Slack bot.</p>
<h4 id="incoming-webhook">Incoming Webhook</h4>
<p>Incoming Webhooks are URLs that you can use to send messages to your Slack channels. Your incoming webhook will be paired with GitHub’s webhook support to send messages to a Slack channel whenever there are updates to issues in a given repository. You will see the code in more detail as you build your application. First, create a Slack webhook:</p>
<ol>
<li>On the sidebar of Slack's UI, select <strong>Incoming Webhooks</strong>.</li>
<li>In <strong>Webhook URLs for your Workspace</strong>, select <strong>Add New Webhook to Workspace</strong>.</li>
<li>On the following screen, select the channel that you want your webhook to send messages to (you can select a room, like #general or #code, or be messaged directly by your Slack bot when the webhook is called.)</li>
<li>Authorize the new webhook URL.</li>
</ol>
<p>After authorizing your webhook URL, you will be returned to the <strong>Incoming Webhooks</strong> page and can view your new webhook URL. You will add this into your Workers code later. Next, you will add the second component to your Slack bot: a Slash Command.</p>
<p><img src="/assets/upstream/images/workers/tutorials/slackbot/slack-incoming-webhook.png" alt="Select Add New Webhook to Workspace to add a new Webhook URL in Slack's dashboard" /></p>
<h4 id="slash-command">Slash Command</h4>
<p>A Slash Command in Slack is a custom-configured command that can be attached to a URL request. For example, if you configured <code>/weather &lt;zip&gt;</code>, Slack would make an HTTP POST request to a configured URL, passing the text <code>&lt;zip&gt;</code> to get the weather for a specified zip code. In your application, you will use the <code>/issue</code> command to look up GitHub issues using the <a href="https://developer.github.com">GitHub API</a>. Typing <code>/issue cloudflare/wrangler#1</code> will send the text <code>cloudflare/wrangler#1</code> in a HTTP POST request to your application, which the application will use to find the <a href="https://github.com/cloudflare/wrangler-legacy/issues/1">relevant GitHub issue</a>.</p>
<ol>
<li>On the Slack sidebar, select <strong>Slash Commands</strong>.</li>
<li>Create your first slash command.</li>
</ol>
<p>For this tutorial, you will use the command <code>/issue</code>. The request URL should be the <code>/lookup</code> path on your application URL: for example, if your application will be hosted at <code>https://myworkerurl.com</code>, the Request URL should be <code>https://myworkerurl.com/lookup</code>.</p>
<p><img src="/assets/upstream/images/workers/tutorials/slackbot/create-slack-command.png" alt="You must create a Slash Command in Slack's dashboard and attach it to a Request URL" /></p>
<h3 id="configure-your-github-webhooks">Configure your GitHub Webhooks</h3>
<p>Your Cloudflare Workers application will be able to handle incoming requests from Slack. It should also be able to receive events directly from GitHub. If a GitHub issue is created or updated, you can make use of GitHub webhooks to send that event to your Workers application and post a corresponding message in Slack.</p>
<p>To configure a webhook:</p>
<ol>
<li>Go to your GitHub repository's <strong>Settings</strong> &gt; <strong>Webhooks</strong> &gt; <strong>Add webhook</strong>.</li>
</ol>
<p>If you have a repository like <code>https://github.com/user/repo</code>, you can access the <strong>Webhooks</strong> page directly at <code>https://github.com/user/repo/settings/hooks</code>.</p>
<ol start="2">
<li>Set the Payload URL to the <code>/webhook</code> path on your Worker URL.</li>
</ol>
<p>For example, if your Worker will be hosted at <code>https://myworkerurl.com</code>, the Payload URL should be <code>https://myworkerurl.com/webhook</code>.</p>
<ol start="3">
<li>In the <strong>Content type</strong> dropdown, select <strong>application/json</strong>.</li>
</ol>
<p>The <strong>Content type</strong> for your payload can either be a URL-encoded payload (<code>application/x-www-form-urlencoded</code>) or JSON (<code>application/json</code>). For the purpose of this tutorial and to make parsing the payload sent to your application, select JSON.</p>
<ol start="4">
<li>In <strong>Which events would you like to trigger this webhook?</strong>, select <strong>Let me select individual events</strong>.</li>
</ol>
<p>GitHub webhooks allow you to specify which events you would like to have sent to your webhook. By default, the webhook will send <code>push</code> events from your repository. For the purpose of this tutorial, you will choose <strong>Let me select individual events</strong>.</p>
<ol start="5">
<li>Select the <strong>Issues</strong> event type.</li>
</ol>
<p>There are many different event types that can be enabled for your webhook. Selecting <strong>Issues</strong> will send every issue-related event to your webhook, including when issues are opened, edited, deleted, and more. If you would like to expand your Slack bot application in the future, you can select more of these events after the tutorial.</p>
<ol start="6">
<li>Select <strong>Add webhook</strong>.</li>
</ol>
<p><img src="/assets/upstream/images/workers/tutorials/slackbot/new-github-webhook.png" alt="Create a GitHub Webhook in the GitHub dashboard" /></p>
<p>When your webhook is created, it will attempt to send a test payload to your application. Since your application is not actually deployed yet, leave the configuration as it is. You will later return to your repository to create, edit, and close some issues to ensure that the webhook is working once your application is deployed.</p>

<h3 id="separating-files">Separating files</h3>
<p>You can create your application in several files instead of writing all endpoints and functions in one file. With Hono, it is able to add routing of child applications to the parent application using the function <code>app.route()</code>.</p>
<p>For example, imagine the following Web API application.</p>
<pre><code class="language-ts">import { Hono } from &quot;hono&quot;;&#10;&#10;const app = new Hono();&#10;&#10;app.get(&quot;/posts&quot;, (c) =&gt; c.text(&quot;Posts!&quot;));&#10;app.post(&quot;/posts&quot;, (c) =&gt; c.text(&quot;Created!&quot;, 201));&#10;&#10;export default app;&#10;</code></pre>
<p>You can add the routes under <code>/api/v1</code>.</p>
<pre><code class="language-ts">import { Hono } from &quot;hono&quot;;&#10;import api from &quot;./api&quot;;&#10;&#10;const app = new Hono();&#10;&#10;app.route(&quot;/api/v1&quot;, api);&#10;&#10;export default app;&#10;</code></pre>
<p>It will return <code>Posts!</code> when accessing <code>GET /api/v1/posts</code>.</p>
<p>The Slack bot will have two child applications called &quot;route&quot; each.</p>
<ol>
<li>
<p><code>lookup</code> route will take requests from Slack (sent when a user uses the <code>/issue</code> command), and look up the corresponding issue using the GitHub API. This application will be added to <code>/lookup</code> in the main application.</p>
</li>
<li>
<p><code>webhook</code> route will be called when an issue changes on GitHub, via a configured webhook. This application will be add to <code>/webhook</code> in the main application.</p>
</li>
</ol>
<p>Create the route files in a directory named <code>routes</code>.</p>
<pre><code class="language-sh">mkdir -p src/routes&#10;touch src/routes/lookup.ts&#10;touch src/routes/webhook.ts&#10;</code></pre>
<p>Then update the main application.</p>
<pre><code class="language-ts">import { Hono } from &quot;hono&quot;;&#10;import lookup from &quot;./routes/lookup&quot;;&#10;import webhook from &quot;./routes/webhook&quot;;&#10;&#10;const app = new Hono();&#10;&#10;app.route(&quot;/lookup&quot;, lookup);&#10;app.route(&quot;/webhook&quot;, webhook);&#10;&#10;export default app;&#10;</code></pre>
<h3 id="defining-typescript-types">Defining TypeScript types</h3>
<p>Before implementing the actual functions, you need to define the TypeScript types you will use in this project. Create a new file in the application at <code>src/types.ts</code> and write the code. <code>Bindings</code> is a type that describes the Cloudflare Workers environment variables. <code>Issue</code> is a type for a GitHub issue and <code>User</code> is a type for a GitHub user. You will need these later.</p>
<pre><code class="language-ts">export type Bindings = {&#10;	SLACK_WEBHOOK_URL: string;&#10;};&#10;&#10;export type Issue = {&#10;	html_url: string;&#10;	title: string;&#10;	body: string;&#10;	state: string;&#10;	created_at: string;&#10;	number: number;&#10;	user: User;&#10;};&#10;&#10;type User = {&#10;	html_url: string;&#10;	login: string;&#10;	avatar_url: string;&#10;};&#10;</code></pre>
<h3 id="creating-the-lookup-route">Creating the lookup route</h3>
<p>Start creating the lookup route in <code>src/routes/lookup.ts</code>.</p>
<pre><code class="language-ts">import { Hono } from &quot;hono&quot;;&#10;&#10;const app = new Hono();&#10;&#10;export default app;&#10;</code></pre>
<p>To understand how you should design this function, you need to understand how Slack slash commands send data to URLs.</p>
<p>According to the <a href="https://api.slack.com/interactivity/slash-commands">documentation for Slack slash commands</a>, Slack sends an HTTP POST request to your specified URL, with a <code>application/x-www-form-urlencoded</code> content type. For example, if someone were to type <code>/issue cloudflare/wrangler#1</code>, you could expect a data payload in the format:</p>
<pre><code class="language-txt">token=gIkuvaNzQIHg97ATvDxqgjtO&#10;&amp;team_id=T0001&#10;&amp;team_domain=example&#10;&amp;enterprise_id=E0001&#10;&amp;enterprise_name=Globular%20Construct%20Inc&#10;&amp;channel_id=C2147483705&#10;&amp;channel_name=test&#10;&amp;user_id=U2147483697&#10;&amp;user_name=Steve&#10;&amp;command=/issue&#10;&amp;text=cloudflare/wrangler#1&#10;&amp;response_url=https://hooks.slack.com/commands/1234/5678&#10;&amp;trigger_id=13345224609.738474920.8088930838d88f008e0&#10;</code></pre>
<p>Given this payload body, you need to parse it, and get the value of the <code>text</code> key. With that <code>text</code>, for example, <code>cloudflare/wrangler#1</code>, you can parse that string into known piece of data (<code>owner</code>, <code>repo</code>, and <code>issue_number</code>), and use it to make a request to GitHub’s API, to retrieve the issue data.</p>
<p>With Slack slash commands, you can respond to a slash command by returning structured data as the response to the incoming slash command. In this case, you should use the response from GitHub’s API to present a formatted version of the GitHub issue, including pieces of data like the title of the issue, who created it, and the date it was created. Slack’s new <a href="https://api.slack.com/block-kit">Block Kit</a> framework will allow you to return a detailed message response, by constructing text and image blocks with the data from GitHub’s API.</p>
<h4 id="parsing-slash-commands">Parsing slash commands</h4>
<p>To begin, the <code>lookup</code> route should parse the messages coming from Slack. As previously mentioned, the Slack API sends an HTTP POST in URL Encoded format. You can get the variable <code>text</code> by parsing it with <code>c.req.json()</code>.</p>
<pre><code class="language-ts">import { Hono } from &quot;hono&quot;;&#10;&#10;const app = new Hono();&#10;&#10;app.post(&quot;/&quot;, async (c) =&gt; {&#10;	const { text } = await c.req.parseBody();&#10;	if (typeof text !== &quot;string&quot;) {&#10;		return c.notFound();&#10;	}&#10;});&#10;&#10;export default app;&#10;</code></pre>
<p>Given a <code>text</code> variable, that contains text like <code>cloudflare/wrangler#1</code>, you should parse that text, and get the individual parts from it for use with GitHub’s API: <code>owner</code>, <code>repo</code>, and <code>issue_number</code>.</p>
<p>To do this, create a new file in your application, at <code>src/utils/github.ts</code>. This file will contain a number of “utility” functions for working with GitHub’s API. The first of these will be a string parser, called <code>parseGhIssueString</code>:</p>
<pre><code class="language-ts">const ghIssueRegex =&#10;	/(?&lt;owner&gt;[\w.-]*)\/(?&lt;repo&gt;[\w.-]*)\#(?&lt;issue_number&gt;\d*)/;&#10;&#10;export const parseGhIssueString = (text: string) =&gt; {&#10;	const match = text.match(ghIssueRegex);&#10;	return match ? (match.groups ?? {}) : {};&#10;};&#10;</code></pre>
<p><code>parseGhIssueString</code> takes in a <code>text</code> input, matches it against <code>ghIssueRegex</code>, and if a match is found, returns the <code>groups</code> object from that match, making use of the <code>owner</code>, <code>repo</code>, and <code>issue_number</code> capture groups defined in the regex. By exporting this function from <code>src/utils/github.ts</code>, you can make use of it back in <code>src/handlers/lookup.ts</code>:</p>
<pre><code class="language-ts">import { Hono } from &quot;hono&quot;;&#10;import { parseGhIssueString } from &quot;../utils/github&quot;;&#10;&#10;const app = new Hono();&#10;&#10;app.post(&quot;/&quot;, async (c) =&gt; {&#10;	const { text } = await c.req.parseBody();&#10;	if (typeof text !== &quot;string&quot;) {&#10;		return c.notFound();&#10;	}&#10;&#10;	const { owner, repo, issue_number } = parseGhIssueString(text);&#10;});&#10;&#10;export default app;&#10;</code></pre>
<h4 id="making-requests-to-github-s-api">Making requests to GitHub’s API</h4>
<p>With this data, you can make your first API lookup to GitHub. Again, make a new function in <code>src/utils/github.ts</code>, to make a <code>fetch</code> request to the GitHub API for the issue data:</p>
<pre><code class="language-ts">const ghIssueRegex =&#10;	/(?&lt;owner&gt;[\w.-]*)\/(?&lt;repo&gt;[\w.-]*)\#(?&lt;issue_number&gt;\d*)/;&#10;&#10;export const parseGhIssueString = (text: string) =&gt; {&#10;	const match = text.match(ghIssueRegex);&#10;	return match ? (match.groups ?? {}) : {};&#10;};&#10;&#10;export const fetchGithubIssue = (&#10;	owner: string,&#10;	repo: string,&#10;	issue_number: string,&#10;) =&gt; {&#10;	const url = `https://api.github.com/repos/${owner}/${repo}/issues/${issue_number}`;&#10;	const headers = { &quot;User-Agent&quot;: &quot;simple-worker-slack-bot&quot; };&#10;	return fetch(url, { headers });&#10;};&#10;</code></pre>
<p>Back in <code>src/handlers/lookup.ts</code>, use <code>fetchGitHubIssue</code> to make a request to GitHub’s API, and parse the response:</p>
<pre><code class="language-ts">import { Hono } from &quot;hono&quot;;&#10;import { fetchGithubIssue, parseGhIssueString } from &quot;../utils/github&quot;;&#10;import { Issue } from &quot;../types&quot;;&#10;&#10;const app = new Hono();&#10;&#10;app.post(&quot;/&quot;, async (c) =&gt; {&#10;	const { text } = await c.req.parseBody();&#10;	if (typeof text !== &quot;string&quot;) {&#10;		return c.notFound();&#10;	}&#10;&#10;	const { owner, repo, issue_number } = parseGhIssueString(text);&#10;	const response = await fetchGithubIssue(owner, repo, issue_number);&#10;	const issue = await response.json&lt;Issue&gt;();&#10;});&#10;&#10;export default app;&#10;</code></pre>
<h4 id="constructing-a-slack-message">Constructing a Slack message</h4>
<p>After you have received a response back from GitHub’s API, the final step is to construct a Slack message with the issue data, and return it to the user. The final result will look something like this:</p>
<p><img src="/assets/upstream/images/workers/tutorials/slackbot/issue-slack-message.png" alt="A successful Slack Message will have the components listed below" /></p>
<p>You can see four different pieces in the above screenshot:</p>
<ol>
<li>The first line (bolded) links to the issue, and shows the issue title</li>
<li>The following lines (including code snippets) are the issue body</li>
<li>The last line of text shows the issue status, the issue creator (with a link to the user’s GitHub profile), and the creation date for the issue</li>
<li>The profile picture of the issue creator, on the right-hand side</li>
</ol>
<p>The previously mentioned <a href="https://api.slack.com/block-kit">Block Kit</a> framework will help take the issue data (in the structure lined out in <a href="https://developer.github.com/v3/issues/">GitHub’s REST API documentation</a>) and format it into something like the above screenshot.</p>
<p>Create another file, <code>src/utils/slack.ts</code>, to contain the function <code>constructGhIssueSlackMessage</code>, a function for taking issue data, and turning it into a collection of blocks. Blocks are JavaScript objects that Slack will use to format the message:</p>
<pre><code class="language-ts">import { Issue } from &quot;../types&quot;;&#10;&#10;export const constructGhIssueSlackMessage = (&#10;	issue: Issue,&#10;	issue_string: string,&#10;	prefix_text?: string,&#10;) =&gt; {&#10;	const issue_link = `&lt;${issue.html_url}|${issue_string}&gt;`;&#10;	const user_link = `&lt;${issue.user.html_url}|${issue.user.login}&gt;`;&#10;	const date = new Date(Date.parse(issue.created_at)).toLocaleDateString();&#10;&#10;	const text_lines = [&#10;		prefix_text,&#10;		`*${issue.title} - ${issue_link}*`,&#10;		issue.body,&#10;		`*${issue.state}* - Created by ${user_link} on ${date}`,&#10;	];&#10;};&#10;</code></pre>
<p>Slack messages accept a variant of Markdown, which supports bold text via asterisks (<code>*bolded text*</code>), and links in the format <code>&lt;https://yoururl.com|Display Text&gt;</code>.</p>
<p>Given that format, construct <code>issue_link</code>, which takes the <code>html_url</code> property from the GitHub API <code>issue</code> data (in format <code>https://github.com/cloudflare/wrangler-legacy/issues/1</code>), and the <code>issue_string</code> sent from the Slack slash command, and combines them into a clickable link in the Slack message.</p>
<p><code>user_link</code> is similar, using <code>issue.user.html_url</code> (in the format <code>https://github.com/signalnerve</code>, a GitHub user) and the user’s GitHub username (<code>issue.user.login</code>), to construct a clickable link to the GitHub user.</p>
<p>Finally, parse <code>issue.created_at</code>, an ISO 8601 string, convert it into an instance of a JavaScript <code>Date</code>, and turn it into a formatted string, in the format <code>MM/DD/YY</code>.</p>
<p>With those variables in place, <code>text_lines</code> is an array of each line of text for the Slack message. The first line is the <strong>issue title</strong> and the <strong>issue link</strong>, the second is the <strong>issue body</strong>, and the final line is the <strong>issue state</strong> (for example, open or closed), the <strong>user link</strong>, and the <strong>creation date</strong>.</p>
<p>With the text constructed, you can finally construct your Slack message, returning an array of blocks for Slack’s <a href="https://api.slack.com/block-kit">Block Kit</a>. In this case, there is only have one block: a <a href="https://api.slack.com/reference/messaging/blocks#section">section</a> block with Markdown text, and an accessory image of the user who created the issue. Return that single block inside of an array, to complete the <code>constructGhIssueSlackMessage</code> function:</p>
<pre><code class="language-ts">import { Issue } from &quot;../types&quot;;&#10;&#10;export const constructGhIssueSlackMessage = (&#10;	issue: Issue,&#10;	issue_string: string,&#10;	prefix_text?: string,&#10;) =&gt; {&#10;	const issue_link = `&lt;${issue.html_url}|${issue_string}&gt;`;&#10;	const user_link = `&lt;${issue.user.html_url}|${issue.user.login}&gt;`;&#10;	const date = new Date(Date.parse(issue.created_at)).toLocaleDateString();&#10;&#10;	const text_lines = [&#10;		prefix_text,&#10;		`*${issue.title} - ${issue_link}*`,&#10;		issue.body,&#10;		`*${issue.state}* - Created by ${user_link} on ${date}`,&#10;	];&#10;&#10;	return [&#10;		{&#10;			type: &quot;section&quot;,&#10;			text: {&#10;				type: &quot;mrkdwn&quot;,&#10;				text: text_lines.join(&quot;\n&quot;),&#10;			},&#10;			accessory: {&#10;				type: &quot;image&quot;,&#10;				image_url: issue.user.avatar_url,&#10;				alt_text: issue.user.login,&#10;			},&#10;		},&#10;	];&#10;};&#10;</code></pre>
<h4 id="finishing-the-lookup-route">Finishing the lookup route</h4>
<p>In <code>src/handlers/lookup.ts</code>, use <code>constructGhIssueSlackMessage</code> to construct <code>blocks</code>, and return them as a new response with <code>c.json()</code> when the slash command is called:</p>
<pre><code class="language-ts">import { Hono } from &quot;hono&quot;;&#10;import { fetchGithubIssue, parseGhIssueString } from &quot;../utils/github&quot;;&#10;import { constructGhIssueSlackMessage } from &quot;../utils/slack&quot;;&#10;import { Issue } from &quot;../types&quot;;&#10;&#10;const app = new Hono();&#10;&#10;app.post(&quot;/&quot;, async (c) =&gt; {&#10;	const { text } = await c.req.parseBody();&#10;	if (typeof text !== &quot;string&quot;) {&#10;		return c.notFound();&#10;	}&#10;&#10;	const { owner, repo, issue_number } = parseGhIssueString(text);&#10;	const response = await fetchGithubIssue(owner, repo, issue_number);&#10;	const issue = await response.json&lt;Issue&gt;();&#10;	const blocks = constructGhIssueSlackMessage(issue, text);&#10;&#10;	return c.json({&#10;		blocks,&#10;		response_type: &quot;in_channel&quot;,&#10;	});&#10;});&#10;&#10;export default app;&#10;</code></pre>
<p>One additional parameter passed into the response is <code>response_type</code>. By default, responses to slash commands are ephemeral, meaning that they are only seen by the user who writes the slash command. Passing a <code>response_type</code> of <code>in_channel</code>, as seen above, will cause the response to appear for all users in the channel.</p>
<p>If you would like the messages to remain private, remove the <code>response_type</code> line. This will cause <code>response_type</code> to default to <code>ephemeral</code>.</p>
<h4 id="handling-errors">Handling errors</h4>
<p>The <code>lookup</code> route is almost complete, but there are a number of errors that can occur in the route, such as parsing the body from Slack, getting the issue from GitHub, or constructing the Slack message itself. Although Hono applications can handle errors without having to do anything, you can customize the response returned in the following way.</p>
<pre><code class="language-ts">import { Hono } from &quot;hono&quot;;&#10;import { fetchGithubIssue, parseGhIssueString } from &quot;../utils/github&quot;;&#10;import { constructGhIssueSlackMessage } from &quot;../utils/slack&quot;;&#10;import { Issue } from &quot;../types&quot;;&#10;&#10;const app = new Hono();&#10;&#10;app.post(&quot;/&quot;, async (c) =&gt; {&#10;	const { text } = await c.req.parseBody();&#10;	if (typeof text !== &quot;string&quot;) {&#10;		return c.notFound();&#10;	}&#10;&#10;	const { owner, repo, issue_number } = parseGhIssueString(text);&#10;	const response = await fetchGithubIssue(owner, repo, issue_number);&#10;	const issue = await response.json&lt;Issue&gt;();&#10;	const blocks = constructGhIssueSlackMessage(issue, text);&#10;&#10;	return c.json({&#10;		blocks,&#10;		response_type: &quot;in_channel&quot;,&#10;	});&#10;});&#10;&#10;app.onError((_e, c) =&gt; {&#10;	return c.text(&#10;		&quot;Uh-oh! We couldn&#x27;t find the issue you provided. &quot; +&#10;			&quot;We can only find public issues in the following format: `owner/repo#issue_number`.&quot;,&#10;	);&#10;});&#10;&#10;export default app;&#10;</code></pre>
<h3 id="creating-the-webhook-route">Creating the webhook route</h3>
<p>You are now halfway through implementing the routes for your Workers application. In implementing the next route, <code>src/routes/webhook.ts</code>, you will re-use a lot of the code that you have already written for the lookup route.</p>
<p>At the beginning of this tutorial, you configured a GitHub webhook to track any events related to issues in your repository. When an issue is opened, for example, the function corresponding to the path <code>/webhook</code> on your Workers application should take the data sent to it from GitHub, and post a new message in the configured Slack channel.</p>
<p>In <code>src/routes/webhook.ts</code>, define a blank Hono application. The difference from the <code>lookup</code> route is that the <code>Bindings</code> is passed as a generics for the <code>new Hono()</code>. This is necessary to give the appropriate TypeScript type to <code>SLACK_WEBHOOK_URL</code> which will be used later.</p>
<pre><code class="language-ts">import { Hono } from &quot;hono&quot;;&#10;import { Bindings } from &quot;../types&quot;;&#10;&#10;const app = new Hono&lt;{ Bindings: Bindings }&gt;();&#10;&#10;export default app;&#10;</code></pre>
<p>Much like with the <code>lookup</code> route, you will need to parse the incoming payload inside of <code>request</code>, get the relevant issue data from it (refer to <a href="https://developer.github.com/v3/activity/events/types/#issuesevent">the GitHub API documentation on <code>IssueEvent</code></a> for the full payload schema), and send a formatted message to Slack to indicate what has changed. The final version will look something like this:</p>
<p><img src="/assets/upstream/images/workers/tutorials/slackbot/webhook_example.png" alt="A successful Webhook Message example" /></p>
<p>Compare this message format to the format returned when a user uses the <code>/issue</code> slash command. You will see that there is only one actual difference between the two: the addition of an action text on the first line, in the format <code>An issue was $action:</code>. This action, which is sent as part of the <code>IssueEvent</code> from GitHub, will be used as you construct a very familiar looking collection of blocks using Slack’s Block Kit.</p>
<h4 id="parsing-event-data">Parsing event data</h4>
<p>To start filling out the route, parse the request body formatted JSON into an object and construct some helper variables:</p>
<pre><code class="language-ts">import { Hono } from &quot;hono&quot;;&#10;import { constructGhIssueSlackMessage } from &quot;../utils/slack&quot;;&#10;&#10;const app = new Hono();&#10;&#10;app.post(&quot;/&quot;, async (c) =&gt; {&#10;	const { action, issue, repository } = await c.req.json();&#10;	const prefix_text = `An issue was ${action}:`;&#10;	const issue_string = `${repository.owner.login}/${repository.name}#${issue.number}`;&#10;});&#10;&#10;export default app;&#10;</code></pre>
<p>An <code>IssueEvent</code>, the payload sent from GitHub as part of your webhook configuration, includes an <code>action</code> (what happened to the issue: for example, it was opened, closed, locked, etc.), the <code>issue</code> itself, and the <code>repository</code>, among other things.</p>
<p>Use <code>c.req.json()</code> to convert the payload body of the request from JSON into a plain JS object. Use ES6 destructuring to set <code>action</code>, <code>issue</code> and <code>repository</code> as variables you can use in your code. <code>prefix_text</code> is a string indicating what happened to the issue, and <code>issue_string</code> is the familiar string <code>owner/repo#issue_number</code> that you have seen before: while the <code>lookup</code> route directly used the text sent from Slack to fill in <code>issue_string</code>, you will construct it directly based on the data passed in the JSON payload.</p>
<h4 id="constructing-and-sending-a-slack-message">Constructing and sending a Slack message</h4>
<p>The messages your Slack bot sends back to your Slack channel from the <code>lookup</code> and <code>webhook</code> routes are incredibly similar. Because of this, you can re-use the existing <code>constructGhIssueSlackMessage</code> to continue populating <code>src/handlers/webhook.ts</code>. Import the function from <code>src/utils/slack.ts</code>, and pass the issue data into it:</p>
<pre><code class="language-ts">import { Hono } from &quot;hono&quot;;&#10;import { constructGhIssueSlackMessage } from &quot;../utils/slack&quot;;&#10;&#10;const app = new Hono();&#10;&#10;app.post(&quot;/&quot;, async (c) =&gt; {&#10;	const { action, issue, repository } = await c.req.json();&#10;	const prefix_text = `An issue was ${action}:`;&#10;	const issue_string = `${repository.owner.login}/${repository.name}#${issue.number}`;&#10;	const blocks = constructGhIssueSlackMessage(issue, issue_string, prefix_text);&#10;});&#10;&#10;export default app;&#10;</code></pre>
<p>Importantly, the usage of <code>constructGhIssueSlackMessage</code> in this handler adds one additional argument to the function, <code>prefix_text</code>. Update the corresponding function inside of <code>src/utils/slack.ts</code>, adding <code>prefix_text</code> to the collection of <code>text_lines</code> in the message block, if it has been passed in to the function.</p>
<p>Add a utility function, <code>compact</code>, which takes an array, and filters out any <code>null</code> or <code>undefined</code> values from it. This function will be used to remove <code>prefix_text</code> from <code>text_lines</code> if it has not actually been passed in to the function, such as when called from <code>src/handlers/lookup.ts</code>. The full (and final) version of the <code>src/utils/slack.ts</code> looks like this:</p>
<pre><code class="language-ts">import { Issue } from &quot;../types&quot;;&#10;&#10;const compact = (array: unknown[]) =&gt; array.filter((el) =&gt; el);&#10;&#10;export const constructGhIssueSlackMessage = (&#10;	issue: Issue,&#10;	issue_string: string,&#10;	prefix_text?: string,&#10;) =&gt; {&#10;	const issue_link = `&lt;${issue.html_url}|${issue_string}&gt;`;&#10;	const user_link = `&lt;${issue.user.html_url}|${issue.user.login}&gt;`;&#10;	const date = new Date(Date.parse(issue.created_at)).toLocaleDateString();&#10;&#10;	const text_lines = [&#10;		prefix_text,&#10;		`*${issue.title} - ${issue_link}*`,&#10;		issue.body,&#10;		`*${issue.state}* - Created by ${user_link} on ${date}`,&#10;	];&#10;&#10;	return [&#10;		{&#10;			type: &quot;section&quot;,&#10;			text: {&#10;				type: &quot;mrkdwn&quot;,&#10;				text: compact(text_lines).join(&quot;\n&quot;),&#10;			},&#10;			accessory: {&#10;				type: &quot;image&quot;,&#10;				image_url: issue.user.avatar_url,&#10;				alt_text: issue.user.login,&#10;			},&#10;		},&#10;	];&#10;};&#10;</code></pre>
<p>Back in <code>src/handlers/webhook.ts</code>, the <code>blocks</code> that are returned from <code>constructGhIssueSlackMessage</code> become the body in a new <code>fetch</code> request, an HTTP POST request to a Slack webhook URL. Once that request completes, return a response with status code <code>200</code>, and the body text <code>&quot;OK&quot;</code>:</p>
<pre><code class="language-ts">import { Hono } from &quot;hono&quot;;&#10;import { constructGhIssueSlackMessage } from &quot;../utils/slack&quot;;&#10;import { Bindings } from &quot;../types&quot;;&#10;&#10;const app = new Hono&lt;{ Bindings: Bindings }&gt;();&#10;&#10;app.post(&quot;/&quot;, async (c) =&gt; {&#10;	const { action, issue, repository } = await c.req.json();&#10;	const prefix_text = `An issue was ${action}:`;&#10;	const issue_string = `${repository.owner.login}/${repository.name}#${issue.number}`;&#10;	const blocks = constructGhIssueSlackMessage(issue, issue_string, prefix_text);&#10;&#10;	const fetchResponse = await fetch(c.env.SLACK_WEBHOOK_URL, {&#10;		body: JSON.stringify({ blocks }),&#10;		method: &quot;POST&quot;,&#10;		headers: { &quot;Content-Type&quot;: &quot;application/json&quot; },&#10;	});&#10;&#10;	return c.text(&quot;OK&quot;);&#10;});&#10;&#10;export default app;&#10;</code></pre>
<p>The constant <code>SLACK_WEBHOOK_URL</code> represents the Slack Webhook URL that you created all the way back in the <a href="/workers/tutorials/build-a-slackbot/#incoming-webhook">Incoming Webhook</a> section of this tutorial.</p>

<h4 id="handling-errors-1">Handling errors</h4>
<p>Similarly to the <code>lookup</code> route, the <code>webhook</code> route should include some basic error handling. Unlike <code>lookup</code>, which sends responses directly back into Slack, if something goes wrong with your webhook, it may be useful to actually generate an erroneous response, and return it to GitHub.</p>
<p>To do this, write the custom error handler with <code>app.onError()</code> and return a new response with a status code of <code>500</code>. The final version of <code>src/routes/webhook.ts</code> looks like this:</p>
<pre><code class="language-ts">import { Hono } from &quot;hono&quot;;&#10;import { constructGhIssueSlackMessage } from &quot;../utils/slack&quot;;&#10;import { Bindings } from &quot;../types&quot;;&#10;&#10;const app = new Hono&lt;{ Bindings: Bindings }&gt;();&#10;&#10;app.post(&quot;/&quot;, async (c) =&gt; {&#10;	const { action, issue, repository } = await c.req.json();&#10;	const prefix_text = `An issue was ${action}:`;&#10;	const issue_string = `${repository.owner.login}/${repository.name}#${issue.number}`;&#10;	const blocks = constructGhIssueSlackMessage(issue, issue_string, prefix_text);&#10;&#10;	const fetchResponse = await fetch(c.env.SLACK_WEBHOOK_URL, {&#10;		body: JSON.stringify({ blocks }),&#10;		method: &quot;POST&quot;,&#10;		headers: { &quot;Content-Type&quot;: &quot;application/json&quot; },&#10;	});&#10;&#10;	if (!fetchResponse.ok) throw new Error();&#10;&#10;	return c.text(&quot;OK&quot;);&#10;});&#10;&#10;app.onError((_e, c) =&gt; {&#10;	return c.json(&#10;		{&#10;			message: &quot;Unable to handle webhook&quot;,&#10;		},&#10;		500,&#10;	);&#10;});&#10;&#10;export default app;&#10;</code></pre>
