<p>Use <code>wrangler flagship</code> to manage <a href="/flagship/">Flagship</a> apps and feature flags from the command line.</p>
<p><code>wrangler flagship</code> is available in Wrangler v4.107.0 and later.</p>
<h2 id="authentication">Authentication</h2>
<p>Run <code>wrangler login</code>, or set <a href="/workers/wrangler/system-environment-variables/"><code>CLOUDFLARE_API_TOKEN</code></a> to an API token with Flagship permissions.</p>
<table>
<thead>
<tr>
<th>Permission</th>
<th>Required for</th>
</tr>
</thead>
<tbody>
<tr>
<td><code>flagship:read</code></td>
<td>Listing apps, inspecting flags, evaluating flags, and reading changelogs.</td>
</tr>
<tr>
<td><code>flagship:write</code></td>
<td>Creating, updating, deleting, enabling, disabling, rolling out, and splitting apps or flags.</td>
</tr>
</tbody>

<p>Most write workflows also read the current flag before writing the updated definition, so grant both permissions for operational use.</p>
<h2 id="app-ids">App IDs</h2>
<p><code>wrangler flagship flags</code> commands always take the app ID as the first argument. Most subcommands then take a flag key; list-style commands, such as <code>flags list</code>, take only the app ID:</p>
<pre tabindex="0"><code class="language-sh">wrangler flagship flags get &lt;APP_ID&gt; new-checkout&#10;wrangler flagship flags disable &lt;APP_ID&gt; new-checkout&#10;wrangler flagship flags list &lt;APP_ID&gt;&#10;</code></pre>
<p>Create an app first if you do not already have one:</p>
<pre tabindex="0"><code class="language-sh">wrangler flagship apps create checkout-service&#10;</code></pre>
<p>Pass <code>--binding &lt;NAME&gt;</code> when creating an app to add it to your <code>wrangler.json</code> or <code>wrangler.jsonc</code> file as a Worker binding.</p>
<h2 id="common-workflows">Common workflows</h2>
<p>Create a boolean flag. With no variations, Wrangler creates <code>on=true</code>, <code>off=false</code>, and serves <code>off</code> by default:</p>
<pre tabindex="0"><code class="language-sh">wrangler flagship flags create &lt;APP_ID&gt; new-checkout&#10;</code></pre>
<p>Add targeting rules with the compact rule syntax:</p>
<pre tabindex="0"><code class="language-sh">wrangler flagship flags create &lt;APP_ID&gt; premium-banner \&#10;	&#45;V on=true \&#10;	&#45;V off=false \&#10;	&#45;-default off \&#10;	&#45;-rule &quot;serve=on; when=plan equals enterprise AND country in [US,CA]; rollout=25%@user_id&quot;&#10;</code></pre>
<p>Use uppercase <code>AND</code> and <code>OR</code> outside quoted values to combine conditions. Quote values that contain reserved words or separators:</p>
<pre tabindex="0"><code class="language-sh">wrangler flagship flags create &lt;APP_ID&gt; banner-copy \&#10;	&#45;V shown=true \&#10;	&#45;V hidden=false \&#10;	&#45;-default hidden \&#10;	&#45;-rule &#x27;serve=shown; when=title equals &quot;WAR AND PEACE&quot; OR country in [&quot;US&quot;,&quot;CA&quot;]&#x27;&#10;</code></pre>
<p>For deeply nested condition groups, use <code>--rule-json</code>. Wrangler validates both compact rules and JSON rules before sending requests.</p>
<p>Change one existing rule without rewriting the full rule set:</p>
<pre tabindex="0"><code class="language-sh">wrangler flagship flags rules update &lt;APP_ID&gt; premium-banner \&#10;	&#45;-priority 1 \&#10;	&#45;-rollout 50%@user_id&#10;</code></pre>
<p>Evaluate a flag for a user:</p>
<pre tabindex="0"><code class="language-sh">wrangler flagship flags evaluate &lt;APP_ID&gt; premium-banner \&#10;	&#45;-context plan=enterprise \&#10;	&#45;-context country=US \&#10;	&#45;-targeting-key user-42&#10;</code></pre>
<p>Use <code>disable</code> as an immediate kill switch:</p>
<pre tabindex="0"><code class="language-sh">wrangler flagship flags disable &lt;APP_ID&gt; premium-banner&#10;</code></pre>
<p>Enable, disable, or delete multiple flags by passing the app ID followed by multiple keys:</p>
<pre tabindex="0"><code class="language-sh">wrangler flagship flags disable &lt;APP_ID&gt; new-checkout dark-mode premium-banner&#10;wrangler flagship flags delete &lt;APP_ID&gt; coming-soon old-banner --force&#10;</code></pre>
<p>Delete commands require <code>--force</code> when used with <code>--json</code> so prompts cannot corrupt JSON output. <code>rollout</code> and <code>split</code> require the same when they would replace existing targeting rules that have conditions.</p>
<p>Refer to the <a href="/flagship/reference/wrangler-commands/">Flagship Wrangler commands reference</a> for a complete workflow guide covering targeting rules, rollouts, traffic splits, changelogs, and scripting with <code>--json</code>.</p>
