<p class="article-summary">Export a D1 database into R2 storage with Workflows</p>
<p>In this example, we implement a Workflow that runs on a schedule using the <code>schedules</code> field on the Workflow binding. That Workflow initiates a backup for a D1 database using the REST API, and then stores the SQL dump in an <a href="/r2">R2</a> bucket.</p>
<p>When the Workflow is triggered, it fetches the REST API to initiate an export job for a specific database. Then it fetches the same endpoint to check if the backup job is ready and the SQL dump is available to download.</p>
<p>As shown in this example, Workflows handles both the responses and failures, thereby removing the burden from the developer. Workflows retries the following steps:</p>
<ul>
<li>API calls until it gets a successful response</li>
<li>Fetching the backup from the URL provided</li>
<li>Saving the file to <a href="/r2">R2</a></li>
</ul>
<p>The Workflow can run until the backup file is ready, handling all of the possible conditions until it is completed.</p>
<p>This example provides simplified steps for backing up a <a href="/d1">D1</a> database to help you understand the possibilities of Workflows. In every step, it uses the <a href="/workflows/build/sleeping-and-retrying">default</a> sleeping and retrying configuration. In a real-world scenario, more steps and additional logic would likely be needed.</p>
<pre tabindex="0"><code class="language-ts">import {&#10;	WorkflowEntrypoint,&#10;	WorkflowStep,&#10;	WorkflowEvent,&#10;} from &quot;cloudflare:workers&quot;;&#10;&#10;// We are using R2 to store the D1 backup&#10;type Env = {&#10;	BACKUP_WORKFLOW: Workflow;&#10;	D1_REST_API_TOKEN: string;&#10;	BACKUP_BUCKET: R2Bucket;&#10;	ACCOUNT_ID: string;&#10;	DATABASE_ID: string;&#10;};&#10;&#10;// Workflow logic&#10;export class backupWorkflow extends WorkflowEntrypoint&lt;Env&gt; {&#10;	async run(_event: WorkflowEvent&lt;unknown&gt;, step: WorkflowStep) {&#10;		const accountId = this.env.ACCOUNT_ID;&#10;		const databaseId = this.env.DATABASE_ID;&#10;&#10;		const url = `https://api.cloudflare.com/client/v4/accounts/${accountId}/d1/database/${databaseId}/export`;&#10;		const method = &quot;POST&quot;;&#10;		const headers = new Headers();&#10;		headers.append(&quot;Content-Type&quot;, &quot;application/json&quot;);&#10;		headers.append(&quot;Authorization&quot;, `Bearer ${this.env.D1_REST_API_TOKEN}`);&#10;&#10;		const bookmark = await step.do(&#10;			`Starting backup for ${databaseId}`,&#10;			async () =&gt; {&#10;				const payload = { output_format: &quot;polling&quot; };&#10;&#10;				const res = await fetch(url, {&#10;					method,&#10;					headers,&#10;					body: JSON.stringify(payload),&#10;				});&#10;				const { result } = (await res.json()) as any;&#10;&#10;				// If we don&#x27;t get `at_bookmark` we throw to retry the step&#10;				if (!result?.at_bookmark) throw new Error(&quot;Missing `at_bookmark`&quot;);&#10;&#10;				return result.at_bookmark;&#10;			},&#10;		);&#10;&#10;		await step.do(&quot;Check backup status and store it on R2&quot;, async () =&gt; {&#10;			const payload = { current_bookmark: bookmark };&#10;&#10;			const res = await fetch(url, {&#10;				method,&#10;				headers,&#10;				body: JSON.stringify(payload),&#10;			});&#10;			const { result } = (await res.json()) as any;&#10;&#10;			// The endpoint sends `signed_url` when the backup is ready to download.&#10;			// If we don&#x27;t get `signed_url` we throw to retry the step.&#10;			if (!result?.signed_url) throw new Error(&quot;Missing `signed_url`&quot;);&#10;&#10;			const dumpResponse = await fetch(result.signed_url);&#10;			if (!dumpResponse.ok) throw new Error(&quot;Failed to fetch dump file&quot;);&#10;&#10;			// Finally, stream the file directly to R2&#10;			await this.env.BACKUP_BUCKET.put(result.filename, dumpResponse.body);&#10;		});&#10;	}&#10;}&#10;&#10;export default {&#10;	async fetch(req: Request, env: Env): Promise&lt;Response&gt; {&#10;		return new Response(&quot;Not found&quot;, { status: 404 });&#10;	},&#10;};&#10;</code></pre>

<p>Each scheduled run creates a new Workflow instance automatically.</p>
<p>Scheduled instances include the matching cron expression and scheduled trigger time on <code>event.schedule</code>.</p>
<p>Use the latest Wrangler release when configuring Workflow schedules. If your local Wrangler schema does not recognize <code>schedules</code> yet, update Wrangler before deploying.</p>
