<p>The Python Workflows SDK supports DAG workflows in a declarative way, using <code>step.do</code> and parameter names to define dependencies (other steps that must complete before a step can run).</p>
<pre tabindex="0"><code class="language-python">from workers import Response, WorkflowEntrypoint, WorkerEntrypoint&#10;&#10;class PythonWorkflowStarter(WorkflowEntrypoint):&#10;    async def run(self, event, step):&#10;        async def await_step(fn):&#10;            try:&#10;                return await fn()&#10;            except TypeError as e:&#10;                print(f&quot;Successfully caught {type(e).__name__}: {e}&quot;)&#10;&#10;        await step.sleep(&#x27;demo sleep&#x27;, &#x27;10 seconds&#x27;)&#10;&#10;        @step.do()&#10;        async def dep_1():&#10;            &#35; does stuff&#10;            print(&#x27;executing dep1&#x27;)&#10;            return &#x27;dep1&#x27;&#10;&#10;        @step.do()&#10;        async def dep_2():&#10;            &#35; does stuff&#10;            print(&#x27;executing dep2&#x27;)&#10;            return &#x27;dep2&#x27;&#10;&#10;        @step.do(concurrent=True)&#10;        async def final_step(dep_1, dep_2):&#10;            &#35; does stuff&#10;            print(f&#x27;{dep_1} {dep_2}&#x27;)&#10;&#10;        await await_step(final_step)&#10;&#10;class Default(WorkerEntrypoint):&#10;    async def fetch(self, request):&#10;        await self.env.MY_WORKFLOW.create()&#10;        return Response(&quot;Hello world!&quot;)&#10;</code></pre>
<p>In this example, <code>dep_1</code> and <code>dep_2</code> are run concurrently before execution of <code>final_step</code>, which depends on both of them.</p>
<p>Having <code>concurrent=True</code> allows dependencies to be resolved concurrently. If a dependency has already completed, it will be skipped and its return value will be reused.</p>
